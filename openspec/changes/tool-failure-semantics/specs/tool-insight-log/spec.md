# Spec Delta

## MODIFIED Requirements

### Requirement: 事件触发的完整轨迹检测

系统 SHALL 在工具异常、反复修改或用户主动反馈时检查相关完整工具轨迹。检测 MUST 覆盖应调用而未调用、工具选择错误、参数错误、无意义重复调用或重试、恢复失败，以及表面成功但任务未完成；正常调用 MUST NOT 逐条生成 AI 意见。无意义重复的判定 SHALL 区分批量并行与顺序重试：同一轮内多个调用先发出、结果后到的批量并行形态 MUST NOT 记为无意义重复、恢复失败或表面成功问题；仅当同一调用在成功返回之后再次以相同参数发起时才计入无意义重复。

#### Scenario: 工具未报错但路径错误

- **WHEN** 一次任务最终完成，但轨迹显示 agent 先选择了不适用工具并重复无效调用
- **THEN** 系统将该轨迹形成效率或工具使用问题，不因没有异常而丢弃

#### Scenario: 应当调用工具而未调用

- **WHEN** 用户反馈某项需要持久化的操作被 agent 仅在文字中宣称完成，且轨迹没有相应调用
- **THEN** 系统记录「应调用而未调用」问题并关联真实结果核验状态

#### Scenario: 普通成功调用

- **WHEN** 工具按预期一次成功且真实结果符合目标，也没有用户负反馈
- **THEN** 系统不生成该次调用的 AI 改进意见

#### Scenario: 批量先发后收不记重复

- **WHEN** 同一轮内一个工具的多个调用全部先于任何结果发出，随后全部成功返回
- **THEN** 系统不将其记为无意义重复、恢复失败或表面成功问题，也不生成对应问题记录

#### Scenario: 批量门禁拦截不建档

- **WHEN** 同一轮内一个工具的多个调用全部先于任何结果发出，随后因同一前置拦截全部失败
- **THEN** 系统不将其记为无意义重复、恢复失败或表面成功问题，也不生成对应问题记录

#### Scenario: 成功后同参重试记重复

- **WHEN** 某调用已成功返回后，同一轮内又以相同参数再次发起同一工具调用
- **THEN** 系统将其计入无意义重复问题

### Requirement: 稳定指纹归并与索引

系统 SHALL 根据工具、错误类别和操作场景等稳定事实生成问题指纹。相同指纹的新证据 MUST 更新同一问题记录的出现次数、时间、影响版本和证据索引，并维护可读总索引，MUST NOT 因措辞变化重复建档。错误类别词汇演进时，新类别问题文档首次登记且同工具、同场景的旧机制指纹文档实际存在时，SHALL 在新文档登记旧指纹作为历史溯源标注，旧文档保持不变，MUST NOT 自动归并或重定向。证据 MUST 使用跨重启不重复的稳定标识，归并 MUST 按该标识去重；出现次数 MUST 按独立稳定的发生实例标识计算，同一实例的多条证据不得重复计数。

#### Scenario: 同一问题重复发生

- **WHEN** 同一工具在不同会话中以相同错误类别和操作场景再次失败
- **THEN** 系统更新原问题记录并增加出现次数和证据引用，不创建重复问题文件

#### Scenario: 一次发生产生多条证据

- **WHEN** 同一次工具失败同时生成过程、错误和真实结果三条证据
- **THEN** 三条证据都可被问题记录引用，但出现次数只增加一次

#### Scenario: 不同根因候选不得仅凭报错文案合并

- **WHEN** 两次失败的工具或操作场景不同，仅错误文案相似
- **THEN** 系统分别保留问题记录，不因自然语言相似度强行归并

#### Scenario: 两个进程同时写入同一项目日志

- **WHEN** 两个应用进程同时追加证据并整理同一指纹的问题
- **THEN** 文件更新被真实跨进程锁串行化，同一证据不重复计数，并发更新不丢次数，JSONL 与问题索引保持可读

#### Scenario: 重启后继续产生证据

- **WHEN** 应用重启后产生与重启前同指纹的新证据
- **THEN** 新证据不复用历史证据标识，归并结果能区分待整理与已整理证据

#### Scenario: 词表演进后旧文档保留且新文档标注历史指纹

- **WHEN** 错误类别词表切换后，同一工具与场景的失败以新类别首次登记，且旧机制指纹的问题文档已存在
- **THEN** 新问题文档登记旧指纹为历史溯源标注，旧文档保持不变，不自动归并

## ADDED Requirements

### Requirement: 失败类别归一

失败问题记录的错误类别 SHALL 取自失败事件携带的稳定错误类别；事件未携带类别时 MUST 标记为未分类。MUST NOT 以错误对象的构造器名或运行时类型名充当错误类别。

#### Scenario: 事件携带类别时直接使用

- **WHEN** 工具失败事件带有稳定错误类别
- **THEN** 对应问题记录与指纹使用该类别，无需模型归因即可分类

#### Scenario: 事件无类别时不猜

- **WHEN** 工具失败事件未携带任何错误类别
- **THEN** 问题记录的类别标为未分类，不记录构造器名

### Requirement: 失败证据携带脱敏标识符

客观证据 SHALL 为失败调用记录脱敏后的稳定标识符摘要（如章节、实体类短标识）与参数键名，使后续归因可直接定位调用目标；MUST NOT 保存正文片段或完整参数内容。

#### Scenario: 章节更新失败可定位目标

- **WHEN** 一次章节更新失败被采集为证据
- **THEN** 证据包含该章节的标识与参数键名列表，不包含章节正文

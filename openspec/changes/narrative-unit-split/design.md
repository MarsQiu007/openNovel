# Design

## Context

前置就绪：paragraph-aware-split 提供句末集合、字数范围边界与可配置范围（快速模式继续使用，组章句流切分复用其句末集合）；WorkRun 工作队列提供持久化推进、断点续跑与挂起恢复；agent 体系与 `agent.<name>.model` 配置链；agent-model-fallback 已归档上线，编程式入口模型回落已修复，本提案无阻塞依赖。

## Goals / Non-Goals

**Goals**

- 导入双模式：快速拆章（现状零变化）与 AI 拆章（存档 → 预估 → 逐章组章 → 自动清洗 → 设定自动入库）
- `cutter` 逐章组章：衔接上下文 + 游标句流窗口输入，输出章末句/章题/分段点
- `cleaner` 单读全章：自动修复直写 + 设定提取自动入库合并
- 预估驱动的稳定队列（N 个组章单元 + 收尾），失败暂停保留游标、不静默降级

**Non-Goals**

- 快速模式行为零变化；AI 模式不改写/生成正文（只从存档组章与确定性修复）
- 不做 embedding 语义分割；LLM 不通读全书
- 存量书（无存档）不支持 AI 拆章

## Decisions

### D1：双模式入口、AI 模式仅预估
导入确认页新增「拆章方式」选择：快速拆章（默认）与 AI 拆章。快速模式走现状全流程（analyze 解析预览 → apply 建书 → 可选既有 AI 整理）。AI 模式 analyze 仅输出预估：编码识别与清洗归一照常，按目标章字数（默认 2000–3000，中值 2500）折算章数预估，任务量按每章 2 次 LLM 调用（组章 + 清洗）加收尾估算 token 量级；预览展示估算而非卷章树，确认后 apply 建书 + 存档 + 自动建 AI 拆章队列。模式随 apply 落库（`split_mode`），管线与 UI 按标记分派。

### D2：AI 模式整书存档 = 文件 + 元数据
选择 AI 拆章时，apply 建书事务内将归一后原文（UTF-8）写 `.opennovel/sources/<novelID>.txt`，DB 元数据表记录 novelID、内容哈希、编码、字数、存档时间；文件写失败整体回滚；随书删除级联删文件与元数据。备选「DB 大字段」被否：千万字书 10–30MB 入库膨胀 FTS 与备份体积。AI 模式建书不创建卷章——章节由拆章管线逐章产出；快速模式不存档（避免无谓大对象写入，行为零变化）。analyze 不落盘原则不变——存档只发生在 apply。

### D3：`cutter` 组章 agent 与输出契约
`agents/cutter.ts`，subagent 模式，模型经 `agent.cutter.model` 配置链解析（未配置按继承链回落，导入全程零配置）。单次调用输入：前文衔接（上一章末尾 2 句）+ 从游标开始的目标范围句流窗口（目标上限 +50% 缓冲，约 4500 字）+ 后文缓冲句流（约 500 字，判断边界后情节走向）。输出 JSON：

```json
{ "endSentence": 42, "title": "第三章 破庙夜雨", "segments": [12, 37], "reason": "场景转换后情节收束" }
```

`endSentence` 为相对句流窗口的章末句号，`title` 为章题，`segments` 为章内分段点。解析失败（非 JSON、字段缺失、句号越界）重试一次，仍失败计该单元失败。字数为软约束（提示词引导 2000–3000 区间，叙事完整性优先），硬校验由执行器负责。原文含完整连续章题时，章题行作为强边界信号：组章按章题边界落章，cutter 只补章内分段，节省调用。

### D4：确定性执行器与清洗修复护栏
句流切分（句末标点 + 引号闭合，复用 paragraph-aware-split 句末集合）、游标管理、cutter 输出校验（句末、引号闭合、endSentence 单调推进、章非空）、章记录创建（标题/正文/分段）、进度笔记——全部确定性实现于 plugin 工具；LLM 只输出组章结论。清洗由 `agents/cleaner.ts` 单读全章一次完成三产出：修复后全文（错字、残留噪声、格式）、设定抽取、技法候选。护栏：只修确定性错误（明显错别字、重复行、页眉页脚水印、段落错乱），人名/术语/有歧义表达不动；修复后章字数与原章偏差超 10% 拒绝本次修复并降级为仅结构清洗（分段与噪声，不改正文用词）；修复对照（原文片段 → 修复结果）写入进度笔记可追溯。

### D5：设定自动入库与合并
cleaner 产出的设定线索由编排会话直接写库（不走审阅收件箱）：LLM 判断信息足够即经 `organize_settings` 自动入库；与既有设定同主体时自动合并更新（附出处章节与变更轨迹），不重复新建。技法沿用 `save_technique` 口径（unverified 初始状态、同名合并保留既有 status 与 confidence、空泛候选自过滤）。入库清单与变更轨迹记入进度笔记与最终汇总，事后可查但不阻塞。

### D6：预估驱动的稳定队列与失败暂停
建队形态：按预估章数 N 声明 N 个「AI 组章」单元 + 1 个「收尾」单元（简介 + 汇总），队列总数恒定 N+1。每个组章单元处理「游标处的下一章」（组章 → 清洗 → 写库 → 设定/技法入库）；全书提前处理完时剩余单元直接跳过完成，预估不足时收尾单元先处理剩余章再收尾。进度 = 已完成章 / 预估章。失败语义：单章重试上限 2 次，连续 5 章失败 → 暂停队列并提示检查模型配置；MUST NOT 静默退回规则拆分，用户显式改用快速拆章是唯一兜底。断点续跑沿用 WorkRun 队列语义，游标持久化使重试不重复组章。

## Risks / Trade-offs

- [cutter 窗口有限，边界判断可能失准] → 窗口给足缓冲 + reason 记录 + 存档可重新拆章；实测书冒烟验证后调窗
- [cleaner 自动修复误伤] → 只修确定性错误 + 歧义不动 + 长度突变校验 + 修复对照可追溯 + 存档回滚
- [预估章数与实际偏差大] → 尾部单元吸收偏差、进度按已完成/预估展示、预估仅用于成本参考
- [长书成本累积] → 建队前估算展示 + 窗口硬上限 + 失败暂停语义

## Migration Plan

纯增量：存档表/字段与 `split_mode` 标记新增；快速模式行为零变化；存量书无存档仅 AI 拆章入口不可用。回滚 revert 即可。

# Design

## Context

前置已就绪：`paragraph-aware-split`（2026-11-26 归档）提供 reflow 段落重组、字数范围边界感知粗切、可配置范围与预览确认；既有 WorkRun 导入整理队列提供逐章单元、单读多产出、断点续跑与审阅收件箱；agent 体系提供 14 个专职 agent 定义模式与 `agent.<name>.model` 配置链。

**Dependencies**：`agent-model-fallback`（审查中）必须先实施——AI 整理等编程式入口创建的会话当前不携带模型，服务端回落目录默认模型导致「Header中未收到Authorization参数」；`cutter` 的调用链与该入口同源，不先修则定界必然失败。

## Goals / Non-Goals

**Goals**

- 整书原文存档：导入即存档，定界/整理/返工从存档工作，随书删除
- `cutter` 专用 agent：边界上下文输入、结构化定界输出、按句增减（迭代 ≤3）、章内分段重建
- 队列打头单元按书形态分派：有章题书结构校验、兜底分章书叙事定界（自动应用 + 对照可回滚）
- 成本估算展示与无模型降级（规则切分直接可用）

**Non-Goals**

- 不改 `parseStructure` 章题路径；不做 embedding 语义分割；analyze 同步链路不内嵌 LLM
- 定界不增删章数（过短末章允许并入前章）；错字不直改正文

## Decisions

### D1：整书存档 = 文件存档 + 元数据入库

原文写工作区文件（如 `.opennovel/sources/<novelID>.txt`，UTF-8 归一后），DB 记录元数据（novelID、内容哈希、编码、字数、存档时间）。备选「DB 大字段」被否：千万字书 10–30MB 文本入库会膨胀 FTS 与备份体积，文件系统天然适合大对象且随书删除只需删文件 + 行。`analyze` 不落盘原则不变——存档发生在 apply 建书事务内（同事务写元数据，文件写入失败则整体回滚）。

### D2：`cutter` agent 定义与输出契约

`agents/cutter.ts`，subagent 模式（与 observer 同构），模型经 `agent.cutter.model` 配置链解析、未配置按继承链回落。单次调用输入：本章首 8 句 + 尾 8 句 + 相邻章衔接句（各 2 句），硬上限约 600 token。输出 JSON：

```json
{ "verdict": "ok" | "move-earlier" | "move-later", "shiftSentences": 0, "segments": [12, 37], "reason": "..." }
```

`segments` 为章内分段点（句号序）。解析失败（非 JSON、字段缺失、句数越界）按降级处理（该章用规则边界）。

### D3：定界执行器是确定性的，LLM 只做判断题

句子切分（句末标点 + 引号闭合，复用 paragraph-aware-split 的句末集合）、按句移动切点、迭代控制（≤3 次取当前最优）、调整后字数按既有规则二次收束、引号配对硬校验——全部确定性实现于 plugin 侧工具；LLM 仅输出 verdict 与句数。章内分段按 `segments` 插入段落边界，不增删文字。

### D4：队列单元分派与自动应用 + 可回滚

打头单元执行时检测书籍边界形态（导入时记录 `fixed_split` 标记沿用）：有章题 → 结构校验（现状行为）；兜底分章 → 逐章定界。定界结果**自动应用**（逐章审阅对数千章不现实），进度笔记与汇总记录前后章界对照；回滚 = 从存档重新粗切（规则切分确定性可重放）。章节清洗与设定提取复用既有「单读三产出」单元，不新增单元类型。

### D5：成本估算与降级

建队前估算 = 章数 × 单次约 600 token（输入为主），按当前配置模型展示量级说明；估算不阻断建队。无可用模型、凭证失效或调用失败：该章降级为规则边界 + 规则分段，队列继续；连续失败超阈值（如 10 章）暂停队列并提示检查模型配置，不静默烧调用。

## Risks / Trade-offs

- [LLM 定界质量不稳，边界仍可能不合预期] → 迭代上限 + 硬约束 + 对照记录可回滚；降级路径始终可用
- [长书调用量累积成本] → 上下文硬上限、建队估算展示、连续失败熔断
- [定界自动应用存在误切风险] → 只调边界不增删章数 + 字数二次收束 + 存档可回滚
- [`agent-model-fallback` 未落地时本提案不可用] → 显式 Dependencies，实施顺序其先

## Migration Plan

纯增量：存档表/字段新增，存量书无存档则定界跳过（spec 已述）；无数据迁移。回滚 revert 即可，已建书籍与存档不受影响。

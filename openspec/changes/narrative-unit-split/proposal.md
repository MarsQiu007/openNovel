# Proposal

## Why

无章题书籍经规则兜底分章（paragraph-aware-split）只能保证「不切句子、字数达标」，无法识别叙事单元边界——切点可能落在情节中段（对话高潮、场景进行中），读者体验断裂。用户目标形态：章题完整连续的书走章题路径；无章题的书按情节/叙事单元切分——整书存档后清理换行，先按字数粗切，再由 LLM 逐章判断切点是否满足叙事分章并按句增减，定界后重建分段、清洗章节、提取设定，多章设定合并审阅入库。

## What Changes

- **整书存档**：导入建书时原文落档（文件存档 + 元数据入库），后续定界、整理、返工均从存档读取，不依赖用户重新上传；存档随书删除。
- **抹平换行的处理底稿**：定界流程在「抹掉所有换行/空行的连续文本流」上工作（字符级信号如标点、引号、场景分隔线保留），切分不再依赖书源段落（硬换行书源段落本不可靠）。
- **新增 `cutter` 专用 agent**：subagent 模式，模型经既有 `agent.cutter.model` 配置链解析（未配置按继承链回落，导入全程零配置）；逐章执行「定界判断 → 按句增减 → 章内分段」：输入为章边界上下文（每章首尾各若干句，不通读全书），输出结构化结论（边界成立 / 前移 N 句 / 后移 N 句 + 章内分段点）。
- **迭代与硬约束护栏**：定界迭代 ≤3 次；切点必须落在句末且引号配对闭合；调整后章字数越出目标范围时按既有规则二次收束；只调边界不增删章数（过短末章允许并入前章）。
- **导入整理队列升级**：打头的「分章结构校验」单元（只汇报不重切）升级为「叙事定界」单元——每章依次完成定界、分段重建、章节清洗（残留噪声与错字建议），设定线索提取与跨章合并入库沿用既有「单读三产出」与审阅收件箱，不旁路直改。
- **成本护栏与降级**：建队前展示 LLM 调用量估算（章数 × 单次边界上下文 token）；无可用模型或调用失败时整链降级为规则切分结果（paragraph-aware-split 成果直接可用），不阻塞导入。

## Capabilities

### New Capabilities

- `narrative-split`: `cutter` agent 的叙事定界行为契约——边界上下文输入、结构化定界输出、按句增减迭代与硬约束、章内分段重建、失败降级。

### Modified Capabilities

- `novel-book-import`: 新增整书原文存档行为（导入建书时存档、随书删除、定界与整理从存档读取）。
- `book-import-pipeline`: 打头「分章结构校验」单元由「只汇报不重切」升级为「叙事定界」单元（定界→分段→清洗，复用单读多产出）；建队前新增 LLM 调用量估算展示。

## 非目标

- 不改变章题完整连续书籍的章题解析路径（`parseStructure` 不变）。
- LLM 不通读全书、不逐章全文阅读（仅边界上下文）；不做embedding 语义分割。
- 错字/正文修订不直改章节正文，仍走既有审阅流。
- 不移除规则兜底分章：保留为无模型降级路径与即时预览。
- 不处理导入时异步化（analyze 同步链路不内嵌 LLM；LLM 定界全部在导入后的队列中执行）。

## Impact

- `packages/novel-store` — 原文存档元数据（新表或字段）与随书删除级联。
- `packages/server` — 导入 apply 落档原文；存档读取接口；定界结果应用（章节边界重排事务）。
- `packages/plugin` — 新增 `agents/cutter.ts`；导入整理队列单元定义升级（director 编排、cutter 子代理）。
- `packages/schema` / `packages/sdk` — 存档与定界相关契约（如需新端点则 `bun run generate`）。
- `packages/app` — 建队前成本估算展示、定界建议审阅入口。
- 数据兼容性：新增存档表/字段为纯增量，存量书籍无存档时定界功能不可用但不影响既有功能；无迁移。

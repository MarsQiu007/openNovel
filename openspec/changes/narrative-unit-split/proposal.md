# Proposal

## Why

无章题书籍的导入目前只有两条路：章题解析（`parseStructure`）与规则兜底分章（paragraph-aware-split）。规则分章只能保证「不切句子、字数达标」，切点常落在情节中段，段落重组也无法从噪声书源还原阅读体验。用户需要两种明确的导入模式：**快速拆章**（纯脚本，现状）与 **AI 拆章**（LLM 逐章组章 + 自动清洗 + 设定自动入库）。AI 模式下错字修复与设定入库由 LLM 自动判断并直接执行，不设人工审阅闸门；失败时暂停保留进度，不静默退回脚本拆分。

## What Changes

- **导入拆章方式选择**：导入确认时选择「快速拆章」（默认，现状全流程不变）或「AI 拆章」（本提案新增）；选择随建书落库（`split_mode`），管线与界面按其分派。
- **AI 模式整书存档**：选择 AI 拆章时，apply 建书事务内将原文完整存档（文件 + 元数据），随书删除；AI 拆章管线全部从存档读取，不依赖重新上传。
- **AI 模式导入分析只做预估**：不做脚本拆章、不创建章节；分析输出章节数预估（按目标章字数折算）、任务量与 token 成本量级，确认后建书并自动启动 AI 拆章队列。
- **逐章组章管线**：`cutter` agent 从原文游标处按目标字数与句断评估，判断当前范围构成完整叙事单元时输出一章（章末句、章题、章内分段点）；执行器确定性校验（句末、引号闭合、游标单调）并落章、推进游标，逐章推进直到全书处理完；收尾基于成品章生成书籍简介与全书汇总（章数偏差、修复对照、设定入库清单）。
- **逐章清洗自动修复**：`cleaner` agent 单读全章，直接修复错字、残留噪声与格式问题并直写章节正文（不入审阅收件箱）；只修确定性错误，歧义内容不动，修复对照全程记录，原书存档可随时回溯。
- **设定自动提取入库**：每章清洗时同步提取设定与技法；LLM 判断信息足够即自动入库，后续章节的补充与修订自动合并到既有设定（不重复新建、不等人工确认）；入库轨迹记入进度与汇总。
- **模型零配置**：`cutter` 与 `cleaner` 的模型经既有 `agent.<name>.model` 配置链解析，未配置按继承链回落，导入与拆章全程无需额外配置。
- **失败暂停不降级**：模型不可用或调用连续失败时管线暂停并保留游标进度，修复配置后续跑；MUST NOT 静默退回脚本拆分，用户显式改选快速拆章是唯一兜底路径。
- **快速模式零变化**：章题解析、规则兜底分章、既有「AI 整理」队列全部保持现状。

## Capabilities

### New Capabilities

- `narrative-split`: AI 拆章行为契约——组章输入（衔接上下文 + 原文句流窗口）、结构化组章输出、执行器硬校验、章内分段重建、清洗自动修复直写、设定自动入库与合并、模型配置链。

### Modified Capabilities

- `novel-book-import`: 导入拆章方式选择；AI 模式预览形态（估算代替卷章树）；AI 模式建书事务（存档落盘、不建卷章）；随书删除级联；存量书无存档时 AI 拆章不可用。
- `book-import-pipeline`: AI 拆章队列形态（预估 N 个组章单元 + 收尾，逐章组章→清洗→设定自动入库）；失败暂停与续跑；收尾产出；快速导入书既有队列不变。

## 非目标

- 不改变快速拆章模式的任何现状行为（`parseStructure`、规则兜底分章、既有 AI 整理队列）。
- LLM 不通读全书（cutter 只见衔接上下文与句流窗口；cleaner 只读单章）。
- AI 模式不改写/生成正文——章节内容出自原文存档，清洗只做确定性修复。
- 不做 embedding 语义分割。
- 无存档书籍（存量书与快速拆章书）不做 AI 拆章，可重新导入或继续使用快速模式。

## Impact

- `packages/novel-store` — 存档元数据表与随书删除级联、书级 `split_mode` 标记。
- `packages/server` / `packages/schema` — 导入方式契约、AI 模式 analyze 预估产出、apply 落档与存档读取接口；涉新端点时 `bun run generate`。
- `packages/plugin` — 新增 `agents/cutter.ts`、`agents/cleaner.ts`；director 编排指令新增 AI 拆章队列流程；组章/清洗相关新工具（句流窗口、游标提交、章节落库）。
- `packages/app` — 导入方式选择控件、AI 模式预览（估算展示）、AI 拆章进度呈现。
- 数据兼容性：存档与 `split_mode` 为纯增量；快速模式行为零变化；存量书无存档仅 AI 拆章入口不可用。

# Design

## Context

导入解析链路现状（实测定论见 proposal.md - Why）：`decodeSource`（编码归一）→ `cleanText`（清洗）→ `parseStructure`（章题识别）→ 无章题且开启兜底时 `splitFixedLength`（3000 字硬切）。实测 2.8 万字无章题书：0 章题走兜底，8 个切口全部拦腰断句；清洗合并 648 行但残留 26 处段内碎行，段首缩进被 `trim()` 摧毁，广告行未清除且粘连正文第一段。

约束：deterministic-first（零 LLM）；遵循 AGENTS.md 风格（无 try/catch、无 any、early return、不预先提取单次 helper）；契约变更后须在 packages/client 重新生成 SDK。

## Goals / Non-Goals

**Goals**

- 清洗升级为段落重组（reflow）：段落信号驱动的合并决策，段内碎行聚合，广告特征扩充
- 兜底拆分升级为边界感知：目标字数范围可配（默认 2000–3000），切点优先级「段落边界 > 引号闭合句末 > 受限兜底」
- 范围参数进入契约、解析输入与预览令牌漂移检测

**Non-Goals**

- 不改动 `parseStructure` 章题/卷题模式族与章题路径行为
- 不改变兜底章节命名规则（沿用「第N部分」）
- 不处理诗歌/剧本等特殊版式的专门适配（只保证不误并、不丢内容）

## Decisions

### D1：段落重组以缩进/空行为首要信号，右引号为强分段信号

`cleanText` 逐行处理时在 `trim()` 前记录行首缩进标记（≥2 个半角空格或含全角空格 `　`），随 trim 后的行一起进入合并决策。合并决策树（按优先级）：

1. 当前行为空行 → 段落分隔（现状）
2. 当前行有缩进标记 → 新段落，不并入上一行
3. 上一行以右引号（`”` `’` `」` `』`）结尾 → 新段落（对话段保护；修复当前 `”` 不在句末集合导致对话被误并的 bug）
4. 上一行无句末标点 → 合并（句内断行，现状行为）
5. 上一行有句末标点、当前行无缩进、且全书存在段落信号 → 合并（段内句间碎行聚合，新增）
6. 否则 → 新段落（保守）

**护栏**：仅当全书缩进行或空行占比达到可判定水平（实施时定阈值，初始 5%）才启用规则 5；全书无缩进且无空行时退回现状行为（句末不合并），避免把整本书并成一段。

备选方案「句末标点一律不合并」（现状）被否决：对按视觉行宽硬换行的书源，大量行恰好以 `。` 结尾，段内碎行无法聚合——这正是实测残留 26 处碎行的根因。

### D2：边界感知拆分算法替代 `splitFixedLength`

新函数（命名实施时定，如 `splitByRange`）替换 `splitFixedLength`，调用方仅 orchestrate 一处：

- 输入：清洗后文本 + `{min, max}`；reflow 后段落为单行、空行分段，先按空行切出段落块及字符区间。
- 扫描：章起点 `cur`；剩余 ≤ `max` 时全部归入末章（允许 < `min`）；否则在 `[cur+min, cur+max]` 窗口内选切点：
  1. 窗口内最后一个段落边界（空行处）→ 切
  2. 否则窗口内最后一个「引号闭合的句末位置」（句末标点或右引号处，且自章首至该点 `“”「」『』` 计数各自平衡）→ 切
  3. 否则向后扩展至硬上限（`max + min / 2`）找最近句末 → 切并在问题清单标注受限切点
  4. 仍无 → `cur + max` 处切并标注（极端长句无标点，实测书不会触发）
- 拆分只决定章节边界，不修改正文任何字符。

### D3：契约与参数流

- `packages/schema/src/novel.ts`：导入预览与确认请求结构各加 `splitRange: optional(Struct({ min: Int, max: Int }))`；校验 `min >= 500`、`max <= 20000`、`min < max`，非法 400。
- `orchestrate.ts`：`fallbackFixedLength` 开关语义不变，`splitRange` 仅开关开启时生效，缺省 `[2000, 3000]`；`PreviewTokenPayload` 增加 `range` 字段，漂移检测沿用既有 `fixed` 字段模式（任一参数漂移即预览过期）。
- 契约变更后在 `packages/client` 运行 `bun run generate`，不手改生成目录。

### D4：导入预览 UI

开关旁加下限/上限两个数字输入（默认 2000/3000），变更复用开关的重新分析链路刷新预览与令牌；新文案进既有 locale 体系（zh/en/zht）。

### D5：广告特征扩充

`AD_LINE_PATTERN` 增加书源站名（搜书吧、soushu 等）与网址模式（`www.`、`http(s)://`、常见 TLD），维持「限短行（≤40 字符）命中」约束，正文提及网址的长行不误伤；清除计数入清洗摘要可审计。

## Risks / Trade-offs

- [诗歌/剧本类每行缩进的书被规则 2 逐行分段] → 不产生错误合并、不丢内容；拆分时退化到句末兜底，与现状相当
- [无缩进且无空行的书句间聚合失效] → D1 护栏退回现状行为，不劣化
- [右引号强分段把连续引用块逐段拆开] → 只影响分段粒度，内容无损；摘要有计数可审计
- [范围参数极端值导致章节过碎或过大] → D3 schema 校验下限 500、上限 20000、min < max
- [旧预览令牌因负载新增字段失效] → 由既有「预览过期」语义覆盖，用户重新分析即可，无数据迁移

## Migration Plan

纯解析层与契约新增字段变更，无持久化数据迁移；已入库书籍不追溯。回滚直接 revert，与已入库数据无耦合。

# Spec Delta

## MODIFIED Requirements

### Requirement: 编码自动检测与归一

系统 SHALL 自动识别文件文本编码（UTF-8 含或不含 BOM、UTF-16 LE/BE、GBK/GB18030、Big5）并统一归一为 UTF-8 原文后启动导入。识别置信不足时，系统 SHALL 明确报错并允许用户显式指定编码后重试，SHALL NOT 在编码不明时静默以错误编码解码入库。

#### Scenario: GBK 编码文件

- **WHEN** 用户导入 GBK 编码的 TXT 文件
- **THEN** 原文与后续章节产出为可读中文，不出现乱码

#### Scenario: UTF-16 编码文件

- **WHEN** 用户导入 UTF-16 LE 或 BE 编码的 TXT 文件
- **THEN** 系统正确解码并保存 UTF-8 原文

#### Scenario: 编码无法可靠识别

- **WHEN** 文件字节序列无法用任何受支持编码可靠解码
- **THEN** 系统提示编码识别失败，允许用户显式指定一种受支持编码重试；重试前不创建导入任务或书籍数据

### Requirement: 拆卷拆章结构解析

系统 SHALL 将章题、卷题、编号、段落和场景线索作为 Agent 分章依据，由 Agent 按阅读顺序逐章确定正式边界与标题。任何确定性标题匹配或字数统计 MUST NOT 在 Agent 阅读前直接生成正式章节；编号断裂、重复与乱序 SHALL 作为待处理线索保留。

#### Scenario: 常规章题拆分

- **WHEN** 原文含连续章题且 Agent 确认其与正文边界一致
- **THEN** 系统按 Agent 确认的边界逐章落库，各章标题与正文范围正确

#### Scenario: 含卷题拆分

- **WHEN** 原文同时包含卷题与章题且 Agent 确认归属
- **THEN** 系统按 Agent 确认的卷章结构落库，各章归属正确卷

#### Scenario: 特殊章归位

- **WHEN** 原文包含序章、楔子、前言、尾声或番外等特殊章题
- **THEN** Agent 结合上下文确定特殊章位置与类型，系统保留其特殊章标识

#### Scenario: 编号断裂与重复

- **WHEN** 章序存在跳号、重号或乱序
- **THEN** Agent 结合上下文判断结构并记录处理结果，系统不因编号异常而忽略或机械重排正文

#### Scenario: 隐藏章题

- **WHEN** 原文存在未匹配已知模式但语义上构成章节起点的标题
- **THEN** Agent 根据上下文确认其边界与标题，不因确定性模式未命中而忽略

#### Scenario: 无章节边界

- **WHEN** 全文没有可识别的章题
- **THEN** Agent 根据段落、场景和语义边界顺序重建章节，不提供固定长度分章入口

### Requirement: 确定性内容清洗

正文修复 SHALL 在 Agent 阅读各章原文时通过结构化操作完成，覆盖错误断段、连续对话断段、局部乱序、错字、广告与机械重复。系统 MUST NOT 在 Agent 阅读前用句末标点等单一规则直接改写或删除原文；每项修复 SHALL 可追溯到来源段落和处理理由。

#### Scenario: 段落不连续修复

- **WHEN** Agent 判断同一段落被硬换行错误断开
- **THEN** 系统按结构化合并结果生成连续段落，并保留来源关系

#### Scenario: 连续对话断段修复

- **WHEN** Agent 判断相邻短行属于同一对话轮次或被错误断开的表达
- **THEN** 系统按结构化合并结果生成章节正文，并保留这些行到输出段落的来源关系

#### Scenario: 局部乱序修复

- **WHEN** Agent 根据上下文确认当前阅读窗口内段落顺序错误
- **THEN** 系统按指定顺序重排并记录移动理由，原文快照保持不可变

#### Scenario: 噪声行清除

- **WHEN** Agent 确认广告、机械重复或无用内容
- **THEN** 系统记录排除操作及理由，导入报告可查看对应原文与处理结果

#### Scenario: 清洗摘要可见且可关闭

- **WHEN** 用户查看修复摘要，或在启动前选择关闭正文修复
- **THEN** 摘要持续展示各类操作数量；关闭后 Agent 仍执行语义分章，但正文只保留来源内容，不执行合并、移动、替换或排除

### Requirement: 事务化建书写入

启动导入时，系统 SHALL 在事务内创建书籍、原文和导入任务；每章 SHALL 独立事务提交正文、来源映射、处置账本与序号。任一章节提交失败 MUST NOT 留下该章半成品，也不得回滚此前已完成章节；全部原文处置和收尾完成后书籍转为正常可用状态。

#### Scenario: 写入失败回滚

- **WHEN** 启动事务创建书籍、原文或导入任务失败
- **THEN** 本次导入不产生任何书籍、原文或任务残留，用户得到可读错误提示

#### Scenario: 单章失败保留前序成果

- **WHEN** 第 N 章提交失败且此前已有章节完成
- **THEN** 第 N 章写入整体回滚，前 N-1 章及处理记录保持不变，可从第 N 章重试

#### Scenario: 成功导入

- **WHEN** 全部原文已消费或明确排除且全书收尾完成
- **THEN** 书籍卷章顺序正确，可在书架打开并正常使用既有导出、审阅与版本能力

### Requirement: 导入报告

导入完成后，系统 SHALL 展示统一报告：最终卷章结构、实际章节数、队列重规划次数、各类正文修复统计、排除内容、未解决问题、设定与技法产出及简介结果。报告 SHALL 提供打开书籍、查看章节原文对照和重新处理失败项的入口，不再提供二次「AI 整理」入口。

#### Scenario: 展示报告

- **WHEN** 导入任务完成全部章节与收尾
- **THEN** 报告展示最终结构、修复与抽取统计、未解决项和原文对照入口

#### Scenario: 报告保留问题清单

- **WHEN** 导入过程中发现编号异常、无法安全修复或其他未解决问题
- **THEN** 报告按章节保留问题清单与处理状态，便于用户逐项查看

#### Scenario: 报告反映计划修正

- **WHEN** 校准后的任务数量因原文实际消耗发生追加或取消
- **THEN** 报告列出重规划次数与原因，最终章数以实际落库结果为准

### Requirement: 导入输入边界校验

系统 SHALL 拒绝空文件与超过单书大小上限的文件，并给出可读提示；二进制内容伪装成文本文件时 SHALL 在启动阶段报错，不创建导入任务或书籍数据。

#### Scenario: 空文件

- **WHEN** 用户导入不含任何正文的文件
- **THEN** 系统提示文件为空，不创建导入任务或书籍数据

#### Scenario: 超大文件

- **WHEN** 用户导入超过单书大小上限的文件
- **THEN** 系统提示文件超出大小上限并给出上限数值，不创建导入任务或书籍数据

#### Scenario: 二进制伪装

- **WHEN** 用户导入扩展名为 TXT 但内容为二进制的文件
- **THEN** 系统提示文件内容不是有效文本，不创建导入任务或书籍数据

## ADDED Requirements

### Requirement: 原文持久化与只读保留

启动导入后，系统 SHALL 持久化完整 UTF-8 原文、内容哈希、稳定段落索引与处理进度。已处理内容 SHALL 通过游标和逐段处置状态标记为已消费或已排除，MUST NOT 通过物理删除原文推进；原文在任务完成、暂停和失败重试后均保持可读取。

#### Scenario: 推进不删除原文

- **WHEN** 一章提交成功并推进处理进度
- **THEN** 对应来源被标记为已消费或已排除，完整原文及其段落索引仍可查询

#### Scenario: 删除书籍清理来源

- **WHEN** 用户删除与导入任务关联的书籍
- **THEN** 该书的原文、段落账本和导入记录按书籍删除语义一并清理，不影响其他书籍

### Requirement: 导入配置与异步启动

导入前 SHALL 提供文件、编码、书名、目标章节长度倾向与内容修复强度（含关闭正文修复）配置。用户启动后系统先持久化导入任务，再异步唤醒 Agent；请求 MUST NOT 等待整书 LLM 处理结束，也不再展示机械章节预览或固定长度开关。

#### Scenario: 启动后立即可查看任务

- **WHEN** 用户确认导入配置并启动
- **THEN** 系统返回书籍与任务标识并进入实时处理页，Agent 在后台持续处理，页面无需等待整书完成

#### Scenario: 启动前取消

- **WHEN** 用户尚未启动导入便取消
- **THEN** 系统中不存在与本次导入相关的书籍、原文或任务数据

### Requirement: 实时处理界面

导入处理页 SHALL 展示当前阶段、真实原文处理比例、当前章节与阅读范围、已产出章节、队列状态和修复统计。校准阶段 MUST NOT 显示虚假的精确总章数；暂停、恢复与重试后页面 SHALL 反映持久化状态而非仅依赖当前页面内存。

#### Scenario: 校准阶段展示真实进度

- **WHEN** 导入仍处于前段结构校准
- **THEN** 页面显示校准状态、已完成章节和原文比例，不显示未经校准的总任务数

#### Scenario: 处理中查看章节

- **WHEN** 至少一章已提交且后续章节仍在处理
- **THEN** 用户可打开已完成章节并同时看到当前处理状态继续更新

#### Scenario: 重新打开处理页

- **WHEN** 用户离开处理页后重新进入未完成任务
- **THEN** 页面恢复显示持久化进度、队列和最近状态，不重新开始导入

### Requirement: 原文对照与修复可见性

系统 SHALL 为每章提供正文与原文对照，展示合并、拆分、移动、替换和排除的来源及理由。用户 SHALL 能区分原文保留、自动修复和待人工判断内容；任何自动修复 MUST NOT 只存在于对话记录而无法在导入报告中查看。

#### Scenario: 查看段落修复依据

- **WHEN** 用户在报告或章节处理记录中查看一项自动修复
- **THEN** 系统展示来源段落、处理后内容、操作类型与理由

#### Scenario: 查看排除内容

- **WHEN** Agent 将广告或重复内容排除在正式正文外
- **THEN** 用户可在报告中查看被排除原文及排除原因

### Requirement: 存量本地数据兼容

导入数据模型升级 SHALL 采用新增持久化结构，不修改既有书籍正文与卷章结构。既有书籍 MUST NOT 被自动回填原文或启动重处理；需要新导入流程的存量书由用户显式重新导入原文件。

#### Scenario: 打开既有书库

- **WHEN** 用户升级后打开包含既有书籍的本地书库
- **THEN** 新增导入结构可用，既有书籍、章节和设定内容保持不变

#### Scenario: 存量书无原文来源

- **WHEN** 用户查看升级前创建且没有原文快照的书籍
- **THEN** 系统不虚构原文对照，也不自动启动导入任务

## REMOVED Requirements

### Requirement: 导入预览与确认

**Reason**: 机械解析预览会在 Agent 阅读前固化错误结构，已由导入配置与实时处理页取代。

**Migration**: 用户启动后直接在实时处理页查看真实章节产出，不再确认预解析章节目录。

### Requirement: 固定长度兜底预览再生

**Reason**: 固定长度切分会产生断句与场景截断，新流程对所有书籍统一使用 Agent 语义分章。

**Migration**: 无标题书籍直接进入同一原文驱动流程，不迁移固定长度开关或预览令牌。

### Requirement: 导入后 AI 整理受控委托

**Reason**: 分章、正文修复、设定与技法整理已合并到导入主任务，二次委托会重复阅读并产生相互独立的处理状态。

**Migration**: 启动导入即自动执行完整整理，旧「AI 整理」按钮与建队指令由实时处理页和统一报告替代。

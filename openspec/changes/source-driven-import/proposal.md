# Proposal

## Why

现有导入在 Agent 阅读前就用确定性规则清洗并拆章，随后的整理只能基于既有章节汇报问题或修补边界，无法可靠解决原书已有的段落错位、连续对话错误断段、局部乱序与噪声残留。需要把导入改为由不可变原文驱动、Agent 顺序判断边界并同步修复正文的完整流程，同时避免任务总数随每章处理不断变化。

## What Changes

- **BREAKING**：以「原文入库 → 前段校准 → 稳定队列 → 逐章分章与修复 → 全书收尾」取代现有 analyze/apply 机械解析建书、固定长度兜底和导入后独立「AI 整理」流程；标题解析与字数统计都只作为 Agent 可参考的信号，不再直接决定正式章节。
- 导入开始时持久化完整解码原文、稳定段落索引、导入配置、处理游标与逐段处置账本；原文只读保留，以逻辑消费取代物理删除，支持断点恢复、失败重试和原文对照。
- Agent 按完整段落和模型上下文预算流式阅读，逐章确定标题与章末；候选边界不合理时自动追加段落，达到上下文上限仍无法安全分章时明确受阻，不静默硬切。
- 分章与内容修复共用同一轮阅读：通过结构化段落操作完成断段合并、连续对话恢复、局部乱序调整、错字与无用内容修复；所有正文改动可追溯，禁止无来源改写或补造正文。
- 前约 25% 原文用于结构校准，不展示虚假的预计总章数；校准后一次性生成剩余章节队列，正常推进只更新状态，不重估总数。仅在原文耗尽但任务剩余、任务耗尽但原文剩余、发现足以使计划失效的结构或用户修改配置时重规划未开始尾部。
- 每章通过来源覆盖、重复消费、边界衔接和结构化操作校验后自动落库，不要求逐章人工确认；设定候选、技法学习、书籍简介与最终汇总保留并接入同一导入任务。
- 重做导入 UI：从「解析预览 → 确认机械章节 → 报告后再整理」改为「导入配置 → 实时处理与章节产出 → 统一报告」，提供校准状态、真实进度、动态队列、原文对照、修复统计、暂停/恢复/重试和未完成项。
- **BREAKING**：移除旧导入 analyze/apply 契约及固定长度开关、旧导入报告「AI 整理」二次入口；扩展 WorkRun 以支持保留历史状态的待处理尾部重规划。
- 本提案取代尚未合入的 `fixed-split-restructure` 路线，并覆盖 Issue #32、#33、#34 的可见性、分章与正文清理目标；不在旧重切实现上继续叠加。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `novel-book-import`: 导入从确定性预览后建书改为原文持久化、Agent 顺序重建、实时处理与统一报告；保留编码识别、文件边界、事务安全和既有书籍使用能力。
- `book-import-pipeline`: 静态 N+3 整理队列改为前 25% 校准、稳定后续队列、逐章分章修复与可追溯落库、必要时尾部重规划。
- `agent-work-continuation`: WorkRun 增加只替换待处理单元的重规划语义，已完成、进行中、跳过和受阻历史不得被重写。

## Impact

- `packages/novel-store`: 新增导入任务、原文/段落索引、段落处置与章节来源映射等持久化模型及事务接口；迁移仅新增数据，不修改既有书籍、章节和设定内容。
- `packages/core`: 扩展 WorkRun 待处理尾部重规划与恢复语义；其他写作、审查队列的既有推进语义保持不变。
- `packages/plugin`: 新增原文读取、候选章节提交、校准建队、修复统计与收尾工具/编排提示，移除旧固定分章分诊与导入后静态整理指令。
- `packages/schema`、`packages/protocol`、`packages/server`: 以新导入启动、状态查询和控制契约替换 analyze/apply；启动只负责持久化与 durable prompt admission，不在 HTTP 请求内执行整书 LLM 工作。
- `packages/client`、`packages/sdk`: 公开契约变化后重新生成 SDK，禁止手改生成文件。
- `packages/app`: 重构导入向导、处理页、队列与报告页，接入实时状态和原文对照；旧导入相关组件、查询和测试同步清理。
- `packages/desktop`: 复用现有桌面文件选择、后端托管与语言行为，不新增原生导入通道。
- 兼容性：既有本地书库通过新增表迁移打开，既有书籍不自动重建、不回填原文；既有非导入 WorkRun 不受影响。旧导入接口属于有意破坏性替换，app 与生成客户端同步升级。

## Non-goals

- 不保留快速机械导入、固定长度分章或导入后再手动启动整理的双流程。
- 不要求用户逐章审批，也不另建 `chapter-cleanup-review` 的独立修订审批实体；以自动结构化修复、原文对照和章节版本承担审阅与回滚。
- 不允许 Agent 脱离原文自由重写、续写或补全原书缺失内容。
- 不对存量书籍虚构原文来源，不自动重处理既有书籍；需要新流程的存量书由用户重新导入原文件。
- 不并行拆分全书给多个 Agent，不在本变更中引入跨书籍导入调度或云端处理。

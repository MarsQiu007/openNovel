# Proposal

## Why

风格指南的编辑界面（风格设定表单）只有 4 个扁平字段：基调（tone）、视角（pov）、时态（tense）、规则（rules，每行 `键: 值` 手工解析的文本域）。AI 生成或用户构思的风格通常是结构化长文——叙事节奏、对话与描写比例、章节结构偏好、语言风格要点等分区内容——塞不进单一文本域，且现状存在三个体验缺陷：

1. 规则以裸键值文本行呈现，无分组、无键名提示，回看与编辑成本高；
2. 文本域解析失败的行**静默丢弃**（保存时过滤掉无法解析的行，无任何反馈），用户以为存上了其实丢了；
3. 即使 `style-guide-pipeline` 打通了落库通道，UI 侧仍无法完整、可读地展示与编辑落库的风格规则。

## What Changes

- 风格编辑界面重构为分区结构：基调三要素一组，写作规则按语义分区（叙事节奏、对话与描写、章节结构、语言偏好、「其他」兜底）分组展示。
- 每条规则改为键 + 值成对控件编辑，支持添加与删除规则行；解析失败静默丢弃的问题随结构化编辑自然消除。
- 保存前校验：键为空的规则行阻止保存并标示问题行。
- 规则键输入提供常用键名建议，自定义键不受限。
- 篇幅限制复选框与 `chapter_length_limit` 键的承载关系保持现状。
- API 契约不变（`update-style-guide` 端点与 `rules: Record<string, string>` 形态不动），无需重新生成 SDK。
- `style-rules-pipeline` 的读取侧归一化契约不变；其「面板以每行一条 `键: 值` 展示」的展示形态要求随本变更修改为规则行成对控件（见 Modified Capabilities）。

## Capabilities

### New Capabilities

- `style-editor-ui`: 风格指南编辑界面的结构化编辑契约——分区展示、规则行成对编辑、无效行保存前反馈、键名建议与篇幅限制承载不变。

### Modified Capabilities

- `style-rules-pipeline`: 「读取侧与写入侧同构归一化」要求中，风格编辑面板的展示形态由「每行一条 `键: 值`」改为规则行（键与值成对控件）；归一化语义与「展示与回存一致」要求不变；设定检查工具与内嵌阅读器风格页的文本形态展示不变。

## Impact

- **packages/app**：`src/pages/novel/style-guide-editor.tsx` 重构 + 新增规则模型纯函数模块（分区归组、校验、序列化）及其单测；不改 i18n locale 文件（分区标题沿用界面内硬编码中文先例）、不改 API 契约。
- 与 `style-guide-pipeline` 的衔接：其落库通道决定本编辑器消费的数据来源与丰富度，已归档实施。

## 非目标

- 不改 StyleGuide 表结构与 rules 归一化契约（写入归一化、拒绝写入、快照渲染行为均不动）。
- 不新增 i18n key（分区标题与操作文案沿用界面内既有硬编码中文先例）。
- 不做 AI 生成风格的前端入口（生成动作在会话内由 director 路由，见已归档的 `style-guide-pipeline`）。
- 不改设定检查工具与内嵌阅读器风格页的展示形态。

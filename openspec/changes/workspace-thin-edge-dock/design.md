## Context

当前工作台布局由全局持久化状态 `novel.workspace.layout.v1` 驱动，已有左/右栏手动收起、拖拽宽度、窄屏自动收边、右栏 peek/expand 与活动面板状态。实现上，左/右 `aside` 在收起态直接 `hidden`，全局页头只保留两个低对比度箭头。相关宽度常量和阈值派生集中在 `packages/app/src/pages/novel/workspace-pane-width.ts`。

## Goals / Non-Goals

**Goals:**

- 左右栏收起后保留 32px–40px 的可见薄边坞。
- 左坞保留导航模式入口和当前模式高亮；右坞保留当前活动面板入口和生成活动指示。
- 不引入新的布局状态结构；继续复用 `leftManual`、`railManual`、分栏宽度和右栏活动面板状态。
- 自动收边阈值计入薄边坞保留宽度，避免收起后主区保底被薄边坞挤穿。
- 收纳控件靠近对应分栏，减少全局页头箭头造成的歧义。

**Non-Goals:**

- 不修改后端协议、服务端 API 或 SDK。
- 不升级持久化版本，不迁移本地数据。
- 不修改 `packages/app/src/i18n/*.ts`；优先复用现有工作台与面板文案键。
- 不重构 peek/expand、小说会话绑定或数据模型。
- 不新增跨书籍布局记忆分支。

## Decisions

### 1. 用常驻薄边坞替代浮动手柄

保留左右两个分栏容器，只是根据收起态切换宽度与内容形态：

```text
展开态:
[ 左栏 220-400px ] [ 主区 ] [ 右栏 320-560px ]

收起态:
[ 左坞 36px ] [          主区          ] [ 右坞 36px ]
```

- 左坞：纵向显示设定、大纲、章节三个紧凑入口，当前模式高亮；点击入口只切换主区，不强制展开左栏；另有展开箭头。
- 右坞：显示当前活动面板图标和展开箭头；有生成任务进行中时追加活动指示。点击活动面板或箭头恢复右栏。
- expand 态：两个分栏容器进入薄边坞形态；右坞当前活动面板入口可作为返回常规布局的可见入口。
- 展开态渲染现有分栏内容、拖拽手柄和右栏图标列；收起态隐藏完整内容与拖拽手柄，只渲染坞内容。

这样优于继续调整页头箭头：薄边坞同时表达“这里有一栏”“它当前收起”“当前保留了什么状态”。也优于 hover 临时抽屉：不依赖悬停发现，桌面端触控板和窄屏场景更稳定。

### 2. 移除页头两个全局收纳箭头

收纳入口移到对应坞内后，页头左侧和右侧的现有箭头按钮应移除，避免同一个动作出现两个位置。左坞/右坞按钮继续使用现有 `toggleNav`、`toggleRail`、导航模式和面板标签文案键，并通过 `aria-expanded`、`aria-label` 和 tooltip 表达状态。

### 3. 布局状态继续使用 v1 结构

不新增“dock mode”字段。现有 `boolean` 收起态自然解释为“完整面板收起、薄边坞可见”；`null` 继续交给自动宽度规则。旧数据、非法枚举和非数值宽度仍按现有安全降级路径处理。这样可以在不迁移数据的情况下回滚到旧渲染。

### 4. 阈值计入薄边坞保留宽度

在宽度派生模块中补充左坞/右坞常量，并把保留宽度纳入 `collapseThresholds` 的输入。测试目标从“归档固定阈值不变”调整为“自动收边完成后，主区内容区域宽度不低于 720px”。`ResizeObserver` 继续观察三区布局外层容器，避免因主区宽度变化造成收起/展开反馈振荡。

### 5. 视觉与可访问性

薄边坞使用主题背景、边框和 hover/active 态，使其在深色写作界面中可辨识但不抢焦点。默认宽度取 36px，在 32px–40px 规范内保证紧凑入口有足够点击面积。所有坞内操作必须是真实按钮，支持键盘焦点和焦点可见性；活动模式/面板用主题强调色，而不是只靠图标方向区分。

## Risks / Trade-offs

- [薄边坞永久占用约 72px 宽度] → 阈值计算计入坞宽；坞内使用紧凑图标，不显示长文案。
- [左坞 3 个入口加展开箭头可能拥挤] → 使用纵向图标按钮和 tooltip，保持 36px 宽度；不为当前模式显示完整标题。
- [阈值变化造成既有宽度测试回归] → 更新阈值单测，覆盖默认宽度、拖窄右栏、拖宽右栏和历史非法值。
- [expand 态下坞入口与既有右上返回按钮重复] → 保留右上返回作为显式自救入口；右坞入口仅显示当前面板状态，不承担额外文案。
- [自动收边和手动收起叠加导致状态误恢复] → 继续保留“当前会话手动选择优先，宽度回到阈值以上后交还自动规则”的现有约定。

## Migration Plan

无数据迁移和 API 变更。实现可按宽度常量、左右坞 UI、阈值验证的顺序推进；回滚到上一个应用版本即可恢复旧的隐藏式收起态。

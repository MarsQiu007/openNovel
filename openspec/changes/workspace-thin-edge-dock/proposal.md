# 提案：工作台悬停边缘收纳条

## Why

工作台左右分栏已有收起能力，但当前常驻薄边坞既占用横向空间，也让收纳状态过于突兀。用户希望在展开态平时“看不见”收纳控件，只有靠近对应边缘时出现轻量线索；收起态则把空间完全还给主区，并在边缘保留可发现、可点击的恢复入口。

## What Changes

- 展开态：移除常驻边缘图标坞。鼠标悬停左侧或右侧面板时，在对应分栏边界外侧淡入虚化收纳条；键盘聚焦到收纳条时也必须可见。
- 点击展开态收纳条后，对应面板完全收起；导航、大纲、章节、会话、活动面板等状态保持挂载。
- 收起态：左右分栏不再保留 36px 图标坞，主区获得完整宽度。边缘保留低透明度幽灵把手和窄热区，但不占用布局宽度。
- 收起态鼠标悬停或键盘聚焦边缘时，淡入展开控件；点击后恢复对应面板。
- 右栏 expand 态也使用同一边缘逻辑提供返回常规布局入口。
- 拖拽调整宽度期间隐藏可点击收纳条，避免与 resize 交互冲突。
- 移除页头的左右收纳箭头，把入口留在对应边缘。
- 保留 `leftManual`、`railManual`、分栏宽度和右栏活动面板的持久化语义；自动收边不再为图标坞预留宽度。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `novel-workspace-layout`: 面板收起形态从“常驻可见薄边坞”改为“悬停边缘收纳条 + 完全隐藏面板”；恢复入口改为常显幽灵把手和边缘热区上的 hover/focus 控件。

## Impact

- 影响包：`app`，主要是工作台布局容器、边缘控件和宽度阈值。
- 不影响 `novel-store`、`plugin`、`opennovel` 后端协议、桌面进程管理和本地数据格式。
- 现有布局持久化数据可继续读取；旧收起布尔值按“面板完全隐藏”的新语义渲染。

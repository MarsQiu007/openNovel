# 提案：工作台薄边坞收纳

## Why

当前书籍工作台左右栏收起后完全隐藏，只在顶部保留两个低对比度箭头入口。左侧入口还紧挨“返回”按钮，右侧入口混在导出、待审批和写作模式之间，导致用户难以发现侧栏只是被收起，也难以快速恢复。

## What Changes

- 将左右栏收起态从完全隐藏改为保留 32–40px 的“薄边坞”。
- 左侧薄边坞保留导航语义，显示设定、大纲、章节等入口；当前导航模式高亮，并提供明确展开箭头。
- 右侧薄边坞保留随行面板语义，显示当前活动面板图标；对话、检视面板等状态仍由右栏状态控制，并提供明确展开箭头。
- 展开态的收纳入口移到对应分栏薄边坞内，并移除全局页头的两个收纳箭头，避免和返回、导出、待审批等页头操作混淆。
- 保留现有拖拽收起、窄宽度自动收边、面板活动状态与布局持久化能力；仅改变收起后的可见形态与入口组织。
- 非目标：不改变右栏面板的 peek / expand 交互模型，不重构小说会话绑定或数据模型，不移除分栏宽度持久化，不新增跨书籍布局分支。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `novel-workspace-layout`: 左右栏手动收起的行为从“面板区域完全隐藏”改为“保留可见薄边坞”；收起态必须显示归属明确的恢复入口和活动状态。

## Impact

- 影响包：`app`，主要是书籍工作台布局与图标入口。
- 可能需要同步调整布局相关组件的宽度计算、右栏图标列挂载位置与样式。
- 不影响 `novel-store`、`plugin`、`opennovel` 后端协议、桌面进程管理和本地数据格式。
- 现有布局持久化数据可继续读取；旧布尔收起态按原语义解释，渲染形态统一改为薄边坞。

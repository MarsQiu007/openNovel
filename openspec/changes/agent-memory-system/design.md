# Design: agent-memory-system

> 本设计由五轮讨论收敛而成（2026-10-20）。外部参照：OpenHands 双层记忆模式、vectorize-io/hindsight（只吸收设计，不引入实现）。

## 1. 总体架构

```
                +-------------------------------------------+
                |  注入召回包（物化视图，章通过时预计算）      |
                |  起草时 = 一次数据库读                      |
                +---------------------^---------------------+
                                      | 组装器
                +---------------------+---------------------+
                |     横切状态层: pending -> reviewed ->     |
                |     approved -> stale -> retired          |
                +--------+-----------+-------------+--------+
                         |           |             |
              +----------+--+ +------+------+ +-----+--------+
              | 正文事实表   | | 设定引用     | | 技巧卡        |
              | (新增)      | | (既有表+    | | (新增,事件    |
              | 引句+出处   | |  落文状态)   | |  出处+账本)   |
              +----------+--+ +------+------+ +-----+--------+
                         |           |             |
              +----------v-----------v-------------v--------+
              |  既有本体：角色表 / 世界观表 / 伏笔表          |
              |  （不动，唯一本体）+ FTS5 检索                |
              +----------------------------------------------+
                    SQLite 单库，无向量库、无外部服务
```

核心不变量：

- **单一数据世界**：一切记忆都在 novel-store 的 SQLite。文件不是存储本体（导出快照是旁路功能，远期）。
- **事实卡是派生物**：注入层没有独立存储，任何时刻可从本体表重建。
- **出处强制**：无出处的卡不存在（正文事实=章号+原文引句；设定引用=条目 ID；技巧=评审事件链）。
- **本书硬隔离**：所有记忆表带 `book_id`，注入/检索第一道过滤永远是 `WHERE book_id = ?`。跨书共享在数据层不可能，不靠 agent 自觉。

## 2. 数据模型（novel-store 新增）

### 2.1 正文事实表 `memory_fact`

```
id              PK
book_id         FK -> book          -- 硬隔离
chapter_id      FK -> chapter       -- 出处章
quote           TEXT                -- 原文引句（逐字，校准锚点）
quote_span      TEXT                -- 引句在正文中的定位（偏移区间）
entity_hint     TEXT?               -- 关联实体提示（角色/世界观 ID，可空）
text            TEXT                -- 结构化事实陈述（保留原文语态，不改写归一）
status          TEXT                -- pending | reviewed | approved | stale | retired
confidence      INTEGER             -- 0-100；来源分级：作者裁决 > 审计校准 > 即时登记
proof_count     INTEGER DEFAULT 1   -- 独立支撑章数（吸收 Hindsight observations）
created_by      TEXT                -- draft-register | audit | author
created_at / updated_at
```

FTS5 虚表 `memory_fact_fts`（text 列），触发器同步。

### 2.2 技巧卡表 `memory_skill`

```
id              PK
book_id         FK -> book
statement       TEXT                -- 技巧陈述（"对白推进情节在本卷审校反馈良好"）
source_events   JSON                -- 评审事件链（auditID/discard 理由/裁决结果）
status          TEXT                -- 同上状态机；转正门槛=作者确认（高于事实卡）
usage_ledger    JSON                -- 饱和度账本 {近期使用: {卷, 章, 次数}}
scope           TEXT                -- book（默认）| author（显式晋升的作者级）
promoted_from   FK?                 -- 晋升来源卡（retired 留痕链）
```

饱和度账本由注入组装器维护：每次注入某技巧卡且本章正文采用了相应手法，登记一次使用。

### 2.3 既有表加列

- 世界观/角色条目：`establishment` 列（`planned | established`）+ `established_chapter_id?`——设定落文状态。伏笔表已有埋设/回收语义，不加列。

### 2.4 物化注入包 `memory_injection_snapshot`

```
book_id + chapter_id    联合键（为"下一章"预计算）
payload                 JSON    -- 五件套序列化结果
built_at / budget_used  元数据
```

章审批通过事件触发重建；起草开始时一次读。同一输入必得同一注入包（可测试、确定性）。

## 3. 生命周期状态机

```
起草登记        审计校准         审批通过          文本变更(diff命中引句)
[pending] --> [reviewed] --> [approved] --------+------> [stale] --> 重新提取+校准
 当章生效，      出处核实，       事实正式确立     |                        |
 降权注入       冲突已裁决                        |                        v
                                             未命中引句          [reviewed] 或
                                             保持 approved       [retired]（设定被删，留痕）
```

- **pending 的空窗风险**（登记未审计就出错）由"下一章注入时 pending 卡降权"兜底。
- **触发器挂文本变更事件**（章节状态提交、编辑器保存），agent 修订与作者手改两条路自动汇合——不挂 agent 流程步骤，否则手改静默过期。
- **diff 范围失效**：正文修改时，diff 与 `quote_span` 比对，只失效命中的卡；改正别字不惊动全书记忆，避免修订循环的状态抖动。
- **retired 不删行**：同"角色只能退场不能删除"哲学。

## 4. 冲突处理

新事实与既有卡矛盾（含设定引用与正文事实矛盾）时：

1. 不自动裁决。生成冲突单：双方卡片 + 两方向影响成本对比
   - 方向 A（顺正文改设定/旧记忆）：动 N 张卡
   - 方向 B（逆设定改正文）：受影响章节清单
2. 走现有审批闸门，作者裁决。
3. 裁决 A：更新本体/记忆，状态机自动流转。
4. 裁决 B：生成回改任务清单（引用关系可查询——结构化存储的核心红利）。

原则：**已写正文 > 设定**（读者只见正文）。系统摆成本，作者定方向。

## 5. 召回

### 5.1 注入召回（被动，五件套）

| 序 | 内容 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| 1 | 本章出场角色卡 | 活跃角色快照（既有） | 复用现有"已出场/活跃"概念 |
| 2 | 活跃伏笔卡 | 伏笔表 | 已埋设未回收 |
| 3 | 相邻章新事实 | memory_fact | 前 2-3 章的 approved 卡 |
| 4 | 当前卷 planned 设定 | 既有设定表 | 提示可用弹药 |
| 5 | 本书技巧卡 | memory_skill | 含饱和度（"断章悬念卷二已用 11/14 章"） |

体量预算（目标 <4K tokens）内按 权重三信号（引用频次 + 近因 + 确认级别）排序截断。审校子代理同样吃技巧卡（审"是否遵守已验证经验"）。

### 5.2 检索召回（主动）

工具签名（草案）：

- `memory_search(query, filters?)`：FTS5 全文 + 结构化过滤（实体/类型/状态/章节范围）
- `memory_register(fact, quote, chapterID, entityHint?)`：起草即时登记（写 pending 卡）
- `memory_lookup(entityID)`：实体全史（"银瞳症在哪几章出现过"）

多语言原则：`text` 与 `quote` 保留原文语态，禁止翻译/改写归一（吸收 Hindsight multilingual 的动机；中文语料天然成立，写入约束防未来漂移）。

## 6. 整理与合并

| 触发 | 时机 | 动作 | 风险级别 |
| --- | --- | --- | --- |
| 事件驱动（主） | 章审批通过时 | 本章相关卡去重、同义合并、账本更新 | 自动 + 可撤销 |
| 阈值触发 | 注入组装超预算 | 针对性瘦身（低权重卡出包） | 自动 + 可撤销 |
| 定时兜底 | 后台 job | 僵尸卡清扫、planned 滞留提醒、retired 归档统计 | 报告制，不自动删 |

合并升级三通道（全部单向、过审批、原卡 retired 留痕）：

1. 自由事实碎片 -> 正式实体条目（角色/世界观表，走既有登记流程）
2. 计划设定 -> 落文正文事实（establishment 流转）
3. 技巧经验 -> 分层规范文件（agent-instruction-layering 领地），记忆层随之 retired

记忆系统定位：**从 agent 学到的流动知识，向作者确认的固化知识的上升管道**。

## 7. 与其他 change 的协同边界

- **agent-instruction-layering**：规范（作者写的、稳定、分层文件）与记忆（增长的、agent 沉淀）注入通道独立，互不吞并；技巧固化的落点在对方。
- **agent-task-subagent**：审校子代理的干净上下文 = 设定集 + 目标章节 + 技巧卡；审校产出的评审事件是技巧卡的上游来源。
- **37 维审计**：本变更不改审计维度；审计是记忆校准的执行者之一（reviewed 状态的生产者）。
- 文风统计基线：语料现算的 computed metric，存书级元数据，**不进记忆**（记卡必漂移）。

## 8. 迁移与实施顺序（tasks 阶段细化）

1. novel-store：表 + 状态列 + FTS5 + 迁移脚本
2. 组装器 + 物化注入包（先只做五件套，预算截断）
3. 登记/检索工具挂 tool registry + system prompt 起草纪律
4. 流水线挂钩：审计校准、审批预计算、文本变更事件失效
5. 冲突裁决单 + 审批闸门对接
6. 技巧卡 + 账本 + 晋升/固化通道
7. 整理 job + 滞留提醒
8. app 记忆查看/编辑界面（可拆独立后续 change）

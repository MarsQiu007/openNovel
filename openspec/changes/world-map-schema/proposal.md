## Why

当前地图页只是占位提示，小说世界地理没有结构化数据模型。为了让后续矢量地图渲染、手动编辑和 AI 生成草稿有统一、可校验的持久化基础，需要先建立世界地图数据层。

## What Changes

- 新增世界地图持久化模型，支持每本小说最多一个 `active` 正式世界地图和一个 `draft` 地图草稿。
- 新增地图要素模型，第一版只覆盖 `region` 区域和 `place` 命名地点。
- 新增角色图钉模型，用于记录角色在当前世界地图中的位置。
- 为地图、地图要素和角色图钉提供基础 CRUD API。
- 使用局部平面坐标 `x/y`，统一约束在 `0..10000`，不使用经纬度或屏幕像素坐标。
- 世界观条目删除时保留地图要素，仅解除关联；角色删除时级联清理对应图钉；小说删除时级联清理整张地图数据。
- 通过幂等迁移添加新表，不修改或重写既有小说数据。

### 非目标

- 不实现 Leaflet 渲染、缩放、平移、hover 或详情界面。
- 不实现地图编辑器、拖拽保存或角色匹配建议。
- 不实现 AI 生成世界地图草稿。
- 不支持路线、河流、山体、装饰图层、地图版本历史或多层级下钻。
- 不支持地理投影、瓦片底图或经纬度坐标。

## Capabilities

### New Capabilities

- `world-map-data`: 世界地图、地图要素和角色图钉的本地持久化、生命周期约束与基础 CRUD 行为。

### Modified Capabilities

_none_

## Impact

- `packages/novel-store`：新增 Drizzle 表定义、DDL、索引、外键和幂等迁移。
- `packages/opennovel`：新增地图数据的后端处理逻辑。
- `packages/schema` / `packages/protocol`：新增地图 CRUD 的公共数据契约。
- `packages/client`：在公开 API 变更后重新生成客户端代码。
- `packages/app`：本提案不修改界面；后续渲染与编辑提案才会消费这些 API。
- 现有数据库兼容性：只做增量建表，不迁移旧数据；已有小说、世界观和角色数据保持不变。

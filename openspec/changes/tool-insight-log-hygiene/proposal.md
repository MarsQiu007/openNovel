# Proposal：tool-insight-log-hygiene

## Why

工具改进日志现在把「运行期是否存在问题」与「每个 Location 启动」绑在了一起：空的共享日志根会不断生成只有 0 问题索引的目录，复测临时项目也会留下哈希目录；同时多个插件实例可能重复消费同一批事件，导致同一证据被写入多份。这会让用户把真实的改进信号淹没在空目录和重复记录里，也削弱了自我优化数据的可信度。

## What Changes

- 将 tool-insight 的落盘从「启动即初始化」改为「按需落盘」：无证据、无问题文档、无复测记录时不创建索引、锁目录或空日志根。
- 将复测临时 Location 与常规写作 Location 的日志边界分离：复测遥测只归属原问题与复测运行，不为每次临时运行创建新的常规项目日志根。
- 收紧事件归属与去重：同一事件由明确的采集归属方消费一次，共享日志根中的证据标识在存储层保持唯一，避免多实例复制和同根重复追加。
- 增加轻量负反馈信号层：用户对 LLM 说出「不对 / 错了」这类纠正时，先只记录低噪声的结构化信号与目标范围，不直接保存完整对话原文或小说正文。
- 为负反馈提供确认升级路径：高频、重复或用户明确要求的负反馈可以升级为现有 `user_report` 问题文档；普通负反馈保持为信号，不自动建完整 issue。
- 保留证据先行原则：客观证据仍可先于模型分析保存，但空状态不再产生用户可见的日志骨架。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `tool-insight-log`: 修改日志根、空状态落盘、复测隔离、事件归属去重、证据唯一性和用户负反馈采集/升级的行为要求；不改工具改进日志的整体能力边界。

## Impact

- 主要影响 `packages/plugin` 中 tool-insight 的采集、整理与复测编排。
- 可能影响 `packages/novel-store` 中路径解析、JSONL 追加与读取辅助。
- 可能影响 `packages/core` 中事件订阅、后台会话或 Location 归属相关的行为；需要避免插件跨项目重复消费事件。
- 不修改写作工具的业务语义，不新增数据库表，不改变现有问题文档格式；旧目录中的历史文件保留只读兼容。
- 涉及负反馈信号时，需要处理会话消息或反馈意图与 tool-insight 的边界，必须遵守现有隐私白名单和脱敏截断规则。

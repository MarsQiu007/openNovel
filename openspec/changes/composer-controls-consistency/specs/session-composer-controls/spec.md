# Spec Delta: session-composer-controls

## ADDED Requirements

### Requirement: 代理列表跨入口收敛到同一真源

无论以何种入口进入会话页（页面刷新、书架点击、会话切换、新开会话），代理选择器呈现的可选项 SHALL 收敛到同一真源的最新全量：server 端注册表在页面打开后继续增量落地时，列表 SHALL 自动更新至全量，无需用户手动刷新或重新进入页面。加载代理列表期间 SHALL 呈现加载占位，不得把"尚未加载"呈现为"无代理可选"。

#### Scenario: 注册表晚于页面打开落地

- **WHEN** 用户在 server 注册表尚未全量落地时打开会话页
- **THEN** 代理选择器先呈现加载占位；注册表落地后列表自动补齐到全量，期间无需任何手动操作

#### Scenario: 不同入口终态一致

- **WHEN** 用户分别以页面刷新与会话切换两种方式进入同一项目的会话页
- **THEN** 两种方式稳定后代理选择器呈现的选项集合完全一致

### Requirement: 控件栏加载过程形状稳定

代理、模型、推理档位三个控件 SHALL 由单一的区域就绪信号统一控制呈现：未就绪时控件栏渲染与最终控件同布局的占位形态，就绪后三个控件同时切换到最终形态。任何单一数据通道的就绪或刷新都不得导致控件逐个出现/消失。占位与最终形态在控件栏高度上 SHALL 一致（无垂直跳动）；水平宽度允许近似（终态宽度由内容决定），加载过程不得出现控件整块消失的形态。

#### Scenario: 占位到终态无跳动

- **WHEN** 用户打开会话页并观察底部控件栏从加载到就绪的全过程
- **THEN** 占位与最终控件的尺寸、位置一致，切换瞬间内容所在栏位不发生位移

#### Scenario: 三控件同时切换

- **WHEN** 代理数据先于 provider 数据到达
- **THEN** 代理控件不单独闪现，三个控件保持占位形态直至区域就绪信号满足后同时呈现

### Requirement: 推理档位控件显隐由模型数据属性决定

区域就绪后，推理档位控件的存在性 SHALL 仅由当前模型是否配置推理档位决定：已配置时呈现可选控件；未配置时呈现禁用占位并提示当前模型不支持推理档位，不得整块消失或出现"时有时无"的跳变。

#### Scenario: 模型支持推理档位

- **WHEN** 用户切换到一个配置了推理档位的模型
- **THEN** 推理档位控件呈现为可用选择器，默认档位置为 default

#### Scenario: 模型不支持推理档位

- **WHEN** 用户切换到一个未配置推理档位的模型
- **THEN** 推理档位控件呈现为禁用占位并带有"当前模型不支持"提示，控件栏布局位置保留

### Requirement: 显示与提交的模型状态一致

选择器呈现的当前代理、模型与推理档位 SHALL 与提交请求所使用的值来自同一份解析结果：不得在显示链路与提交链路各自维护一套解析逻辑，不得存在从未生效的可选覆盖入口。提交时所使用的值即用户在选择器中看到的值。

#### Scenario: 提交值等于显示值

- **WHEN** 用户在代理、模型、推理档位选择器中完成切换后立即提交
- **THEN** 提交请求携带的代理、模型、推理档位与选择器当前呈现值完全一致

#### Scenario: 加载中提交有明确反馈

- **WHEN** 区域未就绪（当前模型或代理尚未解析成功）时用户尝试提交
- **THEN** 应用给出明确的不可用反馈，不得使用解析过程中的中间态值发起提交

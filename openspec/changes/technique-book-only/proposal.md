# Proposal

## Why

写作技法当前按“全局通用库 + 本书库”双源路由和召回，跨书共享会把某本书提炼出的写法自动扩散到所有书，污染不同书籍的文风与写作上下文。用户已确认技法以后按书籍组织，且旧全局库无需保留，因此需要在切换前固化方案并彻底清理旧数据。

## What Changes

- **BREAKING**：运行时不再把全局通用技法库作为写作召回来源；所有技法召回只查询当前书籍的技法库。
- **BREAKING**：对话学习和手工创建的新技法一律写入当前书籍技法库；`scope` 不再决定存储位置，只保留“内容性质分级”语义，用于书级/章节级成人内容闸门。
- **BREAKING**：技法库界面不再合并展示全局技法条目，也不再展示“通用库/本书”来源路由语义；用户只能看到和维护当前书籍技法。
- **BREAKING**：全局通用库数据一次性彻底删除，包括本地全局 `techniques.db` 及其 SQLite sidecar 文件、其中的技法与反馈数据、远端 `@library` 同步单元及其登记；不做迁移，不做归档，不做恢复入口。
- 云同步不再登记或运行全局通用技法库 `@library` 同步单元，清理时同步移除远端 `@library` 数据，避免残留或旧登记继续参与同步。
- 成人内容双闸门继续生效：`scope=adult` 的技法仍只在“本书显式判为成人 + 当前章节判为成人”时进入候选，只是候选池改为当前书籍库。
- 旧全局技法不复用；如果某本书需要类似写法，用户以后在当前书籍中重新学习或手工创建。

## Capabilities

### New Capabilities

- 无

### Modified Capabilities

- `technique-shared-library`: 全局通用库从运行时写入/召回/反馈来源改为一次性彻底删除；移除双源合并和跨书反馈语义。
- `technique-library`: 入库与生命周期一律限定到当前书籍库，`scope` 语义从存储路由改为内容性质分级。
- `technique-ui`: 技法面板改为仅展示当前书籍库，移除全局/本书双库合并、来源徽标和跨库迁移编辑行为。
- `technique-library-sync`: 移除 `@library` 全局库同步单元，并删除本地与远端 `@library` 数据及登记。
- `technique-content-nature`: 成人内容闸门继续作用于当前书籍库，移除全局通用技法的免过滤例外语义。

## Impact

- `packages/plugin`：技法学习、保存工具与召回快照需要改为当前书籍库单源。
- `packages/server`：全局技法相关处理、保存路由与 `@library` 注入需要移除或收窄。
- `packages/novel-store`：需要执行旧全局库一次性删除，并确保只删除全局库，不误删任何书籍库。
- `packages/core`：同步单元列表、`@library` 特殊路径与远端单元清理逻辑需要调整。
- `packages/app`：技法列表、详情、创建/编辑表单和同步设置展示需要更新。
- `packages/schema` / `packages/protocol`：如删除或修改全局技法相关 API 契约，需在 `packages/client` 重新生成 SDK。
- 数据兼容：这是破坏性清理，全局技法、全局反馈、全局使用统计与远端 `@library` 备份都会消失；所有书籍库不受影响。

## Non-goals

- 不迁移、合并或复制任何旧全局技法到书籍库。
- 不为旧全局库提供备份、归档、恢复或导入入口。
- 不删除任何书籍库中的技法、反馈、状态或使用统计。
- 不改变成人书级内容性质的显式声明流程和章节级闸门逻辑。
- 不改变技法 `unverified → verified` 状态机本身。

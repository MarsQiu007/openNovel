# Design

## Context

- fork 桌面入口的现状失败链路（详见 proposal.md「Why」）：命令面板/斜杠触发 → `Session.fork` 创建无绑定、无父链的顶层会话 → 对话框导航旧式独立会话地址 → 重定向宿主按归属解析判无归属 → 提示并降级书架。
- 平台层消费方：CLI `--fork`（run / attach）、ACP `unstable_forkSession`、HTTP `POST /session/:sessionID/fork`、SDK 生成物，以及 opennovel 测试基建（`session.test.ts`、`messages-pagination.test.ts`、`httpapi-exercise`）。
- 桌面端既有替代能力：`session.undo`/`session.redo` 命令（回滚与提示词回填/恢复）、消息级回滚按钮、回滚消息坞（恢复）、书内切换器「+」新建（懒创建绑定会话）。
- 约束：不改 i18n locale 文件；不改 Protocol / Server HttpApi；改动面限 packages/app 两个文件。

## Goals / Non-Goals

**Goals:**
- 从桌面产品面彻底移除 fork 入口与对话框，不留悬空引用与双态维护。
- 给「fork 想解决的诉求」建立替代映射与回归防线，避免重演「下线会话面板 → 子代理不可见」类回归。

**Non-Goals:**
- 平台层 API 裁剪与 SDK 再生成（保留，另行评估）。
- 既有未接线残留的清理（session-ui 类型字段、ui 文案键与图标；见 proposal「非目标」）。
- 任何会话导航/归属解析链路的修改。

## Decisions

### D1 退役入口，而不是让 fork 继承归属
备选方案是「fork 时继承源会话的书籍归属并导航进工作台」。否决理由：fork 的独有价值是平行分支，但内容层没有分支——两条会话共享同一本书的章节/设定，无对比、合并、回收语义；修完仍要重构工作台管理面（同书双会话语义、活跃回退、归档级联），投入与收益不成比例。桌面端「回到某点重说」已由回滚/恢复覆盖（同会话内重走，不丢归属）。

### D2 删除，而不是隐藏
备选方案是仅在命令列表中过滤。否决理由：隐藏保留双态维护与再次误暴露的风险；本入口无任何依赖消费方，删除是干净解，且随删除自然关闭「对话框导航旧式地址」遗留事项（无需单独修复）。

### D3 分层边界：桌面层删除、平台层保留
- 保留：`Session.fork` 与 HTTP/CLI/ACP/SDK 消费方（不经桌面书籍归属路由，非本模型范畴）；本变更不触碰 opennovel / sdk 任何文件，无契约变更、无需 SDK 再生成。
- 删除：桌面两处运行时引用——命令条目与承载函数、对话框组件。
- 保留不清理：i18n 键（app 与 ui）按惯例不动；session-ui `UserActions.fork` 类型字段、ui `fork` 图标为既有零消费残留，另行评估。

### D4 回归防线与补救措施（对应「下线会话面板导致子代理不可见」的教训）
- 上次回归的机制：访问路径整体退役而无替代——会话宿主被移除后，子代理会话失去可达入口。
- 本次差异核验：fork 是**创建入口**而非访问路径；本变更不触碰任何会话打开/归属/导航代码，桌面端对既有会话（含子代理）的可达性零变化。
- 替代映射（fork 诉求 → 现路径）：
  - 回到某点重说 → 会话内回滚/恢复（消息级回滚按钮、回滚消息坞、`/undo`、`/redo`）；
  - 开一条带上下文的新对话 → 书内切换器「+」（懒创建绑定会话，天然继承书籍上下文）；
  - 保留原效果同时另起一条 → 桌面端无等价能力（接受；原入口产物不可打开，无实际损失）。
- 既有数据：无归属会话行为与今天一致（降级书架提示）；不迁移。
- 验证：app 包 typecheck + unit + browser；e2e 子集（`subagent-child-navigation`、`session-book-routing`、`session-switcher-subagent`）；手工验收清单与 grep 审计（见 tasks 1.3 / 2.x）。

## Risks / Trade-offs

- [用户仍在依赖 fork 工作流] → 桌面端该工作流自「自由会话下线」起已不可用（产物不可打开），实际损失为零；替代路径见 D4；平台层入口保留。
- [命令列表编辑引入回归] → 仅删除两个代码块，命令框架与其余命令不动；typecheck + 命令面板/斜杠手工验收兜底。
- [残留键与类型字段引发疑问] → proposal「非目标」显式登记上下文与理由，留给后续清理决策。

## Migration Plan

无数据迁移。应用更新后入口即刻消失；回滚 = 恢复两处代码块（无状态残留）。

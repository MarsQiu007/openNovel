# Proposal

## Why

项目已在 `workflow-self-evaluation`（2026-11-06 归档）中落地本地指标桶、三分部复盘报告、自动触发和分级诊断导出，解决了「整体运行得怎么样、哪些信号最异常」。但工具事件入桶后主要只剩计数，无法回答「这个具体问题是什么、如何复现、应该怎样修、修好后如何证明」。

方向二需要一项独立能力来承载完整的问题改进闭环，同时复用现有会话事件、脱敏纪律、本地文件与 `/evaluate` 入口，而不是重复建设采集和存储底座。`workflow-self-evaluation` 继续负责聚合指标与定期复盘；新增的 `tool-insight-log` 负责单问题证据、AI 归因、复现验收与修复后验证。

## What Changes

- **新增本地工具改进日志**：设置仅提供「是否启用」和「日志目录」两项，保存为独立全局 `toolInsight` 设置，不写入插件加载列表，也不改变任何项目的插件加载范围。开关默认关闭；仅修改这两项设置时无需重开项目即可生效。关闭时不采集新增证据、不发起归因模型请求，并取消本能力仍在执行的后台任务。目录默认使用项目 `.novel/evaluate/tool-insight/`，配置共享目录时按项目隔离。既有指标、报告和诊断包不受开关影响。
- **客观证据先于 AI 分析**：命中工具失败、异常工具轨迹、反复修改窗口或用户主动记录时，程序先向 `evidence.jsonl` 追加白名单事实，再让 AI 整理。证据包括工具名、callID、错误类别与脱敏摘要、会话/章节标识、agent/模型/应用版本、实际结果与稳定证据标识；不得直接转储完整工具参数、输出、小说正文或密钥。无法确认的事实写「未知」，禁止 AI 补编。
- **按事件时机处理**：写作会话中的工具异常或用户反馈发生时立即保存证据，AI 整理在当前模型轮次结束后的安全边界后台执行，不向原写作会话插入提示词、不阻塞或打断写作。归因后台只接收已脱敏证据并返回结构化文本，不调用原项目工具。内部会话的全部事件不得进入旧指标或触发旧报告。重启时一次性补齐已保存但未整理的证据，不按 token 成本采样，也不以周期扫描替代事件触发。既有自评价报告的 24 小时冷却保持不变。
- **覆盖完整工具轨迹而非仅报错**：在异常、反复修改或用户反馈触发时，检查该调用工具而未调用、工具选择错误、参数错误、无意义重复调用/重试、恢复失败，以及工具表面成功但任务未完成。正常调用不逐条生成 AI 意见。
- **明确失败分类**：每条已确认问题归入工具实现缺陷、工具能力缺失、工具描述或参数 Schema 问题、agent 选择/参数误用、工具结果误解、产品交互或流程问题；证据不足时主分类保持「未确认」，可保留多种假设，不强行归因。
- **过程与真实结果并验**：同时记录执行轨迹和可核实的最终状态，例如章节是否落库、审批是否生效、设定是否更新；不得仅凭 agent 自称完成判定成功，无法核验时标记「未验证」。
- **按稳定问题指纹归并**：程序依据工具、错误类别和操作场景等生成指纹。重复事件更新同一 `issues/<fingerprint>.md` 的出现次数、最近发生时间、影响版本和证据，并自动维护 `index.md`。跨进程追加与整理通过真实文件锁串行化，并按稳定证据标识去重，不制造重复问题、不丢失次数。
- **形成可行动的 Markdown 记录**：每条包含用户目标、实际行为、期望行为、复现条件与步骤、影响程度（阻断工作/错误结果/效率损失/体验问题）、客观证据、AI 原因假设、改进建议和验收标准。事实与推测必须分节，验收标准应能转化为后续测试或 OpenSpec 需求。复现案例优先使用匿名或合成数据；默认不保存小说正文，只有用户明确指定的必要正文片段才可例外保留，并显著标记分享风险。正文本地保留与发送给模型分别授权，未另行授权时该片段不得进入归因或复测模型请求。
- **保留用户主动入口**：扩展 `/evaluate`，允许用户用自然语言要求「记录这个工具问题」、重新整理某条日志或补充反馈；自动检测不得替代用户主动报告。旧报告和诊断导出的确定性、只读写作数据行为保持不变。
- **修复后隔离复测与回归留痕**：用户明确要求并在系统展示问题、次数、版本和案例摘要后确认时，才在隔离临时项目中自动复测。只有具备程序注册的确定性隔离适配器（合成夹具、固定工具白名单、真实结果核验器）的工具与操作才可自动执行，AI 文本不得扩大白名单；没有适配器的一律转人工。每次确认由宿主签发与插件、准备时案例内容、次数和模型绑定的执行授权，次数限 1–20 次；确认后案例发生变化必须重新确认。复测会话使用独立临时 Location，复测 agent 默认不得读取或修改原书，只有用户明确指定且授权本次模型使用的片段例外。插件、专用 agent 和目标工具未就绪或实际工具集合超出白名单时不得发车。多次运行逐次追加修复版本、真实核验和通过/失败结果；具有外部副作用、无法安全复制或无法隔离的案例只能人工验证。除已配置模型的必要请求外，复测工具不得访问真实外部服务。
- **仅使用配置的模型进行归因**：发送给模型的证据同样经过脱敏；除该模型调用外，不新增遥测、上报或外发通道。本地日志可自动生成，分享、采纳建议和修改产品仍由人决定。

**非目标**：

- 不替代或改写 `workflow-self-evaluation` 的指标桶、确定性三分部报告、自动报告策略和诊断包；不重复规定其产品信号报表。
- 不新增 SQLite 表、FTS 索引、洞察 CRUD API、工作台汇总页面或 new/triaged/exported 状态生命周期。
- 不开 GitHub issue、不接 gh、不自动上报；用户自行选择并分享本地文件。
- 不对所有正常工具调用生成 AI 评论，不采集完整正文、原始敏感参数或密钥。
- 不让 agent 自动修改工具、提示词、Schema 或产品代码，不自动注册新工具，不把 AI 推测当作已确认根因。
- 不自动执行有真实外部副作用或无法隔离的复测，不在本变更中另建完整 CI 评测平台或支持网络共享盘。

## Capabilities

### New Capabilities

- `tool-insight-log`: 面向具体工具与 agent 问题的本地改进日志能力；覆盖按需客观证据、异常轨迹分析、失败分类、真实结果核验、问题指纹归并、AI 原因假设、复现与验收标准、用户主动记录及修复后复测。它以可行动、可验证的单问题记录为边界，不承担聚合运营指标和定期创作复盘。

### Modified Capabilities

（无——复用 `workflow-self-evaluation` 的既有事件、指标与入口，不改变其 spec 级行为；新能力的独立要求由 `tool-insight-log` 承担。）

## Impact

- `packages/plugin`：新增工具改进日志模块、独立全局设置的窄解析器和本地文件格式；复用 `novel-writer/evaluate` 的事件与 `/evaluate` 入口，所有新旧事件处理统一排除内部会话。归因后台不开放工具；复测通过系统问题确认、确定性案例适配器、案例级权限与隔离临时项目执行。新增插件侧文件锁与用户确认契约，显式声明 JSONC 解析依赖。
- `packages/core`：为插件宿主提供受约束的后台会话桥接，直接使用真实 `SessionV2.Service`、`SessionExecution.Service`，仅在目标 Location 就绪与权限预检时使用 `LocationServiceMap.Service`；新增进程级后台 purpose 标记、真实执行取消、跨进程文件锁适配和 `QuestionV2` 用户确认适配。为既有全局配置契约增加 additive 的 `toolInsight` 字段，不修改公开 SessionEvent Schema。
- `packages/opennovel` / `packages/protocol`：复用既有 `global.config.get/update`，不新增端点；仅当实际变化字段集合恰好为 `toolInsight` 时跳过全局项目 dispose，其他字段单独变化或混合变化保持原行为，并保证返回界面的是本地有效设置。配置 Schema 变化须从仓库根运行 `bun ./script/generate.ts` 同步客户端与 SDK；既有 global config httpapi-exercise 场景增加新字段往返、选择性 dispose 和有效值覆盖验证。
- `packages/app`：经典与 V2 设置页复用同一组件，只新增开关与目录选择，使用全局配置更新和既有目录选择器；复用现有问题确认界面，不新增工作台管理页面。新增用户可见文案使用简体中文，遵守仓库约束不修改既有 i18n locale 文件。
- `packages/desktop`：复用既有原生目录选择与问题确认桥接，不新增 IPC 或洞察管理界面。
- `packages/novel-store`：数据库 Schema 与既有指标写入不变；新增工具改进日志的路径解析、JSONL 追加写及不完整尾行恢复辅助，继续由该包承担 `.novel` 数据域写盘，不新增表或迁移。跨进程锁由 Core 宿主适配提供，不让 novel-store 反向依赖 Core。
- `packages/schema`：现有工具事件已包含所需原始字段，公开 SessionEvent 与会话 SDK 契约无需改动；变化的是 Core 既有全局配置 Schema 及其 OpenAPI 生成物。
- 数据兼容性：只新增 `evidence.jsonl`、`issues/*.md`、`index.md`、复测记录、损坏尾部恢复文件和运行期锁目录，既有 `metrics.jsonl`、报告和诊断包保持原路径与原格式；旧版本可继续读取既有文件，无需数据库迁移。

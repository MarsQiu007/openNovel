# Spec Delta

## Purpose

配置健康守卫：在升级/跨机场景下，全局配置（插件条目、agent 覆盖项、旧式定义残留）与新版本脱节时，让漂移可见、可定位、可经确认修复，而不是静默生效或静默失败。

## MODIFIED Requirements

### Requirement: 体检结果经 API 暴露

体检结果 MUST 经 HTTP API 暴露给客户端，内容包含问题清单，每条含严重级别、人类可读说明、来源文件路径、键路径与修复建议。无问题时 MUST 返回空清单。结果 MUST 随配置变更刷新。体检评估的 `info` 数据源 MUST 为配置文件的当前内容（直读装载），MUST NOT 依赖可能陈旧的进程内缓存；对一键修复，修复 draft 与评估 MUST 同源，且修复完成后的复查 MUST 重新直读文件。

#### Scenario: 客户端查询健康状态

- **WHEN** 客户端请求配置健康状态且存在两处漂移（一个失效插件条目、一个失效模型覆盖）
- **THEN** 响应包含两条问题记录，各带来源文件路径、键路径与修复建议，且不包含内部异常栈

#### Scenario: 健康无漂移

- **WHEN** 全局配置与当前版本完全兼容
- **THEN** 响应为空清单，且响应不触发任何写操作

#### Scenario: 外部直改文件立即可见

- **WHEN** 进程内缓存已填充后，配置文件被服务之外的路径改写（用户手改、跨机覆盖、直写种子），且写入内容引入新的漂移（如新增指向未知提供商的 agent 模型覆盖）
- **THEN** 下一次体检请求反映改写后的文件内容，新漂移被报告，缓存中既有的陈旧内容不影响结果

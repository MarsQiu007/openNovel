# Proposal

## Why

现行章节字数门禁只有一个目标值（缺省 2500）加一个「篇幅限制」开关：开关关时只卡下限，开关开时按目标 ±15% 双向卡。这套设计表达不了「我要 2000–5000 的宽区间」这类常见诉求（百分比容差把区间宽窄锁死在 30%），开关语义也让用户和写作代理都把它误当成系统级硬标准，遇到章节偏短时代理只会劝用户「忍着」而不是引导调整书籍设定。上下限应像基调、视角等其他写作风格参数一样，按书由用户自由设定。

## What Changes

- 「目标字数」规则键（`chapter_length`）语义明确为**字数下限**，缺省 2500 不变（与今天默认模式「至少 N 字」行为完全一致）。
- 新增**字数上限**规则键（`chapter_length_max`），按书设定；留空 = 不设上限（保留长章自由：剧情需要时写到 5000、8000 均可）。
- **删除「篇幅限制」开关与 ±15% 容差**：上限存在即双向区间门禁，上限留空即仅下限门禁；百分比容差概念整体移除。
- 存量数据一次性幂等迁移：开关曾为 "true" 的书按 85%/115% 折算成具体上下限数字后删除开关键；其余书补空上限。迁移只增改 `style_guide.rules` 键值对，无表结构变更。
- 写作风格编辑器提供**常驻**「字数下限 / 字数上限」字段：打开面板即自动回填当前值（缺省 2500 / 空），保存写回规则库，用户无需手动新建规则行；「篇幅限制」复选框随之移除。
- 快照「目标字数」行、writer 提示词字数规则、pipeline dispatch 指示、章节编辑器目标进度全部按「区间 / 仅下限」两态渲染。

## 非目标

- 不改动字数统计口径：`countWords` 网文字数口径（汉字 + 英文/数字词，不含标点）继续作为唯一事实源。
- 不改动顺序门禁、审批流、审计维度等其余章节闸门。
- 不改动上下文 token 预算分层（budget.ts 中的 2500 是 P6 token 预算，与章节字数无关）。
- 不改动导入管线的长度策略（如确认导入不经过写入闸门，则维持现状）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `chapter-length-limit`: 双模式（仅下限 / ±15% 区间）门禁改为显式上下限区间门禁；「篇幅限制」开关需求移除并由上限字段取代；编辑 UI 从复选框改为常驻上下限字段；快照与提示词按两态渲染；新增上下限规则键的存储与传递需求。
- `style-editor-ui`: 「篇幅限制承载不变」需求移除——保留键机制随复选框消失，规则行占用字数上下限键改由新增校验需求承接。
- `setting-center-tree`: 「书籍信息节点单一数据源」需求中「写作风格字段」枚举的「篇幅限制」表述更新为「字数下限/字数上限」。

## Impact

- **plugin**：章节写入守卫（下限常驻、上限存在时双向拒绝）、写作快照「目标字数」行渲染、writer 系统提示词规则 16 与字数要求段、pipeline dispatch 指示；删除死代码模块 chapter-normalize（内部硬编码 ±15%、零调用方）。
- **app**：风格指南编辑器（常驻上下限字段替代复选框）、章节编辑器目标进度（区间判定）、i18n 三个 locale 的篇幅限制/目标字数词条增删改。
- **novel-store / schema**：`style_guide.rules` 键解析与缺省逻辑；存量规则幂等迁移。
- **server**：无功能性改动——style_guide rules 为开放字符串映射透传，端点无键白名单校验，键集合变化不构成契约变化；`word_count` 各写入路径均为 countWords 纯度量，口径不变。
- **docs / repowiki**：docs/ 目录经核查零命中无需更新；repowiki 写作流水线文档中「篇幅限制」「130%/1.3 倍/±30%/±15%」相关描述需同步重写，「章节管理 API」「章节实体」两节随死代码 normalizeChapter 删除整体移除。
- **数据兼容性**：`style_guide.rules` 为按书键值存储，迁移为幂等键级改写，不改表结构；旧版本读取时未知键按既有规则忽略，已开启 ±15% 的书迁移后区间数值固化、不再随代码变化。

# Spec Delta

## RENAMED Requirements

- FROM: ### Requirement: 退出时自动安装已下载的更新
  TO: ### Requirement: 退出时确认后安装已下载的更新

## MODIFIED Requirements

### Requirement: 退出时确认后安装已下载的更新

当 updater 状态为 `ready`（已下载完成）时，用户正常退出 app（关闭窗口或菜单退出），SHALL 先弹出确认对话框（含新版本号），提供「立即重启」与「稍后」两个选项；只有用户确认后立即退出并应用更新，下次启动时运行新版本。用户选择「稍后」时正常退出，不执行安装，已下载的更新包与就绪状态保留（titlebar 圆点保留），留待下次启动处理。updater 状态不是 `ready` 或更新功能被禁用时，退出不弹确认框。

#### Scenario: 已下载更新，用户退出

- **WHEN** updater 状态为 `ready` 且用户正常退出 app
- **THEN** 弹出确认对话框，包含新版本号与「立即重启」「稍后」两个选项
- **AND** 不直接执行安装

#### Scenario: 用户选择立即重启

- **WHEN** 用户在退出确认对话框中选择「立即重启」
- **THEN** app 退出并应用已下载的更新
- **AND** 下次启动时运行新版本
- **AND** titlebar 圆点与就绪持久化记录被清除

#### Scenario: 用户选择稍后

- **WHEN** 用户在退出确认对话框中选择「稍后」
- **THEN** app 正常退出，不执行安装
- **AND** 已下载的更新包与就绪持久化记录保留
- **AND** titlebar 圆点保留，下次启动仍可见

#### Scenario: 未下载更新，用户退出

- **WHEN** updater 状态不是 `ready`（比如 `up-to-date` / `idle` / `checking`），或更新功能被禁用
- **THEN** 正常退出，不弹确认框，不执行安装

## ADDED Requirements

### Requirement: 启动时待安装更新的处理

用户上次选择「稍后」退出、或上次安装未能完成时，下次启动 app SHALL 优先在启动流程中直接应用待安装的更新（当前安装形态无需提权）：应用期间向用户显示可见的安装进度反馈，完成后自动运行新版本，无需用户再次操作。当待安装更新无法应用（缓存安装包校验失败、远端版本已撤销或当前版本已高于目标版本）时，SHALL 清理无效的待安装状态并恢复常规检查流程，同时以可见方式告知用户「更新未完成」并提供重新更新的入口。待安装版本与当前版本一致（说明安装已成功完成）时，清除待安装记录并正常启动。

#### Scenario: 稍后退出后下次启动

- **WHEN** 用户上次以「稍后」退出且更新包仍然有效
- **THEN** 本次启动在展示主界面前应用待安装的更新
- **AND** 应用期间显示可见的安装进度反馈
- **AND** 安装完成后自动运行新版本，并清除待安装记录

#### Scenario: 上次安装被系统中断

- **WHEN** 上次安装过程被关机或注销中断，且缓存安装包校验仍然有效
- **THEN** 本次启动重新尝试应用待安装的更新
- **AND** 不向用户呈现「应用损坏或无响应」的无反馈状态

#### Scenario: 待安装更新无法应用

- **WHEN** 下次启动时缓存安装包校验失败，或远端已撤销该版本，或当前版本已高于目标版本
- **THEN** 清理无效的待安装状态（含缓存与持久化记录）
- **AND** 恢复常规检查流程
- **AND** 以可见方式告知用户「更新未完成」并提供重新更新的入口

#### Scenario: 待安装版本与当前版本一致

- **WHEN** 下次启动时待安装记录中的版本与当前运行版本一致
- **THEN** 清除待安装记录并正常启动
- **AND** 不显示任何待安装相关的提示

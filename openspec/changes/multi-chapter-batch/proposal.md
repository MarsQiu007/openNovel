# 多章节批量连续生成（multi-chapter-batch）

> 状态：草稿 — 优先级 P2（2026-09-07 探索会话产出，方案待研究；长期保留在规划池）

## Why

当前每章必须用户逐次触发"写下一章"，无"连写 N 章"能力（全库搜索 连续写/batch_write/auto_next 零命中）。单章闭环已完整（8 步流水线 + 审批 + 状态机），规模化产能是下一个量级的瓶颈——长篇网文动辄数百章，逐章人工触发不可持续。

## What Changes

- 支持批量连续生成 N 章（入口与实现方式待研究：director 对话指令扩展 / 专用工具 / 会话编排循环）。
- 批量模式下的中间态处理：auto 模式连写、review 模式是否逐章停等、失败中断与续写。
- 上下文一致性：连写时逐章刷新快照（现有 assemble_context_snapshot 已按章组装，天然支持）。

## Capabilities

### New Capabilities

- `multi-chapter-batch`: 批量连续生成的行为要求——触发、逐章衔接、失败中断与恢复。

### Modified Capabilities

（无——待研究后确认是否修改流水线相关行为。）

## Impact

- `packages/plugin`：pipeline 编排、流水线循环控制。
- `packages/app`：批量入口（如"连写 5 章"操作）。
- 预计无数据模型变更（复用章表与版本表）。

**非目标**：本变更不做定时/无人值守自动生成；不做批量生成的并行化（章节严格串行）；P2 阶段仅保留方向，实施前需重新验证最新代码状态。

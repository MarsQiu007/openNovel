## Context

地图草稿生命周期与 CRUD API 已就绪；编辑器（world-map-editing）提供生成后的人工修正。项目的 LLM/会话基础设施在 packages/llm 与会话系统中，插件工具模式已有先例（novel-writer）。

## Goals / Non-Goals

**Goals:**

- 世界观条目 + 指令 → 结构化地图草稿。
- schema 校验、事务替换草稿、进度与失败恢复。

**Non-Goals:**

- 图片生成、自动提升、生成历史。

## Decisions

### 生成走结构化 JSON 输出而非自由文本后处理

提示词要求 LLM 输出符合地图 schema 的 JSON（区域顶点数组、地点坐标、名称、描述、颜色），用 Effect Schema 解码校验。解码失败整体重试，不静默裁剪。评审结论（Q5）确认输入形态：默认从世界观条目提取，允许自然语言指令修正。

### 提示词提供画布几何约定

0..10000 网格、y 轴向下为南、要素不重叠的软约束、区域顶点顺/逆时针不要求。给 LLM 明确的坐标语义，减少越界与退化多边形。

### 替换草稿用事务性"先删后建"

复用数据层约束：草稿删除级联清空要素与图钉（既有行为），再写入新要素。图钉不参与生成（角色位置是叙事决策，交由编辑器手动安放）。

### 地图页直通入口，复用插件 agent 模式

生成入口放在地图页内（选条目 → 指令 → 进度 → 完成），与章节标注等既有 LLM 功能的"前端触发 → 插件 agent 执行 → 记录入库"模式一致。对话式生成留作将来扩展。

### v1 不提供生成取消

客户端取消无法可靠阻止服务端继续写入，abort 信号传播的复杂度不值得。生成中锁定入口直到完成或失败；spec 的"失败不写入"保证只覆盖失败路径。

### 校验失败自动重试一次

首次解码失败后，把具体校验错误注入提示词自动重试一次，显著提高结构化输出成功率；仍失败则转手动重试并展示原因。

### 生成触发为用户显式动作

不做后台自动生成或会话中隐式触发。地图页提供入口，生成期间展示进度，失败可重试。避免 LLM 成本不可控与意外覆盖草稿。

## Risks / Trade-offs

- [LLM 坐标质量不稳定] → schema 校验拦截非法输出，错误反馈自动重试一次；布局美观度靠用户在编辑器微调，第一版不追求自动美化。
- [大量条目超出上下文] → 条目选择范围让用户控制输入规模；提示词压缩条目描述（截断长文）。
- [用户误触生成覆盖精心编辑的草稿] → 已有草稿时生成前弹确认（列出将被覆盖的要素数）。

## Migration Plan

纯新增流程与界面，无数据迁移。

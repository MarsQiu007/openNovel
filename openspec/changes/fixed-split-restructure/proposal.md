# Proposal

## Why

书籍导入未识别章节边界时按固定长度机械分章（约 3000 字/章，标题为「第N部分」），切点常落在句子或场景中间。后续 AI 整理的分章校验被规范限定为只汇报不重切，导致不合理边界永远不会被修复；用户只能得到一份问题清单，书稿结构依然不可用。Issue #33。

## What Changes

- 新增章节结构重切能力：AI 编排会话可对一本书提出结构化重切方案（按锚点拆分、相邻合并、改题），方案先经确定性校验与预览，用户确认后在单事务内应用；内容变更前自动保存章节版本，应用后全书序号重排为 1..N。
- 导入整理管线增加建队前分诊：创建整理队列时识别固定长度分章特征（标题模式 + 长度均匀），命中时先做分章体检并产出重切方案，用户确认应用后再基于新结构建队；用户拒绝或无需调整时按原结构建队，既有队列内分章校验单元保持只汇报语义不变。
- list_chapters 工具输出增加固定分章特征标记，供编排会话确定性识别，不依赖模型自行猜测。

## Capabilities

### New Capabilities

- `chapter-restructure`: 章节结构重切的方案校验、确认式事务应用、版本快照与结构不变量维护。

### Modified Capabilities

- `book-import-pipeline`: 导入整理在建队前对固定长度分章书籍增加体检与确认式重切分诊；队列内分章校验单元的只汇报语义不变。

## Impact

- `packages/novel-store`: 新增章节重切数据层模块（方案模拟校验、事务应用、版本快照、序号重排），复用既有删除/重排/级联帮手。
- `packages/plugin`: 新增 `restructure_chapters` 工具并注册；`list_chapters` 输出增加固定分章特征标记；director 导入整理流程增加建队前分诊段落。
- `packages/app`: 导入报告页「AI 整理」建队指令文案同步提及固定分章体检步骤。
- 不变更 HTTP API、Protocol、Schema 契约与数据库表结构；不需要重新生成 SDK。
- 兼容性：不重切的书行为完全不变；重切只通过确认门禁触发，内容可经既有版本恢复能力回滚，被合并章节的删除在预览中显式警示。

## Non-goals

- 不做静默自动重切：任何结构变更必须经用户确认。
- 不改动导入时的固定长度分章算法本身（仍按 3000 字兜底）。
- 不处理错字/无用信息的正文修订闭环（属 chapter-cleanup-review，Issue #34）。
- 不改动队列内分章校验单元的只汇报语义。
- 不保证被合并章节的结构级撤销（内容可回滚，合并删除在预览中显式列出）。

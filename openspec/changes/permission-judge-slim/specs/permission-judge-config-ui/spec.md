# permission-judge-config-ui Delta

## MODIFIED Requirements

### Requirement: 全局默认裁判模型选择器

系统 SHALL 在智能体设置面板提供一个内置的"权限裁判"行，为其暴露唯一的裁判模型选择器（跟随会话模型缺省 / 已配置供应商的任意模型）；指定后 SHALL 写入全局配置的裁判模型字段，未指定时裁判 SHALL 跟随会话当前模型。设置界面权限区 SHALL NOT 放置独立的裁判模型选择器。

#### Scenario: 指定裁判模型后生效

- **WHEN** 用户在"权限裁判"行选定某供应商的某模型
- **THEN** 后续裁判调用使用该模型，会话模型调用不受影响

#### Scenario: 跟随会话模型为缺省

- **WHEN** 用户未在"权限裁判"行指定模型（跟随会话）
- **THEN** 裁判调用使用与会话相同的模型与供应商凭据

#### Scenario: 设置页权限区不含裁判模型选择器

- **WHEN** 用户打开设置界面的权限配置区
- **THEN** 该区域只提供权限模式三档选择与项目级来源标注，不出现裁判模型选择器

## REMOVED Requirements

### Requirement: agent 级裁判模型覆盖

**Reason**: agent 级裁判模型覆盖把裁判的模型配置复制到每个智能体一行，配置面过度繁殖（全局 + 每 agent 双入口），真实使用收益（给不同智能体配不同裁判模型）不足以支付界面与解析链路的复杂度；裁判作为独立实体只保留一个模型入口。

**Migration**: 升级前在 agent 配置段书写过裁判模型的用户，该书写被忽略，裁判模型回落全局配置；未配置全局裁判模型时按跟随会话当前模型处理。用户如需指定裁判模型，在智能体面板的"权限裁判"行配置一次即可对所有会话生效。

### Requirement: 策略表只读展示

**Reason**: 裁判策略表退为内置常量（见 permission-llm-judge 的需求修订），配置面不再存在策略覆盖，界面上再展示一张用户无法影响、也无法编辑的表格只是噪音。

**Migration**: 设置界面不再展示策略表；各动作的分流行为以内置默认表为准（只读族确定性放行、subagent 人审、执行/写/网络/编排族进裁判）。曾在配置文件中书写策略覆盖的用户，其书写被忽略。

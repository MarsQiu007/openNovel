# Proposal

## Why

信息差是小说写作的核心叙事手段，但当前写作管线没有任何"谁知道什么"的边界概念，用户在两个环节稳定踩坑：

1. **生成期知识错位**：用户设定"主角坠崖未死、不想让家人担心、回家不提"，生成结果却是"家人为了表现不担心，不去问坠崖的事"——家人被写成知情者，信息差情节直接写崩。writer 的 32 条规则只有视角与悬念分类，快照与章纲里没有任何角色知识边界标注，"隐瞒"类设定全靠模型脑补。
2. **纠正指令泄漏进正文**：用户纠正"家人不知道主角坠崖，只知道他很晚回来，很担心"，修订结果却把这局知识边界声明原样改写塞进正文（"他不知道主角坠崖，也不会去问主角坠崖的事情"）。既有"写作反馈意图协议"存在结构性漏洞：知识边界句容易被判为 `narrative_fact`（允许正文否定），且缺少"知识边界"意图类型，writer 唯一的满足手段就是复述否定句。

## What Changes

- 写作反馈意图协议新增 `knowledge_boundary`（知识边界）意图类型：确立谁知道/不知道什么的反馈编译为独立类型，执行只允许"删除矛盾旧断言 + 用知情范围内的可观察言行呈现期望状态"，禁止在正文直述"X 不知道 Y"类元否定。
- 收紧 `narrative_fact` 判定：含"知道/知晓/意识/不知情/了解"类动词、宾语为剧情事实的句子，不得再判为剧情事实，默认进入 `knowledge_boundary` 或 `unclear`。
- 章纲生成（outliner）新增场景信息边界标注：信息差场景为每个场景输出各出场角色的知情范围，写入章纲 markdown 的可选字段「信息边界」。
- 场景硬约束清单确定性编译新增「信息边界」字段解析（映射为「知情范围」），随快照与 `read_outline` 兜底路径进入 writer 输入。
- writer 新增硬规则：清单含「知情范围」时，出场角色只表现出其知情范围内的言行，禁止直述"不知道"类元否定（POV 角色内心独白除外）。
- auditor 反馈聚焦审计新增两项知识边界检查：直述元否定（"X 不知道 Y"类句子）与知情范围外言行（对不知情事件表现知情特征）。

非目标：不新增"角色知识状态"持久化数据结构（全书级"谁知道什么"表留待后续按效果决定）；不改 observer 事实提取 schema；不动审批流与 UI。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `writing-feedback-intent`：新增知识边界意图类型与执行规则，收紧剧情事实判定，审计新增对应检查项。
- `outline-scene-adherence`：场景硬约束清单扩展"信息边界"字段的编译与传递，writer 硬规则扩展知情范围约束。

## Impact

- **packages/plugin**：`agents/feedback-intent.ts`（协议三段落：派发/执行/审计）、`agents/outliner.ts`（输出格式与职责）、`scene-constraints.ts`（字段解析）、`agents/writer.ts`（规则 32 扩展与自检清单）、`agents/pipeline.ts`（dispatch 指示措辞）、`outline.ts`（章纲模板新增可选字段）。`agents/auditor.ts` 与 `agents/reviser.ts` 均内嵌引用 feedback-intent.ts 的协议段，本次无需改动本体。
- **兼容性**：章纲"信息边界"为可选字段，旧章纲无该字段时编译与写作路径保持现状；反馈意图协议的类型扩展向后兼容（旧五类意图语义不变）；仅 prompt 与确定性解析变更，不涉及数据模型与本地数据迁移。

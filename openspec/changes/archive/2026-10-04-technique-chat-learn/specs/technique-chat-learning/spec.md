# Spec Delta

## Purpose

让用户通过一句对话(如"来学习这本书籍的写作技巧")驱动写作 agent 从当前书籍中提取写作技法并进入技法库,覆盖整本与逐章两种粒度,学习过程有进度反馈,遇到同类技法自动或显式合并,无需用户记忆 CLI 命令。

## ADDED Requirements

### Requirement: 一句话触发学习意图

用户在写作会话中用自然语言要求学习本书或某章的写作技巧时,agent SHALL 识别该意图并启动技法学习流程;非学习类指令 MUST NOT 触发该流程。

#### Scenario: 整本学习触发

- **WHEN** 用户发送"来学习这本书籍的写作技巧"
- **THEN** agent 确认学习范围为整本后启动学习流程,逐章读取正文并提炼技法

#### Scenario: 非学习指令不误触发

- **WHEN** 用户发送普通写作或修改指令
- **THEN** agent 不启动技法学习流程,不读写技法库

### Requirement: 支持整本与逐章两种学习范围

学习流程 SHALL 支持整本范围(全部已写章节)与逐章范围(用户指定单个章节号);整本学习时 agent MUST 分批处理章节,不得一次性吞下超出上下文容量的正文。

#### Scenario: 逐章学习

- **WHEN** 用户指定"学习第 N 章的写作技巧"
- **THEN** agent 只读取第 N 章正文并提炼技法

#### Scenario: 整本学习分批处理

- **WHEN** 用户要求学习整本且已写章节较多
- **THEN** agent 按章节分批读取、提炼、落库,分批之间保留已学技法清单用于合并判断

### Requirement: 学习进度与结果可见

每完成一章的学习,agent MUST 简要报告该章结果(新学数量、合并数量、被拒绝数量及原因);全部完成后 MUST 输出汇总报告,包含新学技法名称列表、合并去向与拒绝原因。

#### Scenario: 逐章进度报告

- **WHEN** 某一章学习完成
- **THEN** 用户看到该章新学/合并/拒绝的计数与拒绝原因

#### Scenario: 完成汇总报告

- **WHEN** 整本学习全部完成
- **THEN** 用户看到全部新学技法名称、合并到已有技法的对应关系与被拒绝候选原因

### Requirement: 同类技法合并

同名(规范化名称相同)技法入库时 SHALL 自动合并证据条目并去重;名称不同但 principle 与 instruction 高度近似的技法,agent SHALL 先查询现有技法对比后再显式指定合并目标;任何合并且 MUST NOT 降级已有条目的 status 与 confidence。

#### Scenario: 同名自动合并证据

- **WHEN** 新学技法与库中已有技法规范化名称相同
- **THEN** 新证据追加到已有条目,不产生重复技法

#### Scenario: 显式合并近似技法

- **WHEN** 新学技法与某已有技法名称不同但内容近似
- **THEN** agent 查询并对比后显式指定合并目标,证据合并到目标条目

#### Scenario: 已验证技法不被降级

- **WHEN** 合并目标是 status=verified 的技法
- **THEN** 合并后该技法仍保持 verified 状态与原置信度,仅证据增加

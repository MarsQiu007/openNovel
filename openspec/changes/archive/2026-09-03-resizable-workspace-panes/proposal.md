# 提案：工作台分栏宽度可拖拽调节

## Why

`unify-novel-workspace-layout` 归档时左栏 288px / 右栏 380px 为固定值（当时拍板不做拖拽）。终版走查推翻该决定：宽屏用户希望给右栏对话更多空间，窄屏用户希望给主区更多空间，固定宽度无法分配。宽度可调后，自动收边阈值（现按固定 1100/1008 写死）必须改为从设定宽度派生，语义需一并定义。

## What Changes

- 左右栏增加拖拽手柄（复用 `packages/ui` 现成 `ResizeHandle`），宽度在边界内可调；双击手柄重置默认宽度
- 拖到最小宽度后再向外拖 = 收起该栏（与 »/« 按钮等价的手动收起通道）
- 设定宽度持久化（拖拽期间仅内存态，松手提交）；重启恢复
- 自动收边阈值改为从设定宽度派生：左档 = 左栏宽 + 主区保底；右档 = max(右栏宽 + 主区保底, 左档 + 1)——随行区永远先让位
- 保底语义收敛为终态保证：收边完成后主区不低于保底宽度（修正归档 spec 中"1100 = 右栏 + 720"未计左栏的措辞漏洞）
- 手动展开与拖拽所见即所得：侧栏按设定宽度显示，主区让路；主区保底仅承诺自动收边完成后的终态

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `novel-workspace-layout`: 新增"分栏宽度拖拽调节"要求；"布局状态持久化"中"分栏宽度为固定值"改为设定宽度持久化；"窄宽度自动收边"改为阈值派生公式 + 终态保底措辞 + 手动展开按设定宽度显示

## Impact

- **packages/app**：`workspace-frame.tsx` 宽度状态、阈值判定、ResizeHandle 接线（主要改动面）
- **packages/ui**：无改动（`ResizeHandle` 现成复用）
- **数据兼容**：布局持久化 key `novel.workspace.layout.v1` 追加两个可空宽度字段，不升版本号——旧数据按默认宽度处理，零迁移
- 不涉及 novel-store / plugin / opennovel / desktop，无 Protocol / HttpApi 变更

## Non-Goals

- 不做主区宽度拖拽（主区为弹性分配，无固定宽度可言）
- 不做分栏宽度的逐视图记忆（阅读/写作等主区视图共享同一组栏宽）
- 不做栏宽的命令面板指令与快捷键（手柄拖拽 + 双击重置已覆盖需求）
- 不动 titlebar 书籍级 tab（独立提案）

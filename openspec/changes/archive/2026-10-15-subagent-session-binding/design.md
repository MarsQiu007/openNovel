# Design

## Context

- 会话入口已收敛（session-book-only、retire-sessions-page）：独立会话路由是重定向宿主，会话统一在书籍工作台打开；子代理会话的进入路径为消息时间线子会话卡片、书内切换器与外部深链（动机见 proposal.md - Why）。
- 归属数据现状（已在真实数据核实）：`session_novel` 绑定行由两处写入——书内「+」等显式绑定，以及插件侧懒绑定（`resolveNovelForSession` 仅在目录恰好一本书时标记）。子代理依赖后者碰巧覆盖：多书项目（如 XianXia）的子代理没有绑定行。路由决策 `resolveSessionRoute` 与切换器集合 `boundNovelSessions` 都只读会话自身绑定行，不识别父链归属。
- 涉及三个消费层：
  - app 读侧：重定向宿主 `SessionRedirect`、统一打开动作 `openSessionRouted`、切换器集合构建、自动回跳 `resolveAutoAdoptTarget`、活动判定输入（workspace-frame）。
  - plugin 写侧/运行侧：`packages/plugin/src/novel-writer.ts` 的 12 处 `resolveNovelForSession` 调用（灵魂、系统上下文、压缩注入与工具书籍解析）。
  - 数据层：novel-store 的绑定读写位于项目 `novel.db`；会话对象（含 `parentID`）在 server 会话库，两层不可跨包直连。
- 可复用基础：app 的 server sync `session.lineage` 缓存可沿 `parentID` 逐级加载会话链；`collectDescendants` 已支持任意深度后代收集；TaskTool 子会话创建后立即进入运行，子代理首轮 `system.transform` 是继承的天然时机。

## Goals / Non-Goals

**Goals:**

- 「会话归属解析」成为读侧、写侧、展示侧统一判定：自身绑定 → 沿父链最近绑定祖先 → 无归属
- 子代理（任意层级）运行继承并持久化归属；工具与上下文链路对子代理生效
- 所有打开入口对未绑定子代理兜底进书；切换器任意层级可见；回跳与活动消费同一会话集合
- 存量数据零迁移即可访问（读侧解析），写侧在下一次运行时自愈补写

**Non-Goals:**

- 不做批量回填脚本或启动扫描迁移
- 不改 Server HttpApi / Protocol / Schema，无需 SDK 再生成；归属展开在 app 与 plugin 内完成
- 不改 CLI/TUI 侧、不改 i18n locale 文件、不动归档与级联语义
- 不为父链解析失败新增重试或错误界面，沿用既有降级路径

## Decisions

### D1 归属解析按「自身 → 父链最近绑定祖先」逐级判定

解析优先序为：会话自身绑定行 → 沿 `parentID` 链向上第一个存在绑定行的祖先 → 无归属。不做「只查根会话」简化：链中间层可能是被显式绑定的会话，逐级判定与数据事实一致；walk 需要 visited 环防护（沿用 `rootSession`、`collectDescendants` 先例）。

备选：只查根会话——更少查询但可能漏掉中间层绑定并产生错误归属；先收集全部祖先绑定再仲裁——无增量价值。

### D2 写侧继承落在 novel-store 解析函数，经「父链访问器」依赖倒置接入

novel-store 新增带继承语义的解析函数 `resolveNovelForSessionWithInheritance`：入参为会话 ID、目录与可选 `parentOf` 回调（会话 ID → 父会话 ID）。解析序为自身绑定 → 既有单书懒绑定 → 父链 walk（逐级查绑定行，命中即用 `tagNovelSession` 幂等写回）→ 无归属；`parentOf` 查询失败按无归属降级，不阻断会话运行。plugin 在 novel-writer 的 12 处调用点统一改用该函数并传入基于 `clientV2` 的父链访问器（`parentID` 为不可变字段）。单书懒绑定语义原样保留：单书目录无需走链即命中。

备选：plugin 内私有 helper——继承逻辑散落高层、难以被 novel-store 单测覆盖；让 server `novel.session-bindings` 返回展开后的继承行——改变 API 语义、需要会话数据跨层访问且与写侧形成双实现，弃。

### D3 读侧兜底在 app 完成，路由决策纯函数接收祖先链

`resolveSessionRoute` 扩展为接受可选祖先链数据（`{ id, parentID }` 序列），沿链查找最近绑定行；未命中才返回 orphan。链来源为 server sync `session.lineage` 缓存：重定向宿主等待 lineage 落定后与目录一起进入决策；统一打开动作经 `ctx.sync` 的 lineage 解析获得链。链不可得（查询失败或缓存缺失）时按仅自身绑定判定，与现状一致，不阻断路由。

备选：改造 server bindings 接口做展开——影响协议与 SDK 生成链，弃；仅在时间线卡片链接生成处修补——覆盖不到深链、命令面板、通知等入口，弃。

### D4 切换器集合改为「绑定主会话 + parentID 树挂接的全部后代」

`boundNovelSessions` 重写：主会话 = 绑定行 ∩ 会话列表 ∩ 未归档 ∩ 无父会话；随后从每个主会话出发按 `parentID` 广度挂接全部未归档后代（任意层级），后代不要求自身绑定行；节点结构递归扩展 children。孤儿规则保留、判据更新为「祖先行链无法到达任一棵树根的会话不展示」（父缺失、父归档或父未入树的链断点）。主会话排序保持绑定顺序，子节点保持会话列表顺序。

备选：要求后代自身有绑定行——存量未绑定后代不可见，违背本变更目标；平铺展示后代——破坏父链收纳心智，弃。

### D5 自动回跳：记忆恢复覆盖任意层级，回落保持最近活跃主会话

有效记忆的判定在完整树（含后代）内进行：用户上次查看子代理会话时恢复该子代理；无有效记忆时仍回落到最近活跃的未归档主会话（子代理为只读产物线，避免把用户意外拉入只读页）。回跳输入显式区分为「主会话（回落候选）」与「完整集合（记忆查找）」两个列表。

备选：回落也含后代——后台子代理刷新会改变默认落点，行为噪声大；记忆只认主会话——用户从卡片进入子代理后重开必丢，正是本次要修复的路径。

### D6 活动与批注占用判定输入拍平为完整会话集合

workspace-frame 传给活动/占用判定的会话 ID 列表改为递归拍平（含全部后代）；树拍平提为共享辅助，供切换器触发器标签、回跳记忆查找与活动判定共用。

备选：维持顶层集合——与修正后的会话集合定义矛盾，且子代理运行（如批量生成）时书籍无活动指示、批注占用漏判。

### D7 存量零迁移：读侧即时生效，写侧运行时自愈

不新增迁移任务：路由与切换器对存量未绑定后代即刻可用（链解析与树挂接都不依赖后代自身绑定行）；写侧继承在会话下一次运行时补写绑定行（幂等）。无归属的遗留会话维持既有降级。

备选：启动时一次性扫描回填——跨全局会话库与项目 novel.db 的扫描成本与覆盖面不可控，且修复收益与读侧兜底重复。

### D8 切换器渲染递归化与展开语义

切换器条目渲染抽为递归组件：节点渲染条目、展开控件（有子节点时）与动作菜单；缩进按深度递增；展开态继续按会话 ID 记录。当前打开会话的祖先链自动展开，保证活动项可见；触发器标签与归档/导出所需的拍平走同一递归辅助。

备选：限制二级并平铺孙级——层级语义失真；引入虚拟滚动——切换器规模有限，过度设计。

## Risks / Trade-offs

- [父链 walk 引入额外查询（未绑定会话的解析）] → walk 仅在自身与单书懒绑定均未命中时发生；成功一次即持久化，后续零开销；无归属遗留会话重复 walk 深度有限且为本机 HTTP
- [读侧链解析失败导致子代理仍无法打开] → 链不可得时按既有「仅自身绑定」降级，与现状一致，不引入新失败模式
- [异常数据（parentID 环、超深链）渲染出异常菜单] → visited 环防护，后代挂接单次遍历，异常只影响自身子树
- [回跳记忆指向已归档子代理] → 归档级联覆盖后代（既有语义），恢复判定限定未归档集合，失效自动回落主会话
- [多书绑定会话在一棵树上重复或缺失] → 保持现状的跨绑定行去重行为，不在本变更扩大范围
- [既有「发送到绑定会话」类功能（批注执行、驳回接手、设定一键整理）的会话选择与术语边界] → 这些功能的目标选择含主会话过滤，本变更不改其行为；相关 spec 的术语澄清留待各自变更
- [既有 e2e mock 假定后代有绑定行] → 新增用例显式构造「仅父会话有绑定行」与「孙级链」两种 mock 形态

## Migration Plan

单功能分支交付；无 schema/API/协议迁移、无数据回填、无 SDK 再生成。发布后：存量未绑定子代理立即可打开与可见；其下一次运行时补写绑定行。回滚策略：revert 分支即可——绑定行只增不删，向前兼容。

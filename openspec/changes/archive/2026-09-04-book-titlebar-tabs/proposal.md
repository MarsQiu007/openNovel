# 提案：标题栏书籍标签页（tab 体系重定义）

## Why

标签栏按会话组织与产品"以书为中心"的定位错位：绑定会话已统一在工作台打开（无标签），标签栏只剩自由会话与草稿，而真正的工作单元——书籍——没有标签；书籍工作台路由在布局层被降格为首页，既无活跃标识也不参与标签记忆。同时开多本书时，切换必须回书架多跳一程。

## What Changes

- **BREAKING**：标签栏从会话标签重定义为书籍标签——标签栏只承载书籍，打开书籍（任何入口）即注册该书的标签
- 书籍标签常驻标签栏直到手动关闭；书籍间一键切换；数字快捷键（mod+1..9）与拖拽排序沿用既有机制，语义变为切书
- 关闭书籍标签 = 从标签栏移除并回到书架，书籍数据不受影响；进入"最近关闭"栈可重开
- 新增书籍标签数据模型（服务器、目录、书籍 ID 显式携带），书名异步加载并持久化缓存
- **BREAKING**：会话标签与草稿标签退役——自由会话不再注册标签（从会话页面进出），新建会话草稿流程退化为页面态；遗留会话/草稿标签在启动后自动清除
- 书籍工作台路由在布局层升为一等路由（修复被降格为首页的现状），活跃标签判定与最近标签记忆随之生效

## Capabilities

### New Capabilities

- `titlebar-tabs`: 标签栏行为契约（此前 tab 体系为 openCode 原生行为，无 spec）

### Modified Capabilities

（无——`novel-workspace-layout` 的"绑定会话不进入会话标签栏"等既有场景在书籍标签体系下仍然成立，语义兼容，无需 delta）

## Impact

- **packages/app**（主要改动面，约十余文件）：标签上下文（Tab 联合类型收缩为书籍标签、操作集与持久化迁移）、布局层路由解析（书籍分支）、标题栏（注册副作用、书籍标签槽渲染、活跃判定）、标签栏渲染（会话/草稿槽退役）、会话提交流程（草稿页面态化）、命令面板（标签命令语义）、遗留标签清洗
- **数据兼容**：标签持久化键含旧会话/草稿标签的，启动迁移时清洗为空（书籍标签从零积累），"最近关闭"栈同步处理
- **不涉及**：后端 / Protocol / Server HttpApi、写作流水线；书架页与 /sessions 页的既有形态
- 前置 `book-session-switcher` 已实施归档（书内会话切换器与绑定会话统一工作台入口均已上线），本提案建立在其合并可选段单路由形态之上，无其余前置依赖

## Purpose

为小说世界地图提供本地一等数据模型，约束地图草稿与正式地图的生命周期、地图要素几何、世界观关联和角色图钉位置，并提供基础 CRUD API。

## ADDED Requirements

### Requirement: 世界地图生命周期
系统 SHALL 将世界地图保存为小说关联记录，并只允许 `draft` 与 `active` 两种状态。每本小说 MUST 最多同时拥有一个地图草稿和一个正式世界地图。将草稿确认为正式地图时，系统 MUST 在同一个事务中移除旧正式地图并提升新正式地图。

#### Scenario: 创建地图草稿
- **WHEN** 客户端为没有地图草稿的小说创建 `draft` 世界地图
- **THEN** 系统保存该地图及其小说归属
- **THEN** 后续读取可以返回该草稿

#### Scenario: 草稿替换正式地图
- **WHEN** 客户端确认一个 `draft` 地图成为 `active` 正式地图
- **THEN** 系统在同一个事务中删除旧 `active` 地图及其子数据
- **THEN** 被确认的地图成为唯一 `active` 地图

#### Scenario: 拒绝重复生命周期状态
- **WHEN** 客户端为已有 `active` 地图的小说再创建另一个 `active` 地图，或为已有 `draft` 地图的小说再创建另一个 `draft` 地图
- **THEN** 系统拒绝该请求
- **THEN** 已有地图保持不变

### Requirement: 地图要素结构
系统 SHALL 支持关联到指定世界地图的 `region` 与 `place` 两类地图要素。`region` MUST 携带局部平面多边形坐标，`place` MUST 携带局部平面坐标点。所有坐标 MUST 位于 `0..10000` 的地图网格内。

#### Scenario: 创建区域
- **WHEN** 客户端提交类型为 `region` 的地图要素和有效的多边形坐标
- **THEN** 系统保存该区域
- **THEN** 后续读取地图时返回该区域

#### Scenario: 创建命名地点
- **WHEN** 客户端提交类型为 `place` 的地图要素和有效的 `x/y` 坐标
- **THEN** 系统保存该地点
- **THEN** 后续读取地图时返回该地点

#### Scenario: 拒绝越界坐标
- **WHEN** 客户端提交小于 `0` 或大于 `10000` 的地图坐标
- **THEN** 系统拒绝该地图要素
- **THEN** 数据库中不产生部分保存的要素

#### Scenario: 拒绝不支持的要素类型
- **WHEN** 客户端提交 `region` 与 `place` 以外的要素类型
- **THEN** 系统拒绝该请求

### Requirement: 世界观关联
地图要素 MAY 关联一个世界观条目。系统 SHALL 在世界观条目删除时保留地图要素，并将关联置空。删除地图要素时，系统 MUST NOT 删除仍存在于同一地图上的角色图钉，只解除图钉与该要素的关联。

#### Scenario: 世界观条目删除
- **WHEN** 一个被地图要素引用的世界观条目被删除
- **THEN** 地图要素继续存在
- **THEN** 该要素的世界观关联变为空

#### Scenario: 地图要素删除
- **WHEN** 一个被角色图钉引用的地图要素被删除
- **THEN** 角色图钉继续存在
- **THEN** 图钉的地图要素关联变为空

### Requirement: 角色图钉位置
系统 SHALL 支持为角色保存当前世界地图中的图钉位置，并允许更新坐标或关联地图要素。每个角色在同一张地图中 MUST 最多有一个图钉。角色删除时，对应图钉 MUST 级联删除。

#### Scenario: 放置角色图钉
- **WHEN** 客户端为角色在有效地图坐标上创建图钉
- **THEN** 系统保存该角色、地图和坐标的关联
- **THEN** 后续读取地图时返回该图钉

#### Scenario: 更新角色位置
- **WHEN** 客户端更新已有角色图钉的坐标或关联地图要素
- **THEN** 系统更新同一个图钉记录
- **THEN** 该地图不会出现同一角色的重复图钉

#### Scenario: 删除角色
- **WHEN** 一个已有角色图钉的角色被删除
- **THEN** 系统级联删除该角色图钉

### Requirement: 地图聚合读取
系统 SHALL 提供读取地图及其全部地图要素和角色图钉的 API，避免客户端为渲染一张地图逐项发起查询。

#### Scenario: 读取正式地图
- **WHEN** 客户端请求某本小说的 `active` 地图
- **THEN** API 返回地图元数据
- **THEN** API 同时返回该地图的要素列表和角色图钉列表

#### Scenario: 读取地图草稿
- **WHEN** 客户端请求某本小说的 `draft` 地图
- **THEN** API 返回草稿元数据及其子数据
- **THEN** 正式地图不被替换或修改

### Requirement: 增量迁移兼容
系统 SHALL 通过幂等迁移为既有小说数据库补齐世界地图表、外键和索引。已有小说、角色和世界观记录 MUST 保持不变。删除小说时，其世界地图、地图要素和角色图钉 MUST 级联删除。

#### Scenario: 旧数据库升级
- **WHEN** 应用打开不包含世界地图表的既有小说数据库
- **THEN** 系统创建缺失的世界地图表和索引
- **THEN** 既有记录内容保持不变

#### Scenario: 删除小说
- **WHEN** 一本拥有世界地图数据的小说被删除
- **THEN** 该小说的地图、地图要素和角色图钉一起删除
- **THEN** 其他小说的地图数据不受影响

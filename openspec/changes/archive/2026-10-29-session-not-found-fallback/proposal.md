# Proposal

## Why

书内对话面板在“正在查看的会话”失效时（本端删除当前会话、其他客户端删除该会话、路由指向
已不存在的会话）会显示通用错误页“出了点问题”，而不是既有的“会话无法找到”兜底。实测删除
当前打开的书内会话后，面板立刻进入通用错误页且停留在已删除会话的路由，刷新仍然复现，只能
手动返回书架再重新进入书籍。

根因有二：

1. 服务端 404 被 Solid 的错误处理包装成 `Error("Unknown error", { cause: <SessionNotFoundError 体> })`，
   而面板的“会话不存在”判定只识别 `cause.body` 这一种包装形状，于是把明确的“会话不存在”
   误判为未知故障，落入通用错误页。
2. 删除当前会话后，该书会话集合与会话记忆尚未刷新，工作台“未选中会话自动回跳”仍可能把
   用户带回刚被删除的会话，再次触发上面的错误页。

## What Changes

- 统一“会话不存在”判定：无论错误来自服务端 404、本地合成消息，还是被错误外壳包装，面板
  一律按会话不存在处理并渲染既有的“会话无法找到”兜底（含会话标识与返回入口）。
- 非“会话不存在”的故障（网络失败、服务端 5xx 等）继续渲染通用错误页，不得被误判为会话缺失。
- 删除当前打开的书内会话后，先刷新该书归属会话集合、清理指向已删除会话的会话记忆，再回到
  书籍工作台（会话段为空）；自动回跳 MUST NOT 重新选中已删除的会话。
- 兜底中的返回入口在书内会话场景回到该书工作台基础视图，不离开工作台；其他场景沿用现有行为。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `novel-chat-panel`: 新增“正在查看的会话不存在时的面板兜底”要求，并补充“删除当前打开会话后
  的面板定位”行为——删除后回到工作台基础视图或最近有效会话，不得重新选中已删除会话，也不得
  以通用错误页作为删除结果。

## Impact

- `packages/app`：会话错误判定与归一化（`utils/server-errors`、`pages/session/session-lineage`、
  `pages/session.tsx` 兜底渲染）、书内工作台删除流程与会话回跳（`pages/session/timeline/message-timeline`、
  `pages/novel/workspace-frame`）。
- 不涉及 protocol / core / server 契约，不需要重新生成 SDK；无数据模型或本地数据迁移影响。

## Non-Goals

- 不改变会话归档、导出、切换器的既有语义与列表刷新策略。
- 不新增服务端接口、错误码或重试策略。
- 不新增或修改 i18n 文案键；复用既有 `session.error.notFound*` 键。
- 不改造其他页面（书架、独立会话路由宿主）的错误页样式。

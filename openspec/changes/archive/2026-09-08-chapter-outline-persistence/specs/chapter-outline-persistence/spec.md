## Purpose

把章节大纲作为章节记录的一等数据持久化，保证流水线和写作快照不依赖最脆弱的 Markdown 文件，同时兼容已有本地项目。

## ADDED Requirements

### Requirement: 章纲随章节记录持久化
系统 SHALL 将章节大纲正文保存在章节记录中，并随章节的创建、更新和删除维护。章纲记录 MUST 与章节 ID 和章节序号关联。

#### Scenario: 生成章纲
- **WHEN** AI 或用户通过章纲生成工具写入完整的章纲 Markdown
- **THEN** 章节记录保存该章纲
- **THEN** 后续无需读取外部文件即可获得章纲

#### Scenario: 删除章节
- **WHEN** 用户删除某个章节
- **THEN** 该章节记录及其保存的章纲一起消失

### Requirement: 数据库为读取权威来源
章纲生成、流水线读取、写作快照和 WebUI 章纲展示 SHALL 优先读取数据库中的章纲。数据库章纲为空时，系统 MAY 读取存量 Markdown 文件，并在读取成功后导入数据库。

#### Scenario: 数据库有章纲
- **WHEN** 章节记录的章纲字段非空且对应 Markdown 文件缺失
- **THEN** 章纲读取工具仍返回章纲内容
- **THEN** 写作快照仍包含章纲

#### Scenario: 从存量文件导入
- **WHEN** 章节记录的章纲字段为空且存在对应 `chapter-{n}.md`
- **THEN** 系统读取该文件内容并写入章节记录
- **THEN** 后续读取优先使用数据库内容

#### Scenario: 文件导入失败
- **WHEN** 数据库章纲为空且存量文件读取失败
- **THEN** 写作主流程不因此崩溃
- **THEN** 系统按章纲缺失处理并允许重新生成

### Requirement: 编辑保持双写兼容
通过 WebUI 保存章纲时，系统 SHALL 更新数据库，SHALL 同步写回对应的 `chapter-{n}.md` 文件。数据库内容为权威内容；文件仅作为过渡兼容产物。

#### Scenario: 编辑章纲
- **WHEN** 用户在 WebUI 编辑并保存第 3 章章纲
- **THEN** 数据库中的第 3 章章纲更新
- **THEN** `chapter-3.md` 同步更新

#### Scenario: 旧文件仍可查看
- **WHEN** 用户尚未触发读取导入但打开大纲面板
- **THEN** 大纲面板可显示存量文件中的章纲内容

### Requirement: 迁移不阻塞写作
旧库缺少章纲列时，系统 SHALL 自动补列。存量文件导入失败 MUST NOT 阻止章节创建、读取、写作快照组装或后续章纲生成。

#### Scenario: 旧库升级
- **WHEN** 应用打开缺少 `outline` 列的旧章节数据库
- **THEN** 系统自动添加该列
- **THEN** 已有章节、正文和其他字段保持不变

#### Scenario: 导入失败后继续写作
- **WHEN** 存量章纲文件损坏或不可读
- **THEN** 流水线可提示章纲缺失并允许重新生成
- **THEN** 数据库读写和其他章节流程不因导入失败阻塞

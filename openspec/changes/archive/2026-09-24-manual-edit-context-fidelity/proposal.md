## Why

手动编辑和 AI 写入目前走的是两套事实维护链路：多数 UI 编辑只更新正式表，AI 工具则依赖状态提交、引用扫描、影响任务和上下文快照维护创作记忆。因此用户在界面里保存的正文或设定，可能不会进入 AI 派生记忆，也可能因为静默失败或半提交而没有形成可靠数据。

## What Changes

- 建立统一的手动编辑同步契约：UI 编辑必须经过与 AI 正式写入等价的数据校验、持久化、引用维护和上下文同步策略。
- 新增小说编辑数据目录，将字段明确分类为创作事实、工作流数据或 UI 偏好，并声明每类数据的 AI 感知方式。
- 手动修改章节正文后，系统必须同步或排队重建章节摘要、实体引用、受影响段摘要和故事主轴，并在写作流水线消费前阻止静默使用过期记忆。
- 手动修改角色、世界观、关系、剧情线、伏笔等正式设定时，必须复用既有设定影响面服务，生成可追踪的联动任务。
- 统一保存结果语义：目标不存在时必须显式失败，禁止静默跳过；多步保存必须避免留下不可解释的半提交状态。
- UI 必须展示保存中、已保存、保存失败、待同步、同步失败和已跳过状态；自动保存失败不得被静默吞掉。
- 若公开 HttpApi 返回结构或入参变化，从 `packages/client` 重新生成 SDK，不手改 generated 文件。

### 非目标

- 不把画布布局、侧栏宽度、滚动位置、搜索词等纯 UI 偏好注入 AI 上下文。
- 不在本变更中重写完整 8 步写作流水线。
- 不要求所有批注、评审、执行轮次等过程记录都进入 writer 基线快照。
- 不自动删除用户数据；联动修改仍按影响任务的可执行或待确认策略处理。

## Capabilities

### New Capabilities

- `manual-edit-sync`: 定义 UI 手动编辑的统一持久化、数据分类、AI 同步、过期检测、保存反馈和兼容性要求。

### Modified Capabilities

- `setting-impact-flow`: 将统一影响面入口从 AI 工具路径扩展到所有正式设定的手动 UI 写入路径。
- `context-fidelity`: 增加手动正文修订后的派生记忆同步和过期记忆消费限制。

## Impact

- `packages/app`：小说工作台各编辑入口接入统一保存结果、失败提示和待同步状态。
- `packages/server`：手动编辑 HTTP 处理层补充统一校验、事务保存、错误返回和同步请求落库。
- `packages/opennovel`：组合 Server 与 Plugin，启动手动编辑同步 worker 并调度 AI 侧副作用。
- `packages/novel-store`：补充派生数据新鲜度、引用重建和编辑同步所需的数据模型或迁移。
- `packages/plugin`：复用引用扫描、状态提取、影响任务和上下文快照能力，处理手动编辑同步任务。
- `packages/schema` / `packages/protocol` / `packages/client`：更新同步状态、联合保存和显式错误契约；修改公开 HttpApi 后从 `packages/client` 重新生成客户端。
- `packages/desktop`：只受本地后台任务和错误提示的间接影响，不需要改变桌面壳架构。
- 兼容性：既有本地数据库必须可打开；历史章节和设定允许标记为“待同步”，不得因缺少新元数据而阻塞阅读、导出或写作。

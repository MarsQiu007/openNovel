# Design

## Context

动机见 proposal.md - Why；这里只列影响方案的事实与约束：

- 三个入口（书架点击、标签选择、关闭标签后落入相邻书）都落在不含会话段的书籍路由：标签地址由 `tabHref` 生成到 `novelID` 为止，关闭后导航到相邻书基础地址；「自动回跳」负责二次定址——本变更把回跳并入门控，消除「先基础视图、后被替换」。
- 首帧门现状（`workspace-data.ts`）：`loading = detail || volumes || chapters || tension`；`tension` 无真实消费方（张力面板 `TensionChart` 自查询同一 queryKey），属于纯门控负担。
- 恢复时序现状（`workspace-frame.tsx`）：阅读进度恢复等 `readingProgressReady() && !data.loading`；按书现场恢复等 outline / world / characters 三个查询全部就绪；展开态在打开后通过 `setSearchParams` 恢复；回跳 effect 等 `boundSessions` 查询后二次导航。每个等待点都是一次可见翻转窗口，且与首帧门互不等待（两场赛跑）。
- 挂载副作用现状：`createCloudSyncAutoPilot()` 在每次进入工作台时 `onMount` 触发 `POST /api/sync/run`（未配置云盘必然失败、配置后走真实同步，下载时失效全部小说查询）；`useNovelLiveInvalidation` 以值参数捕获 novelID，切书后失效作用域指向前一本书。
- 持久化：桌面端 `persisted` 走异步 IPC（electron-store），就绪（`readingProgressReady` 等）存在非零窗口，语义是「默认值 → 异步回填」；不并入门控时必然产生可见翻转。
- 约束：不改绑定会话集合查询策略（重拉 / 空守卫 / 上限 1000 保持）；不改三区布局与面板交互；不改 i18n 文案；无协议与数据变更。

## Goals / Non-Goals

**Goals：**

- 三入口打开书籍的可见时序收敛为「加载 → 最终视图」一次转换；地址定址一次到位（无被替换的中间历史条目）。
- 首帧等待集收敛到最小：首帧必需数据 + 持久化就绪 + 回跳决策；次要数据不再阻塞首帧。
- 现场恢复在首帧内生效；失效回落成为罕见路径而非常态翻转。
- 工作台挂载不再携带与首屏竞争的全局副作用；实时失效作用域随当前书。

**Non-Goals：**

- 不重构查询层 / 缓存层（只调缓存保留时长）；不引入预取与骨架屏体系。
- 不改 `loadBoundSessionsWithEmptyGuard` 的次数与间隔；不改会话列表取 1000 条的窗口策略。
- 不改云同步协议、策略与设置开关语义；仅迁移触发位置。

## Decisions

### D1: 单一首帧门（合并数据、恢复与决策）

工作台引入组合就绪判定 `firstFrameReady`（首帧数据就绪〔detail / volumes / chapters〕+ 持久化就绪〔readingProgress / perBookState / layout〕+ 回跳决策落定 + 展开态同步完成），替代现有 `Show when={!data.loading}` 的门条件。门关闭期间执行：回跳 replace 导航、展开态 URL replace 同步、章节选中与左栏模式落值；门仅在「无待应用导航且决策与当前地址一致」时打开。

备选：保留分散 effect、只调整各自守卫——等待点之间的竞态与翻转窗口仍在，弃；骨架直出（不阻塞地边渲染边收敛）——超出本变更范围，留待后续独立变更。

约束：门打开前 MUST 达到稳定态——不存在任何将导致可见替换的待应用导航。

### D2: 回跳与展开态同步一律 replace

回跳导航（基础地址 → 会话地址）与展开态 URL 同步改为 replace：历史中不产生被替换的中间条目，返回键语义正确（打开书籍后按返回直接离开该书工作台，而不是回到会被再次替换的基础视图）。快速连切书时以「发起前仍处于同一 novelID」校验，过期决策丢弃。

备选：维持 push——返回键回到基础视图并触发再次回跳，形成「返回陷阱」，弃。

### D3: 恢复先落值后校验（乐观恢复）

布局与现场值在门内直接生效：右栏面板 / 展开态 / 左栏模式 / 章节选中先行落值（章节以首帧数据校验有效性）；大纲 / 世界观 / 关系选中采纳乐观恢复（门内直接应用持久化值），校验拆分为随各自数据就绪的静默补校验，仅失效时回落（罕见路径允许一次修正）。展开态以门内 replace 同步地址，不再出现「打开后弹开面板」。

备选：把 outline / world / characters 并入首帧门后再渲染——多查询依赖带来失败放大与等待延长，弃；保持现状（三查询全就绪后统一恢复）——翻转窗口最大，弃。

### D4: 首帧门数据分级（张力出列）

将张力从 `workspace-data` 的载荷与首帧门移除（全仓核对无消费方；张力面板已在挂载时自行查询并带自身加载态）。其余次要数据（outline / world / characters / style-guide / 升级横幅等）保持后台加载，不入门。

备选：保留张力在门内（现状）——无谓等待一项网络往返，弃；把次要查询全部纳入门（「全就绪再渲染」）——失败放大、首帧更长，弃。

### D5: 挂载副作用迁移与实时失效作用域修复

云同步 autopilot 迁移至服务器作用域应用壳（`SelectedServerProviders` 内、与 `NewLayout` 同层）：语义保持——启动执行一次 + 页面前台 60s 轮询 + beforeunload beacon；工作台挂载不再触发。`useNovelLiveInvalidation` 的 novelID 改为 accessor：订阅与定时器保持单份，失效判定与 bindings 过滤在调用时读取当前位置；切书后事件失效命中当前书。

备选：autopilot 保留在工作台但增加节流——仍与首屏共享触发窗口，且「进入工作台」不是同步的合适触发语义，弃。

### D6: 读取类查询缓存保留时长上调

为读取类小说查询（detail / volumes / chapters / tension / outline / world / characters / chapter / annotations 等挂载即重取的 novelKeys 读取族）设置更长 `gcTime`（建议 30 分钟，共享常量逐 hook 应用）；`bound-sessions`、`sync-status` 等实时类保持现状（含 staleTime 0 + 重拉语义）。不改全局 QueryClient 默认、不调 staleTime（后台刷新节奏保持）。

备选：提高全局 gcTime——波及所有查询族的内存与新鲜度语义，弃；调高 staleTime——改变既有后台刷新节奏、涉及新鲜度权衡，先不动，按测量结果决定是否另立。

## Risks / Trade-offs

- [门等待变成「更长的加载」观感] → 门集合仅新增「回跳决策」（本就在等待，只是从翻转改为统一加载态），且数据分级与缓存保留同步压低总时长；验收包含前后对照测量。
- [绑定会话查询失败时门无法落定] → 重试耗尽后按「无回跳」开门渲染基础视图（切换器保留失败占位与手动重试），不得无限自旋。
- [持久化存储读取异常时门被拖住] → `persisted` 对缺失 / 损坏数据按默认值完成初始化，不阻塞开门（既有降级语义）。
- [乐观恢复的失效回落仍有一次修正] → 仅失效路径（删除 / 归档后重开），记录为可接受残余；e2e 覆盖「有效恢复无翻转」。
- [快速连切书产生过期回跳决策] → 发起前校验同一 novelID，过期即丢弃；e2e 按需覆盖连点。
- [张力出列后张力面板首次打开出现即时加载] → 面板已有自身加载态与就绪门，行为不变。
- [autopilot 迁移后同步频率下降] → 由「每次进工作台」变为「应用启动 + 周期」；如需要更高频同步可后续调整轮询间隔（非本变更）。

## Migration Plan

纯前端 + e2e 改动；无数据 / 协议 / 配置迁移。回滚 = revert 本变更提交，行为退回「多段加载 + 二次导航」现状。

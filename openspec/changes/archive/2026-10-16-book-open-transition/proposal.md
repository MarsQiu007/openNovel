# Proposal

## Why

桌面端「打开书籍」的三个高频入口——书架点击、标签切换、关闭标签后落入相邻书——共享同一条工作台切换链路，但首屏所需数据、布局恢复值与会话回跳决策分属多场互不等待的赛跑：用户会先看到阅读视图（或尚未落定的布局），数拍之后被替换为写作视图与记忆面板，地址也会发生两次变化。用户反馈「打开书籍要等半天才能打开，有时候还得闪一下；切换书籍标签、关闭书籍标签同样如此」。相关代码注释已记录「从书架点击进入时，路由过渡与数据就绪会让子树多次（含被丢弃的过渡渲染）重建」的既有现象。核心创作路径上的多段等待与可见跳变直接损伤写作心流，且三个入口症状一致，是同一个结构性问题的三种表现。

## What Changes

- **首帧收敛（单一首帧门 + 一次定址）**：把「首帧必需数据 + 布局/现场恢复值 + 会话回跳决策 + 展开态地址同步」合并为统一首帧门；门内完成回跳导航（改用 replace，不残留被替换的中间地址条目）；首个内容帧直接呈现最终视图与最终布局，不再出现被替换的中间视图（书架/标签/关闭落位三入口一致）。
- **门控数据分级**：首帧门只等待小说详情 / 卷列表 / 章节列表；张力数据（当前仅参与门控、无真实消费方——张力面板自行查询同一数据）移出首帧门，其余次要数据由宿主界面就地加载。
- **恢复先落值后校验**：布局现场（右栏面板、展开态、左栏模式、章节选中）在门内落值生效；大纲 / 世界观 / 关系选中采纳乐观恢复 + 随各自数据就绪的静默校验（仅失效时回落）。
- **挂载副作用迁移**：云同步 autopilot 从「每次进入工作台触发」迁移到应用壳（启动一次 + 周期轮询），不再与书籍首屏加载竞争。
- **实时失效修复**：修复工作台实时失效的作用域捕获——切书后会话事件的失效命中当前书（现状为进入工作台时的第一本书）。
- **缓存保留**：读取类小说查询提高缓存保留时长（gcTime），减少离开数分钟后重开书籍的冷启动；实时类查询（绑定会话、同步状态）保持既有重拉语义。
- 验证：新增/扩展 e2e（无中间态直达、首帧不等待次要数据、首帧即恢复现场）与单测（实时失效作用域），并以改动前后对照记录收敛证据。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `novel-workspace-layout`：新增「书籍打开的首帧收敛」要求——打开/切换书籍在统一加载态内完成首帧准备，首个内容帧即最终视图与最终布局，不被次要数据阻塞。
- `novel-chat-panel`：修订「未选中会话时自动回到最近绑定会话」——回跳决策在首个内容帧前完成并与地址保持一致，加载等待期间不得先呈现将被替换的中间视图。

## 非目标

- 不做骨架屏 / 逐区占位体系：保持现有统一加载态语言，不引入过渡动画。
- 不改绑定会话集合查询的重拉与空守卫策略（次数 / 间隔 / 上限均不动），只改「等待如何呈现」。
- 不做书架 / 标签悬停预取：先以首帧收敛与缓存保留改善体感，预取留待测量数据支持后另立。
- 不改三区布局、分栏宽度、面板交互与会话归属解析 / 降级规则。
- 不改云同步协议与策略；仅迁移触发位置（含 beforeunload 兜底语义保持）。
- 无 Protocol / Server HttpApi 变更，无需 SDK 再生成；无数据迁移。

## Impact

- **packages/app**（唯一改动面）：
  - `src/pages/novel/workspace-frame.tsx`：单一首帧门、恢复落值时序、回跳 replace、autopilot 调用移除。
  - `src/pages/novel/workspace-data.ts`：首帧门数据分级（张力出列）。
  - `src/context/novel-live.ts`：实时失效作用域 accessor 化修复。
  - `src/context/cloud-sync.tsx` 与应用壳挂载点：autopilot 迁移。
  - `src/context/novel-queries.ts`：读取类查询缓存保留时长。
- **e2e / 单测**：新增 `packages/app/e2e/novel/book-open-transition.spec.ts` 与实时失效作用域单测。
- **packages/novel-store / plugin / opennovel / desktop / schema / protocol / client / core**：无代码改动。
- **数据兼容性**：无 schema 与数据变更、无迁移；纯前端行为收敛，历史本地数据不受影响。
- **CI**：预期 generate / typecheck / test 不受影响；app 包测试与相关 e2e 子集通过（详见 tasks）。

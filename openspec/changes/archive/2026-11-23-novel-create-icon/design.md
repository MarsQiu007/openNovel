# Design

## Context

`ButtonV2` 的图标名最终由 V2 图标注册表解析。书架页「创建小说」按钮当前仍使用 `icon="add"`，但注册表中只有 `folder-add-left` 等既有名称，没有 `add`，因此开发环境触发缺失兜底并把该按钮图标渲染为空白。

## Goals / Non-Goals

**Goals:**

- 在共享 V2 图标注册表中补齐 `add` 图标。
- 保持 `add` 作为创建语义图标的通用名称，避免为了单一按钮把调用点改成语义不准确的目录图标。
- 用既有图标单测锁定注册结果，防止再次出现未注册名。

**Non-Goals:**

- 不重构图标系统或引入第三方图标库。
- 不修改「创建小说」按钮的文案、位置、导航、禁用规则。
- 不处理重复命令注册或字体加载提示。

## Decisions

- **在注册表中新增 `add`，而不是替换调用点**：书架页的语义就是“创建”，`add` 是准确的图标名；改成 `folder-add-left` 会让图标偏向目录操作语义。使用 16×16 视窗和 `currentColor` 绘制加号，保证与现有 V2 图标的尺寸与配色机制一致。
- **用既有单测文件扩展断言**：`packages/ui/src/v2/components/icon.test.ts` 已经覆盖注册名解析、symbol id 与缺失告警，新增 `add` 断言可以在最小范围内验证行为，不需要新建测试结构。

## Risks / Trade-offs

- [新图标视觉风格与设计稿不一致] → 实现时沿用 16 视窗、`currentColor` 与既有线性描边风格，并在人工冒烟时检查书架按钮。
- [`add` 未来被其他页面误用] → 语义为通用创建操作，属于注册表的合理通用图标；不需要在本次扩大范围做图标命名治理。

## Migration Plan

无需数据迁移。构建时直接包含新图标注册项；如需回滚，移除注册项与对应测试即可恢复原有空白兜底行为。

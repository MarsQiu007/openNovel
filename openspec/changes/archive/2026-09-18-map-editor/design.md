## Context

world-map-data 的 CRUD API 已就绪但无编辑入口；world-map-viewing（渲染提案）提供地图画布。编辑必须在草稿上进行，提升遵循 ADR-0001 强确认。

## Goals / Non-Goals

**Goals:**

- 草稿派生（复制要素与图钉）与空白创建。
- 区域绘制、地点放置、拖拽、属性面板。
- 操作防抖保存，失败可重试。

**Non-Goals:**

- AI 生成、LOD、直接编辑正式地图。

## Decisions

### 派生草稿在服务端循环调用既有 API 实现

数据层没有"复制地图"原语。派生时先创建空白草稿，再逐个调用 createWorldMapFeature / createCharacterMapPin 复制源地图内容。规模小（几十个要素），循环开销可接受，不为此扩展数据层。

### 编辑一律在草稿上

正式地图只读（复用渲染提案）。需要修改正式地图时从它派生草稿，改完后走强确认提升。这保证"正式地图永远是被确认过的状态"，与 ADR-0001 的不可逆提升互补。

### 保存策略：操作即保存（防抖 800ms）

属性修改、拖拽结束、绘制闭合都触发对应 CRUD 调用（编辑用 update，新建用 create）。不做显式"保存按钮"，失败时右下角提示与重试。拖拽中的 move 事件不落盘，只在释放时保存最终坐标。

### 绘制交互用 Leaflet 原生事件

区域绘制：点击收集顶点（临时 polyline 预览），按钮或双击闭合，Escape 取消。不引入 leaflet-draw 插件（维护停滞、样式难融入 v2 系统）。

### 区域顶点可拖拽

选中区域后显示各顶点手柄，拖拽单个顶点实时改形，其余顶点保持不动，释放时保存并钳制坐标范围。相比"删除重画"，顶点微调是多边形编辑的基础体验；实现上为每个顶点维护可拖 marker，成本可控。

### 不做撤销/重做

操作即保存模式下撤销需要完整命令栈。误操作由三层兜底：草稿可放弃重来、提升有强确认（ADR-0001）、单要素删除有确认提示。撤销留到真有痛点再加。

### 图钉唯一性前置校验

安放图钉前前端先查询当前草稿图钉列表判断该角色是否已有图钉，重复则禁用并提示；API 层的冲突约束仍是最终防线。

## Risks / Trade-offs

- [循环复制派生在极端大地图下变慢] → 第一版规模小，接受；将来数据层可加批量复制端点。
- [防抖保存期间用户关闭页面丢失最后修改] → beforeunload 提示未保存变更。
- [草稿上直接删要素不可恢复] → 与"不保留版本历史"的整体取舍一致，接受。

## Migration Plan

纯前端新增，无数据迁移。依赖渲染提案的地图画布组件。

# derived-data-upgrade Specification Delta

## MODIFIED Requirements

### Requirement: 升级进度可见、可暂停、可续跑

升级进度 SHALL 以升级运行（upgrade run）为唯一事实源聚合展示：进度分母 SHALL 为 run 的目标章节集合，不按同步队列来源过滤；`skipped`（被取代）队列条目 SHALL NOT 计入任何进度分母；取代链两端 SHALL 自动跟随到该章最新条目。进度负载 SHALL 携带：当前正在重建的章节标识与开始时间、worker 活性信号（最近轮询时间）、按已同步速率推算的预计剩余时间。用户 SHALL 能暂停升级：暂停后 worker SHALL 停止消费 upgrade 来源任务，队列条目保留。升级消费闸门状态 SHALL 持久化，进程重启后 SHALL 保持暂停或续跑的最后状态。续跑 SHALL 重新开放消费，已完成项 SHALL 按指纹去重幂等跳过。单章失败原因 SHALL 以人话分类与行动建议展示，原始错误文本仅作细节展开。

进度展示 SHALL 覆盖「升级运行实体与章节状态机」定义的全部进行中状态，包括瞬时失败退避等待：退避等待时进度 SHALL 显示恢复时间或下一次尝试时间，而不是无差别的「待同步」。

#### Scenario: 进度聚合展示

- **WHEN** 升级执行中用户查看进度
- **THEN** 展示已同步、待同步、失败章节数与总数

#### Scenario: 失败原因可查

- **WHEN** 某章升级失败
- **THEN** 进度视图能查看该章失败原因

#### Scenario: 进度按运行目标聚合而非队列来源

- **WHEN** 某章的 upgrade 源条目被 dedup 取代为 `skipped`、其重建实际由 manual 源条目完成
- **THEN** 进度以 run 目标章节聚合，该章计入已同步，幽灵 `skipped` 条目不出现在任何分母
- **AND** 横幅到达完成态（或仅剩真实失败章节）

#### Scenario: 进度携带当前章节与预计剩余时间

- **WHEN** 升级执行中且某章正在重建
- **THEN** 进度负载包含该章章节 ID 与重建开始时间，以及按已同步章节速率推算的预计剩余时间

#### Scenario: worker 无活性可识别

- **WHEN** worker 超过两个轮询周期未轮询（进程退出或目录未注册）
- **THEN** 进度负载的活性信号标注无活性，升级视图显示「同步未在运行」提示
- **AND** 该提示 SHALL NOT 把无活性误判为失败或完成

#### Scenario: 瞬时失败退避中的进度语义

- **WHEN** 某章因 provider 配额错误进入退避等待（恢复时间已知）
- **THEN** 进度展示该章为「等待恢复」并携带恢复时间，而非计入失败数
- **AND** 恢复时间到达后该章自动继续，无需用户显式重试

#### Scenario: 失败原因人话分类展示

- **WHEN** 某章进入终态失败（如模型未配置、内容无法解析）
- **THEN** 升级视图展示分类后的人话说明与行动建议（如「请配置默认模型后重试」），原始错误文本仅作可展开细节

#### Scenario: 暂停保留队列

- **WHEN** 用户暂停升级
- **THEN** worker 停止消费 upgrade 来源任务，已入队条目与状态保留，手动编辑触发的重建不受影响

#### Scenario: 续跑幂等继续

- **WHEN** 用户续跑已暂停的升级
- **THEN** worker 重新消费 upgrade 任务，已 synced 的章节跳过，failed 章节按既有重试语义处理

#### Scenario: 阶段一执行期间有反馈

- **WHEN** 用户点击确认升级、start 请求尚未返回（Phase 1 执行中）
- **THEN** 升级视图显示「确定性回填执行中」，不出现静默无反馈窗口

### Requirement: 升级失败章节显式重试

升级进度 SHALL 为每个失败章节返回对应的章节标识。升级视图 SHALL 提供显式的失败章节重试操作；该操作 SHALL 以章节为单位定位：找到该章最新非吸收态队列条目重置为 `pending`，或为其入队新条目；SHALL NOT 要求条目 `source=upgrade` 且 `failed` 才允许重试，也不得直接修改派生数据同步状态。重试后进度视图 SHALL 反映新的聚合结果；消费闸门为暂停时，条目保持 `pending`，待续跑后再消费。

系统 SHALL NOT 在进程启动或进度查询时自动重试终态失败的升级条目；终态错误的重试必须由用户显式触发。瞬时错误的自动恢复由「升级运行实体与章节状态机」的退避语义承担，不受本约束限制（它不是进程启动时的隐式重试，而是进行中执行的延续）。

#### Scenario: 失败进度携带队列条目 ID

- **WHEN** 升级进度查询返回失败章节列表
- **THEN** 每个失败项包含可用于重试的队列条目 ID 与该章章节 ID

#### Scenario: 启动不自动重试失败章节

- **WHEN** 桌面端或服务进程重启且存在终态失败的升级章节
- **THEN** 系统不自动发起模型调用或把这些章节改为待同步，只有用户显式重试后才重新进入消费队列

#### Scenario: 失败进度携带章节标识

- **WHEN** 升级进度查询返回失败章节列表
- **THEN** 每个失败项包含章节 ID、人话分类的失败说明与行动建议、可用于重试的定位信息

#### Scenario: 用户重试失败章节

- **WHEN** 用户在升级视图中触发失败章节重试，且该章最新条目为 failed 或由 manual 源取代
- **THEN** 该章回到待同步，进度重新聚合该章为待同步
- **AND** 重试不要求该条目来源为 upgrade

#### Scenario: 暂停状态下重试保留待同步

- **WHEN** 升级消费闸门为暂停且用户重试失败章节
- **THEN** 该章保持待同步但 worker 暂不消费，用户续跑后继续

## ADDED Requirements

### Requirement: 升级运行实体与章节状态机

系统 SHALL 维护升级运行（upgrade run）实体：用户确认升级时创建 run，记录目标章节集合与创建时间；run 的每章跟踪 SHALL 为显式状态机（pending → running → synced / failed，失败按可恢复性区分为 waiting-retry 与 terminal）。run 到达终态当且仅当全部目标章节到达吸收态（synced 或 terminal-failed）。进度、暂停、重试、展示 SHALL 以 run 为唯一事实源；同步队列退回 Phase 2 消费实现，其条目状态经消费回写映射进 run 章节状态。同一小说同一时刻 SHALL 至多一个活跃 run；再次触发升级 SHALL 并入既有活跃 run 的目标集合而非并发开第二个 run。

#### Scenario: 确认升级创建运行

- **WHEN** 用户在成本预估弹窗确认升级
- **THEN** 系统创建 run，记录目标章节集合（Phase 1 完成后待重建的章节），Phase 2 队列消费与该 run 绑定

#### Scenario: 章节状态随消费推进

- **WHEN** worker 开始消费某章重建任务
- **THEN** 该章在 run 中进入 running 并记录开始时间；重建成功进入 synced；失败按可恢复性进入 waiting-retry 或 terminal

#### Scenario: 运行终态判定

- **WHEN** run 全部目标章节到达 synced 或 terminal
- **THEN** run 到达终态，升级完成（terminal 章节按失败呈现，可逐章重试）

#### Scenario: 再次触发并入活跃运行

- **WHEN** 已存在活跃 run 时用户再次确认升级
- **THEN** 新判定出的待重建章节并入既有 run 目标集合，不创建第二个并发 run

### Requirement: 失败可恢复性分类与自动续跑

瞬时失败（provider 配额、限流、网络类）SHALL 指数退避自动重试；错误携带恢复时间（如额度重置时间）时 SHALL 到点自动续跑。终态失败（内容无法解析、模型不可用）SHALL 保持 terminal 直至用户显式重试。自动恢复 SHALL NOT 消耗用户显式重试次数语义，也不违反「启动不自动重试」约束。

#### Scenario: 配额类瞬时失败自动恢复

- **WHEN** 某章重建因 provider 配额错误失败且错误携带恢复时间
- **THEN** 该章进入 waiting-retry 并记录恢复时间，到点自动重新消费
- **AND** 全程无需用户显式重试，升级视图可见恢复时间

#### Scenario: 瞬时失败指数退避

- **WHEN** 某章重建因限流或网络错误失败且未携带恢复时间
- **THEN** 该章按指数退避自动重试，达到尝试上限后转 terminal 并保留人话说明

### Requirement: 存量数据对账

打开书籍时，系统 SHALL 对升级状态做幂等对账：按升级任务注册表与指纹判定重算每章真实状态，把历史遗留的孤儿队列条目（无活跃 run 归属的 pending / skipped / failed）映射进对账结果。已实际完成重建的章节（内容哈希与派生数据指纹一致）SHALL 收编为已完成，幽灵 `skipped` 条目 SHALL NOT 再计入任何进度分母；未满足判定且无在途条目的章节 SHALL 纳入可升级集合，等待用户显式确认。对账 SHALL NOT 产生 AI 调用，SHALL NOT 伪造已同步（诚实性约束不变），SHALL NOT 把终态失败章节自动改为待同步。

#### Scenario: 幽灵条目对账消解

- **WHEN** 打开的书籍存在被取代的 skipped upgrade 条目，且该章内容由 manual 源条目完成重建（内容哈希与摘要指纹一致）
- **THEN** 对账把该章收编为已完成，升级横幅不再显示无终态的「升级中」

#### Scenario: 真实未完成进入可升级集合

- **WHEN** 对账发现某章缺指纹基线或派生数据过期且无在途队列条目
- **THEN** 该章进入待升级集合，按既有成本预估与显式触发语义呈现

#### Scenario: 对账不消耗 AI 不伪造状态

- **WHEN** 对账执行
- **THEN** 全程零模型调用；收编为已完成的章节必须有内容哈希与派生数据指纹一致的证据
- **AND** 终态失败章节保持终态，仅提示用户可显式重试

#### Scenario: 对账幂等

- **WHEN** 同一书籍短时间内多次打开
- **THEN** 对账结果一致，不重复产生条目、不重复标记、不抖动横幅状态

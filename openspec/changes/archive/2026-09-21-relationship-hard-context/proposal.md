## Why

写作快照中的角色关系目前只是普通参考信息，仍会经历相关性过滤和预算裁剪；writer 的最高优先级硬约束只明确覆盖世界观条目。因此已建立的“母子关系”可能在生成时不可见或不够权威，导致模型创建“儿子”这类称谓型角色或偏离既有关系。

## What Changes

- 将本章相关的正式角色关系提升为写作上下文中的硬约束。
- 相关关系在预算裁剪中获得专用保护，不会因普通截断而被静默丢弃。
- 快照输出使用语义化、带方向的关系表述，例如“张三是李四的儿子”，而不是仅输出 `A ↔ B（母子）`。
- 为可确定方向的亲属关系生成上下文称谓绑定，使“儿子”能解析到已命名的既有角色。

## Non-Goals

- 不修改关系表数据库 schema。
- 不引入通用角色别名表。
- 不实现跨章节自动改写正文。
- 不在本提案中处理 auditor、observer 与候选区防漂移；这些由 `writing-drift-guards` 提案承接。

## Capabilities

### New Capabilities

- `relationship-context`: 定义写作快照中角色关系的选择、保护、语义化呈现与亲属称谓绑定要求。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `packages/plugin`：写作快照装配、召回筛选、预算裁剪和 writer 上下文序列化。
- 可能影响上下文工具输出的文本和内部 metadata，但不改变公开 HTTP API 或数据库 schema。
- 现有本地关系数据保持兼容；方向或描述缺失时仍以原始关系类型呈现。

## Context

目录级同步数据已有 `session_working`，书籍/会话绑定关系也已有 `session-bindings` 查询；问题是当前 `useNovelActivity` 只判断目录内任意会话，没有与当前书绑定列表求交集。

## Goals / Non-Goals

**Goals:**

- 用纯函数统一“绑定会话 × 运行状态”判断。
- 工作台活动指示使用当前书绑定会话。
- 批注执行面板复用同一判断，避免重复逻辑。

**Non-Goals:**

- 不新增服务端接口或修改绑定数据结构。
- 不做跨目录会话聚合。
- 不改变会话启动、取消或审批流程。

## Decisions

### D1: 前端求交集

继续复用 `useBoundNovelSessions` 返回的绑定关系和 `sync().data.session_working`，在纯函数中判断任一绑定会话是否运行。相比新增反向查询端点，这不需要协议、SDK 或服务端改动，并能直接继承查询缓存与实时同步。

### D2: 活动钩子接收会话 ID 列表

`useNovelActivity` 改为接收当前书绑定会话 ID 列表；调用方从已有 `useBoundNovelSessions` 查询传入。这样活动状态随绑定查询和同步状态共同响应。

### D3: 批注面板复用同一纯函数

批注面板已有的本地 busy 判断改为调用同一纯函数，语义与工作台活动状态一致。

## Risks / Trade-offs

- [绑定关系查询短暂加载] → 加载期间按无绑定会话处理，活动为 idle；查询完成后自动更新。
- [同一会话可能被重新绑定] → 绑定查询失效后重新求交集，不缓存书籍归属判断。

## Migration Plan

1. 新增纯函数与单元测试。
2. 工作台改为传入当前书绑定会话 ID。
3. 批注执行面板切换到同一函数。
4. 通过 app 测试、typecheck、根目录质量门验证；无数据迁移，回滚即恢复目录级判断。

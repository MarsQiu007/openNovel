# Proposal

## Why

章节审批栏的「展开审查」目前把 37 维审计详情（9 大类、逐维度 detail/evidence、人工评审记录）以内嵌横条的形式渲染在阅读区与审批按钮之间：全栏宽长行、无独立滚动与高度约束、视觉层级与正文和操作按钮糊在一起，难以阅读；内容足够长时还会挤压阅读区甚至再次触发溢出裁切（与 approval-bar-clip 同类隐患）。审查数据是章节作用域数据，与批注、人物、伏笔同构，而后三者都已有成熟的右栏面板模式，唯独审查详情孤例内嵌。

## What Changes

- 将审批栏内嵌的审查详情（ReviewPanel）抽取为右栏检视面板「审查」，注册进右栏面板体系：图标列入口、与其他面板同层互斥切换、peek/expand 双态。
- 审查面板默认以 expand 态打开（占主内容区，Esc/返回回到 peek），适配 37 维报告的深读场景；结构面板已有同样的默认 expand 先例。
- 审批栏「展开审查/收起」入口改为「审查详情」按钮（硬编码中文标签）：点击激活右栏审查面板（右栏收起时自动展开右栏）；通过/驳回按钮与驳回意见框保持在底部审批栏不动。审批栏既有的「查看审查」按钮（跳转绑定写作会话）名称与语义保持不变，不与新入口混淆。
- 审查面板内容随阅读视图选中章节联动（与批注面板一致），数据仍为 `chapter-reviews` 只读查询——UI 不触发审计执行，查询经 TanStack Query 按章节缓存去重。
- 修改 `novel-workspace-layout` 规格：右栏面板清单与「面板内容跟随章节选中」的需求枚举补充审查面板。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `novel-workspace-layout`: MODIFIED「右栏面板同层互斥切换」（面板清单加入审查）、MODIFIED「面板内容跟随章节选中」（联动枚举加入审查）；ADDED「审查面板承载章节评审详情」。

## Impact

- 受影响包：`packages/app`（`approval-bar.tsx`、`workspace-frame.tsx`，新增审查面板组件；面板标签沿用现有硬编码中文先例，不碰 i18n locale 文件）。
- 无 API / 数据模型 / 依赖变化；`chapter-reviews` 读取接口不变；与现有本地数据完全兼容。

## 非目标

- 不改动审批操作流：通过、驳回、驳回意见框及其「同时让 AI 按驳回意见重写」逻辑全部留在底部审批栏。
- 不改动审计流水线：37 维审计的触发时机与写入逻辑在服务端写作流水线，本次不触碰。
- 不引入中央弹层/模态等第二种浮层模式；审查详情统一走既有右栏面板词汇表。
- 不改动批注面板及其数据模型（annotations 与 reviews 是两张表，本次不合并不联动）。
- 不处理审查面板在写作/关系/地图/画布等其他主区 tab 下的特殊表现（expand 态随主区切换的行为与结构面板现状一致，不做额外约束）。

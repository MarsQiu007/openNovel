# Spec Delta

## ADDED Requirements

### Requirement: 会话时间线展示完整压缩生命周期
会话时间线 SHALL 在原有消息序列中展示压缩排队、运行、完成、失败和中断状态，并保持操作标识稳定；用户 SHALL 能区分自动与手动压缩，并对可操作的排队、失败和中断状态采取相应行动。

#### Scenario: 手动压缩正在排队
- **WHEN** 活跃会话接纳手动压缩但尚未到达安全边界
- **THEN** 时间线显示“排队中”及将在安全点执行的说明
- **AND** 提供撤销该排队操作的入口

#### Scenario: 自动压缩正在生成摘要
- **WHEN** 达到阈值的自动压缩进入运行态并持续产生摘要增量
- **THEN** 时间线显示“正在压缩”、自动触发原因和当前摘要进度
- **AND** 提供停止入口且不把该操作显示为已完成

#### Scenario: 压缩成功完成
- **WHEN** 压缩进入完成态
- **THEN** 时间线显示上下文已压缩的分隔状态和可展开摘要
- **AND** 有可用指标时展示压缩前后 token 估算与摘要成本

#### Scenario: 压缩失败
- **WHEN** 压缩进入失败态
- **THEN** 时间线以警示层级显示安全的失败原因
- **AND** 提供重试入口且完整错误说明可阅读

#### Scenario: 压缩被停止或由进程恢复结算
- **WHEN** 压缩进入中断态
- **THEN** 时间线区分用户停止与进程中断
- **AND** 对可重试操作提供重试入口

#### Scenario: 刷新或切换会话后返回
- **WHEN** 用户刷新界面或离开会话后重新进入
- **THEN** 时间线按持久化状态恢复压缩卡片
- **AND** 运行中操作不会因瞬时摘要增量缺失而显示为完成

### Requirement: 上下文用量展示统一水位与触发阈值
会话上下文用量控件 SHALL 使用服务端提供的统一水位显示当前用量、配置阈值与实际安全触发点，并在后台摘要准备或正式压缩期间呈现相应状态。

#### Scenario: 浏览正常会话用量
- **WHEN** 当前模型窗口已知且水位可计算
- **THEN** 用量控件显示当前 token 估算、窗口百分比和自动压缩阈值
- **AND** 显示值与后端实际触发决策使用同一水位

#### Scenario: 配置阈值受输出空间约束
- **WHEN** 实际安全触发点早于用户配置百分比
- **THEN** 用量控件能够说明实际触发点受安全余量约束
- **AND** 不只显示一个会误导用户等待的配置百分比

#### Scenario: 后台摘要正在准备
- **WHEN** 候选摘要正在后台生成但尚未应用
- **THEN** 用量控件显示正在准备摘要的非阻塞状态
- **AND** 时间线不提前显示压缩完成

#### Scenario: 正式压缩正在执行
- **WHEN** 压缩操作进入排队或运行态
- **THEN** 用量控件与时间线显示同一操作状态
- **AND** 不出现圆环仍在压缩而时间线已经完成的矛盾状态

#### Scenario: 模型窗口未知
- **WHEN** 当前模型没有可用上下文窗口
- **THEN** 用量控件说明暂时无法计算百分比阈值
- **AND** 不显示伪造的百分比或保证不会溢出

### Requirement: 压缩状态更新保持会话阅读与操作稳定
压缩状态卡 SHALL 复用稳定的消息身份和现有时间线内容轴；状态转换、摘要增量和重连恢复 MUST NOT 造成重复消息、跨消息串写或不可接受的滚动跳变。

#### Scenario: 连续接收摘要增量
- **WHEN** 运行中压缩连续收到多个摘要增量
- **THEN** 所有增量只更新所属压缩卡片
- **AND** 不新增重复压缩消息或覆盖相邻助手正文

#### Scenario: 长会话中加载历史并更新压缩状态
- **WHEN** 用户向上加载历史或停留在会话中部时压缩状态发生变化
- **THEN** 虚拟滚动和阅读锚定保持既有行为
- **AND** 状态卡高度变化不造成不可接受的位置跳变

#### Scenario: 使用键盘操作压缩卡片
- **WHEN** 用户通过键盘展开摘要、撤销排队、停止运行或重试失败
- **THEN** 操作控件可达且焦点清晰可见
- **AND** 操作后焦点不会因整张卡片被替换而无故丢失

#### Scenario: 切换语言与主题
- **WHEN** 用户切换既有界面语言或明暗主题
- **THEN** 压缩状态、阈值说明与操作文案遵循当前语言且默认简体中文
- **AND** 各状态保持可辨认并不依赖固定单一主题颜色

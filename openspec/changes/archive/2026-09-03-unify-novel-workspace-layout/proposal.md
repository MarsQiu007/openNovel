# 提案：统一小说工作台布局与导航

## Why

绑定写作会话目前存在两个宿主（工作台内嵌模式 / openCode 独立会话视图），且"进入对话"有 5 个入口（工作台写作按钮、sessions 页最近列表、小说分组侧栏、会话内小说面板、命令面板），行为不一致：同一会话从不同入口进入，可见的书籍上下文（章节、审批流、流水线状态）完全不同。同时工作台内部有三套面板切换机制并存（左栏分段器、主区 tab、右栏 tab），"人物"面板存在两处入口，角色/关系/地图/画布走全宽分支时左右栏瞬移消失。用户在"对话"与"书籍内容"之间来回切换的成本高、上下文易丢失。

## What Changes

- **路由收敛**：绑定会话只有一个家——书籍工作台。所有入口打开绑定会话统一路由到 `/novel/:novelID` 的写作视图（携带会话状态），不再落入独立会话视图；独立会话视图仅保留给未绑定书的自由会话。
- **工作台布局按"位置即语义"统一为四层**：左栏 = 导航（章节/大纲/设定三分段常驻，不再随主区模式消失）；主区 = 焦点（阅读/编辑/关系/地图/面板展开态）；右栏 = 随行区（对话常驻 + 仪表盘面板）。
- **右栏重构为"图标列 + 面板区"**：对话、人物、伏笔、张力、结构、批注六个面板同层图标互斥切换；消除"人物"双入口。
- **面板 peek → expand 双态**：面板默认以 peek（右栏面板区）呈现；一键展开为 expand（主区焦点视图，即现有全宽视图的正式化）；Esc/返回回到 peek 态，右栏恢复之前的面板。各面板默认深度有初值，展开状态持久化。
- **沉浸型视图自动收边**：进入 expand 态时左右栏动画收起（替代现有瞬移），对话收为窄条呼吸灯（生成中可见）；窄屏下伴随型视图自动收左栏。
- **面板内容跟随主区选中**（Inspector 模式）：阅读视图停留的章节变化时，人物/批注等面板自动切换到该章相关内容。
- **布局状态持久化**：右栏活动面板、面板展开状态、左栏收起态沿用现有 persist 机制记忆；分栏宽度为固定值，不做可调节设计。

## Capabilities

### New Capabilities

- `novel-workspace-layout`: 书籍工作台的统一布局与导航行为——绑定会话的单一宿主与入口收敛、四层布局职责、右栏图标列与面板 peek/expand 双态、面板与主区的选中联动、布局状态持久化。

### Modified Capabilities

（无——现有 specs 均为发布流程与写作技法相关，不含 UI 布局行为要求。）

## Impact

- **packages/app**：主要改动包。涉及 `pages/novel/workspace-frame.tsx`（布局重构）、`pages/novel-sessions.ts` 与 `pages/sessions-novel-sidebar.tsx`（入口路由收敛）、`pages/session-novel-panel.tsx`、`components/command-palette.ts`（命令面板入口收敛）、`app.tsx`（路由调整）。
- **packages/desktop**：无改动预期（纯 Web 层 UI 变更，桌面壳自动受益）。
- **后端与契约**：不涉及 Protocol / Server HttpApi 变更，无需在 packages/client 重新生成 SDK。
- **数据兼容性**：纯 UI 层改动，不涉及数据模型、角色生命周期、审计维度；本地数据零迁移。布局状态沿用现有 `Persist` 本地持久化，无新存储字段。

# Proposal: setting-review-hub

## Why

小说写到几十章后，设定与结构信息是一份持续生长、需要长期维护的知识库，但现状只有「写作时捕获」、没有「持续维护」闭环：observer 每章自动提取的新信息按重要度分流——重要内容直接入库，次要内容与冲突标注分别落入候选区（`pending_settings`）与冲突表（`world_entry_conflicts`），而写了几十章后**这些积压没有任何界面可看、可审、可处理**——冲突表甚至「只写不读」，除章节提交时的一次性计数展示外，全仓没有任何读取或处理通路。设定整理需要先到设定中心手动点击、再去会话里逐次确认，AI 批处理的成果没有「成果页」沉淀；结构检查与卷末复盘也全靠人工想起。用户诉求：给 AI 一句指令就能自动完成设定与结构的持续维护，自己在成果页上用批注或直接修改完成把关。

## What Changes

- **设定收件箱**：把三类待审信息聚合为统一队列——observer 候选（既有 `pending_settings`）、世界观冲突（既有 `world_entry_conflicts`）、AI 批处理产出的暂存变更（新增轻量载体）；在设定中心提供可见入口（数量徽标、来源分组、按小说隔离）。
- **成果审阅页**：逐条查看证据（来源章节、旧值/新值对照、冲突说明），支持接受 / 拒绝 / 合并 / 编辑后接受 / 审阅备注与批量操作；备注可「交给 AI 处理」（作为指令发回绑定会话）。
- **冲突闭环补全**：提供冲突的读取与处理通路（按正文更新条目生成草案 / 保留现状并忽略），处理结果可追溯；历史候选与未解决冲突在收件箱直接可见。
- **指令驱动批处理**：用户在会话中下达「整理设定 / 检查设定 / 处理待审」类指令后，AI 以批处理方式扫描既有设定并产出待审变更；不再要求先手动点击面板入口（面板入口保留）。
- **分级自动化**：低风险、可回滚的机械修复（首版：纯格式修复与分类归一，不改变标题）在批处理中自动落库并写入修改历史；语义类变更（合并、删除、内容改写、标题变更、影响下游）必须进入收件箱，经用户确认后执行。
- **契约与界面**：新增收件箱聚合查询、条目操作与冲突处理的服务端端点；Protocol 契约变更，`packages/client` 重新生成 SDK。

## 非目标

- 不做周期巡检节拍（卷末/每 N 章自动生成「设定+结构体检报告」）——留作后续独立变更；本变更只提供「暂存变更」通用载体作为其扩展点。
- 不做知识库图谱/关系可视化与跨实体查询面板——后续独立变更。
- 不做结构规划自动回写（规划与实际偏差的自动修正）。
- 不引入图数据库、向量库，不建立第二套设定存储；候选与冲突继续使用既有表，不做数据搬迁。
- 不改动会话内既有整理路径（`organize_settings` 的 analyze / dry_run / apply 与运行时确认）、影响任务门禁、章节审批与 37 维审计的既有行为。
- 不自动处理需要生成式改写的章节侧任务（仍交由修订流程）。

## Capabilities

### New Capabilities

- `setting-review-hub`：设定/结构信息持续维护的统一待审队列与成果审阅契约——来源聚合（候选 / 冲突 / 暂存变更）、审阅操作语义（接受 / 拒绝 / 合并 / 编辑 / 备注）、分级自动化策略、指令驱动批处理的产出落点与执行留痕。

### Modified Capabilities

- `setting-organization-ui`：修订「UI 不提供直接执行路径」相关需求——保留对任意计划导入与未经校验执行的禁止，新增受控审阅路径（AI 整理产出进入收件箱；成果审阅页对经服务端重校验的暂存变更逐条确认执行）。
- `setting-reorganization`：为低风险白名单的自动执行补充语义（白名单内机械修复可由批处理自动执行并留痕），并明确暂存变更的执行复用既有计划校验。

## Impact

- **packages/novel-store**：新增暂存变更表（本变更唯一新持久化层级）与冲突处理的补充字段；共享常量与类型；既有数据零迁移（新列带安全默认）。
- **packages/plugin**：共享服务（批处理编排、分级自动化白名单、冲突读取/处理、暂存变更读写）、整理分析产出接入暂存、director 提示词编排、新增冲突工具。
- **packages/server / packages/opennovel**：沿用既有 setting-organization 分层（plugin 共享逻辑 → server 服务契约 → opennovel 实现与端点）新增收件箱服务与端点。
- **packages/schema / packages/protocol / packages/client**：新增端点类型与契约，`packages/client` 运行 `bun run generate`（禁止手改生成物）。
- **packages/app**：设定中心新增收件箱入口与成果审阅页（列表、详情、操作、备注、批量操作）。
- **packages/desktop**：无独立改动（随 app 生效）。
- **兼容性**：旧本地数据直接可用——历史候选与未解决冲突进入收件箱可读可处理；新增表/列安全默认、无数据迁移；回滚只需还原代码（暂存数据残留无害，不影响既有流程）。

# tool-insight-log (Delta)

## Modified Requirements

### Requirement: 本地日志开关与目录

系统 SHALL 将「是否启用工具改进日志」和「日志目录」保存为独立全局设置，并在处理事件及后台任务下一步前读取当前值。仅修改这两项设置 MUST 无需重开项目即可生效，且 MUST NOT 改变任何项目的插件加载范围。开关 MUST 默认关闭；未配置目录时 MUST 使用项目自评价目录下的独立子目录，共享目录 MUST 按项目隔离。关闭时 MUST NOT 新增本能力证据、归因模型请求或自动复测，且不得影响既有自评价功能。项目隔离哈希 MUST 对项目目录做路径规范化（统一分隔符），同一目录无论以正斜杠或反斜杠形式传入 MUST 产生相同的日志根。

#### Scenario: 默认不启用

- **WHEN** 用户从未配置工具改进日志并发生工具失败
- **THEN** 系统不新增本能力证据、不发起归因模型请求，既有指标与自评价报告仍按原行为运行

#### Scenario: 多项目共享日志目录

- **WHEN** 两个项目配置同一个日志根目录并分别产生问题
- **THEN** 两个项目的证据和问题记录写入各自隔离的目录，不相互归并

#### Scenario: 同一目录不同分隔符形式

- **WHEN** 同一项目目录分别以 `C:/Novels/adult` 和 `C:\Novels\adult` 形式传入日志根解析
- **THEN** 两者产生相同的项目隔离 slug，证据和问题记录写入同一个日志根

#### Scenario: 运行中仅保存工具洞察设置

- **WHEN** 用户在已打开项目中仅修改工具改进日志开关或目录
- **THEN** 新设置无需重开项目即可生效，当前项目实例与各项目插件加载范围保持不变

#### Scenario: 目录变化时旧目录仍有待整理证据

- **WHEN** 用户修改日志目录时，旧目录仍保存证据或排队整理任务
- **THEN** 新证据使用新目录，旧目录文件保持不删不改，旧队列停止且不自动迁移或写入新目录

#### Scenario: 运行中关闭开关

- **WHEN** 用户在已打开项目中关闭工具改进日志，随后发生工具失败或后台任务准备进入下一步
- **THEN** 系统不新增证据或模型请求，停止派生后续后台工作并保留既有文件，既有自评价功能不受影响

#### Scenario: 关闭或卸载时仍有活动后台任务

- **WHEN** 用户关闭开关或卸载项目时，归因或复测后台会话仍在执行
- **THEN** 系统中断实际后台执行而不只是停止等待，已保存证据和最后完整问题记录保持可用

#### Scenario: 全局配置暂时不可读

- **WHEN** 系统处理事件时无法读取或解析全局设置
- **THEN** 本次按未启用处理并给出非阻断警告，不使用过期配置继续采集

### Requirement: 稳定指纹归并与索引

系统 SHALL 根据工具、错误类别和操作场景等稳定事实生成问题指纹。相同指纹的新证据 MUST 更新同一问题记录的出现次数、时间、影响版本和证据索引，并维护可读总索引，MUST NOT 因措辞变化重复建档。错误类别词汇演进时，新类别问题文档首次登记且同工具、同场景的旧机制指纹文档实际存在时，SHALL 在新文档登记旧指纹作为历史溯源标注，旧文档保持不变，MUST NOT 自动归并或重定向。证据 MUST 使用跨重启不重复的稳定标识，归并 MUST 按该标识去重；出现次数 MUST 按独立稳定的发生实例标识计算，同一实例的多条证据不得重复计数。同一逻辑检测的不同证据类型（如 real_state 与 trajectory 对应同一 surface_success 检测）MUST 使用相同的指纹输入（包含相同的 fact 值），同一逻辑问题 MUST NOT 因证据类型不同而分裂为多个 issue 文档。

#### Scenario: 同一问题重复发生

- **WHEN** 同一工具在不同会话中以相同错误类别和操作场景再次失败
- **THEN** 系统更新原问题记录并增加出现次数和证据引用，不创建重复问题文件

#### Scenario: 一次发生产生多条证据

- **WHEN** 同一次工具失败同时生成过程、错误和真实结果三条证据
- **THEN** 三条证据都可被问题记录引用，但出现次数只增加一次

#### Scenario: surface_success 不同证据类型归入同一指纹

- **WHEN** 一次工具调用返回成功但真实状态核验失败，系统分别生成 real_state 证据和 trajectory 证据
- **THEN** 两条证据使用相同的指纹（包含 fact 值），问题文档只创建一个，occurrence_count 累加

#### Scenario: 不同根因候选不得仅凭报错文案合并

- **WHEN** 两次失败的工具或操作场景不同，仅错误文案相似
- **THEN** 系统分别保留问题记录，不因自然语言相似度强行归并

#### Scenario: 两个进程同时写入同一项目日志

- **WHEN** 两个应用进程同时追加证据并整理同一指纹的问题
- **THEN** 文件更新被真实跨进程锁串行化，同一证据不重复计数，并发更新不丢次数，JSONL 与问题索引保持可读

#### Scenario: 重启后继续产生证据

- **WHEN** 应用重启后产生与重启前同指纹的新证据
- **THEN** 新证据不复用历史证据标识，归并结果能区分待整理与已整理证据

#### Scenario: 词表演进后旧文档保留且新文档标注历史指纹

- **WHEN** 错误类别词表切换后，同一工具与场景的失败以新类别首次登记，且旧机制指纹的问题文档已存在
- **THEN** 新问题文档登记旧指纹为历史溯源标注，旧文档保持不变，不自动归并

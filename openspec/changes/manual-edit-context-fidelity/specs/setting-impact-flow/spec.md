## Purpose

把手动 UI 设定修改纳入与 AI 工具相同的影响面闭环，防止界面保存绕过联动任务和引用维护。

## MODIFIED Requirements

### Requirement: 设定修改必须经过统一入口

所有会改变角色、世界观、关系、伏笔、剧情线等正式设定的写入路径，包括 AI 工具、状态提交和手动 UI API，SHALL 复用同一影响面服务。真实修改后，调用方可获得影响摘要或可查询的同步状态；系统 SHALL 生成影响任务或明确的待同步记录。任何路径 SHALL NOT 在绕过影响任务生成的情况下直接修改正式设定。

#### Scenario: 工具更新角色

- **WHEN** AI 通过角色管理工具修改既有角色名称或描述
- **THEN** 工具返回影响摘要和待处理任务数量
- **AND** 受影响章节或设定生成可追踪任务

#### Scenario: 工具更新世界观

- **WHEN** AI 修改世界观条目的标题或关键内容
- **THEN** 工具返回影响摘要
- **AND** 引用该条目的章节、摘要或其他设定生成任务

#### Scenario: UI 更新角色

- **WHEN** 用户在工作台手动修改角色名称、描述或生命周期状态
- **THEN** 系统保存角色后生成同一模型的影响任务或可查询同步记录
- **AND** AI 后续写作可以查询到该设定变更及其处理状态

#### Scenario: UI 更新世界观

- **WHEN** 用户在设定阅读器手动修改世界观标题、分类或关键内容
- **THEN** 系统重建或排队重建引用关系
- **AND** 引用旧标题或旧定义的章节、摘要和其他设定生成联动任务

#### Scenario: 状态提交引入设定变化

- **WHEN** observer 状态提交更新既有角色、关系或剧情设定
- **THEN** 状态提交也生成统一影响任务，而不是只写入物化视图

# Spec Delta

## Purpose

为长会话提供稳定、可配置且可恢复的上下文压缩能力，使系统能够在 provider 拒绝请求前依据统一水位主动压缩，并让用户在会话中追踪排队、执行、完成、失败与中断的完整过程。

## ADDED Requirements

### Requirement: 上下文水位使用实测锚点与未测量后缀
系统 SHALL 使用与当前 provider、模型和变体匹配的最近一次 assistant usage 作为实测锚点，并叠加锚点之后尚未被 provider 计量的内容估算当前水位。系统 MUST NOT 跨不匹配模型复用实测锚点。

#### Scenario: 锚点后出现新工具结果
- **WHEN** 最近一次匹配 assistant 已记录 usage，且其后新增了工具结果或用户输入
- **THEN** 当前水位包含该 assistant 的输入、缓存、输出与推理 token，并包含后续内容的估算值
- **AND** 水位来源标记为实测与估算混合

#### Scenario: 会话切换模型
- **WHEN** 当前模型或变体与最近一条带 usage 的 assistant 不匹配
- **THEN** 系统不使用该 assistant 的实测值代表当前模型水位
- **AND** 系统重新估算当前完整请求，直到取得新的匹配锚点

#### Scenario: 请求上下文发生不兼容变化
- **WHEN** agent、系统上下文或工具定义变化使最近一次 usage 不再代表当前请求前缀
- **THEN** 该实测锚点失效
- **AND** 系统使用当前请求的保守估算

### Requirement: 无实测数据时采用保守估算
系统 SHALL 在没有可靠实测锚点时保守估算完整请求；对中文等非 ASCII 内容 MUST NOT 继续把统一的每 4 字符 1 token 作为唯一估算依据。

#### Scenario: 中文长会话尚无 assistant usage
- **WHEN** 一个接近配置阈值的中文会话首次准备请求 provider
- **THEN** 系统使用不会仅因中文字符密度而明显低估的估算水位
- **AND** 达到阈值时先执行压缩，而不是等待 provider 溢出

#### Scenario: 取得首个匹配实测锚点
- **WHEN** provider 返回当前模型的 assistant usage
- **THEN** 后续水位以该实测值替代旧估算锚点
- **AND** 只继续估算锚点之后的新增内容

### Requirement: 客户端与自动压缩共享同一水位
系统 SHALL 向自动压缩决策和客户端提供相同的派生水位、模型窗口、配置阈值与实际触发点，并支持初始读取、更新和重连恢复。

#### Scenario: 客户端首次打开会话
- **WHEN** 客户端读取一个已有消息和 usage 的会话快照
- **THEN** 快照包含与后端自动压缩决策一致的当前水位和触发点
- **AND** 客户端无需自行推导另一套触发值

#### Scenario: 客户端断开后重新连接
- **WHEN** 客户端错过了若干水位刷新通知后重新读取会话
- **THEN** 系统根据当前会话状态返回最新水位
- **AND** 客户端不依赖补收全部瞬时通知才能恢复显示

#### Scenario: 模型上下文窗口未知
- **WHEN** 当前模型没有可用上下文窗口
- **THEN** 系统明确返回无法计算百分比阈值的状态
- **AND** 不伪造百分比或自动触发点

### Requirement: 自动压缩阈值可配置且保留输出空间
系统 SHALL 支持按上下文窗口百分比配置自动压缩阈值，默认在约 85% 时触发；既有固定 token 预留配置 SHALL 保持有效，实际触发点 MUST 为模型输出保留足够空间。

#### Scenario: 使用默认配置
- **WHEN** 用户未设置压缩预留且模型窗口已知
- **THEN** 系统在默认安全预留对应的约 85% 水位自动压缩
- **AND** 小窗口仍保留系统要求的安全余量

#### Scenario: 用户设置自定义百分比
- **WHEN** 用户将自动压缩阈值设置为指定百分比
- **THEN** 后续会话按该百分比与必要输出空间共同确定实际触发点
- **AND** 设置重新读取后保持同一语义

#### Scenario: 用户阈值接近窗口上限
- **WHEN** 用户配置的阈值无法同时容纳模型输出空间
- **THEN** 实际触发点提前到能够保留输出空间的位置
- **AND** 客户端能够区分配置阈值与实际安全触发点

#### Scenario: 读取既有固定预留配置
- **WHEN** 既有配置使用固定 token 数值表示压缩预留
- **THEN** 系统继续按固定 token 解释该值
- **AND** 不在升级后静默改写为百分比

#### Scenario: 关闭自动压缩
- **WHEN** 用户关闭自动压缩
- **THEN** 达到阈值不会自动执行压缩
- **AND** 手动压缩仍然可用

### Requirement: 自动压缩在安全边界继续原始输入
系统 SHALL 在首次 provider 调用及每次 continuation 前检查水位，达到阈值时先压缩并重新加载压缩后的历史，再继续原始输入；系统 MUST NOT 截断半个 assistant 响应或重复接纳原始用户输入。

#### Scenario: 首次 provider 调用前达到阈值
- **WHEN** 一个 durable 用户输入已接纳且当前水位达到阈值
- **THEN** 系统先完成压缩，再基于压缩后的投影历史构建原始 provider 请求
- **AND** 原始用户消息只出现一次

#### Scenario: 工具调用后的 continuation 达到阈值
- **WHEN** 工具结果使下一次 continuation 的水位达到阈值
- **THEN** 系统在当前工具交换的安全边界后执行压缩
- **AND** 后续 continuation 使用包含该工具结果的新历史

#### Scenario: 自动压缩成功
- **WHEN** 压缩操作写入完成终态
- **THEN** 原始输入从压缩后的历史继续一次正常 provider turn
- **AND** 不重复调用压缩前已经完成的 provider turn

#### Scenario: 自动压缩失败
- **WHEN** 当前自动压缩进入失败终态
- **THEN** 本轮不继续发送已判定超过安全边界的原始请求
- **AND** 原始 durable 输入保持可追溯

### Requirement: 手动与自动压缩统一排队和去重
系统 SHALL 将手动压缩接入与自动压缩相同的 Session 安全边界；活跃会话中的手动请求 SHALL 排队，同一 Session 的重复活跃请求 SHALL 复用同一操作。

#### Scenario: 会话正在生成时请求手动压缩
- **WHEN** 用户在一个 assistant 响应仍在生成时执行手动压缩
- **THEN** 系统持久化一个排队操作并立即返回其标识
- **AND** 当前 assistant 响应不被半截改写，压缩在下一安全边界开始

#### Scenario: 会话空闲时请求手动压缩
- **WHEN** 用户在会话空闲时执行手动压缩
- **THEN** 系统接纳排队操作并唤醒该会话
- **AND** 无需等待新的用户 prompt 即可开始压缩

#### Scenario: 重复请求与自动触发同时出现
- **WHEN** 同一 Session 已存在排队或运行中操作时又收到手动或自动请求
- **THEN** 系统复用现有操作
- **AND** 不生成第二份摘要或重复改写历史

#### Scenario: 排队请求落在执行退出窗口
- **WHEN** 排队事件提交时会话 drain 正在退出
- **THEN** 持久化排队操作仍会被后续唤醒处理
- **AND** 不会因瞬时唤醒丢失而永久停留在排队中

### Requirement: 后台摘要只暂存候选且可安全回退
系统 SHALL 支持在接近阈值时预生成并暂存候选摘要；候选 MUST NOT 提前改写会话历史，只有达到压缩条件且候选仍有效时才能应用，否则 SHALL 回退到有界前台压缩。

#### Scenario: 水位接近但尚未达到阈值
- **WHEN** 自动压缩和后台摘要均开启且存在可用的同模型实测锚点
- **THEN** 系统可在后台生成一个候选摘要
- **AND** 当前会话继续运行且可见历史保持不变

#### Scenario: 候选仍然有效
- **WHEN** 达到阈值时候选的消息边界、模型和配置仍匹配且新增尾部在允许预算内
- **THEN** 系统等待或应用该候选
- **AND** 不重复生成同一份摘要

#### Scenario: 候选已经失效
- **WHEN** 会话起点、保留边界、模型、配置或新增尾部使候选不再满足应用条件
- **THEN** 系统丢弃或停止该候选
- **AND** 使用当前历史执行一次有界前台压缩

#### Scenario: 后台摘要关闭
- **WHEN** 用户关闭后台摘要但保留自动压缩
- **THEN** 系统不启动提前摘要请求
- **AND** 达到阈值时仍执行自动压缩

#### Scenario: 后台连续失败
- **WHEN** 同一压缩周期的后台摘要连续失败达到系统上限
- **THEN** 系统停止该周期内新的后台尝试
- **AND** 达到阈值时仍允许一次有界前台压缩

#### Scenario: 候选最终未使用
- **WHEN** 一个后台摘要已经产生 provider usage 但因失效而未应用
- **THEN** 该 usage 仍计入会话成本
- **AND** 系统不创建虚假的压缩完成记录

### Requirement: 压缩生命周期持久化且兼容历史消息
系统 SHALL 持久化排队、运行、完成、失败和中断状态及其转换；实时摘要增量 MAY 为瞬时数据，但刷新或重连后 MUST 恢复真实生命周期。历史无状态压缩消息 SHALL 按完成态兼容读取。

#### Scenario: 完整生命周期后刷新
- **WHEN** 压缩依次经过排队、运行和完成
- **THEN** 每个状态转换都有可追溯记录
- **AND** 刷新后显示完成态及其摘要，而不是重新排队

#### Scenario: 运行中重连
- **WHEN** 客户端在压缩运行中断开并重新连接
- **THEN** 客户端恢复运行中状态
- **AND** 即使瞬时摘要增量无法补收，也不会把该操作伪装成完成

#### Scenario: 失败操作被重试
- **WHEN** 用户从一个失败操作发起重试
- **THEN** 系统创建关联到原失败操作的新排队操作
- **AND** 原失败记录保持可追踪

#### Scenario: 读取旧版本压缩消息
- **WHEN** 历史事件或消息只有旧版完成摘要而没有生命周期状态
- **THEN** 系统将其解码为完成态
- **AND** 不要求批量改写既有本地数据

### Requirement: Provider 溢出识别与恢复有明确边界
系统 SHALL 识别已知 provider 的上下文溢出响应并在 assistant 尚未开始时尝试压缩恢复；系统 MUST NOT 在已有 assistant 输出后原样重发被拒绝的请求，也 MUST NOT 把限流或配额错误当作上下文溢出。

#### Scenario: DashScope 返回输入长度错误
- **WHEN** 自动压缩开启且 DashScope 返回包含 `Range of input length should be` 的 HTTP 400
- **THEN** 系统将该失败分类为上下文溢出
- **AND** assistant 尚未开始时进入一次压缩恢复

#### Scenario: Z.ai 返回提示词过长
- **WHEN** Z.ai 返回 `Prompt too long` 或 `Prompt 超长`
- **THEN** 系统将该失败分类为上下文溢出
- **AND** 按相同安全边界处理恢复

#### Scenario: assistant 已经开始输出
- **WHEN** 一个流式请求已经产生 assistant 输出后失败
- **THEN** 系统不原样重发该 provider 请求
- **AND** 保留已有输出与失败状态

#### Scenario: 限流或配额错误
- **WHEN** provider 返回限流、余额或配额错误
- **THEN** 系统不将其分类为可通过压缩修复的上下文溢出

#### Scenario: 自动压缩关闭时发生溢出
- **WHEN** 自动压缩关闭且 provider 拒绝超长请求
- **THEN** 系统不自动执行溢出压缩
- **AND** 用户仍可显式发起手动压缩

### Requirement: 摘要请求缩减与格式重试必须有界
系统 SHALL 在摘要请求自身溢出时逐级缩小输入，并在摘要为空或不符合要求时进行有限纠错；达到重试上限后 MUST 进入失败终态，不得无限重试。

#### Scenario: 摘要请求连续溢出
- **WHEN** 摘要请求被 provider 判定为上下文溢出
- **THEN** 系统按既定阶梯逐级缩小摘要输入并重试
- **AND** 每次重试的请求规模都不大于前一级

#### Scenario: 所有缩减级别仍失败
- **WHEN** 摘要请求已达到最小缩减级别仍无法成功
- **THEN** 系统将当前压缩标记为失败并返回可操作的失败原因
- **AND** 不在同一原始 turn 中重新启动无限自动压缩

#### Scenario: 摘要结构不符合要求
- **WHEN** provider 返回非空摘要但缺少约定结构
- **THEN** 系统最多要求补正一次
- **AND** 再次不符合要求时将压缩标记为失败

#### Scenario: 摘要为空
- **WHEN** provider 没有产生可用摘要
- **THEN** 系统将压缩标记为失败
- **AND** 不用空摘要替换现有历史

### Requirement: 压缩失败提供脱敏原因且不会形成恢复死循环
系统 SHALL 为失败操作记录用户可理解且不含敏感请求数据的原因，并提供显式重试入口；一次原始 turn MUST 只进行有界自动恢复。

#### Scenario: Provider 拒绝摘要请求
- **WHEN** 摘要生成因 provider 错误进入失败终态
- **THEN** 用户能够看到失败类别和安全错误说明
- **AND** 原始响应体、请求头及凭据不会进入压缩消息

#### Scenario: 自动恢复失败后仍有新活动
- **WHEN** 一次自动压缩失败且用户随后显式重试或发送新输入
- **THEN** 系统依据当时水位创建新的有界操作
- **AND** 不自动重复上一轮已经失败的无限循环

### Requirement: 取消压缩不破坏原始输入或活跃助手输出
系统 SHALL 支持撤销排队操作和停止运行中操作；取消 MUST 保留原始 durable 输入和已完成消息，且不得在取消后继续发送已知超过安全边界的原始请求。

#### Scenario: 撤销排队的手动操作
- **WHEN** 当前会话正在执行其他工作且用户撤销排队压缩
- **THEN** 该压缩操作进入中断态
- **AND** 当前 assistant 工作不因撤销排队压缩而被取消

#### Scenario: 停止运行中的压缩
- **WHEN** 用户停止正在生成摘要的压缩
- **THEN** 该操作进入中断态
- **AND** 原始 durable 输入和已有消息保持有效
- **AND** 系统不紧接着发送已判定超过安全边界的原始请求

### Requirement: 进程恢复只结算遗留操作而不自动重放
系统 SHALL 在进程恢复后将上次遗留的排队或运行中操作幂等结算为中断；系统 MUST NOT 因结算而自动重放摘要或原始 provider 请求。

#### Scenario: 进程在压缩运行中退出
- **WHEN** 新进程发现一个上次运行遗留的运行中操作
- **THEN** 该操作被结算为进程中断
- **AND** 不自动启动新的摘要请求

#### Scenario: 进程在排队操作执行前退出
- **WHEN** 新进程发现一个上次运行遗留的排队操作
- **THEN** 该操作被结算为进程中断
- **AND** 用户可显式重试

#### Scenario: 完成事件已在退出前提交
- **WHEN** 新进程发现压缩完成终态已经持久化
- **THEN** 该操作保持完成且历史从压缩投影继续有效
- **AND** 恢复过程不重复执行压缩

#### Scenario: 重复执行恢复结算
- **WHEN** 同一遗留操作被恢复逻辑再次检查
- **THEN** 不追加重复中断记录或重复压缩消息

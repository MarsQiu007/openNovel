# Proposal

## Why

工作台左右分栏目前被硬编码在左栏 220–400px、右栏 320–560px 的静态边界内，主区保底 720px。在大屏上用户无法把侧栏拉到真正可用的宽度，也无法把主区压成一条窄缝专注侧栏内容；期望的行为是类似 VS Code 的拖拽模型——侧栏没有固定像素上限，唯一硬约束是主区极小的保底宽度（30px），主区在两侧收起时占满全窗口。

## What Changes

- **BREAKING（规格级行为变化，无数据迁移）**：左右分栏的可调上限从静态常量（左 400px / 右 560px）改为随窗口动态派生：上限 = 三区容器宽度 − 主区保底（30px）− 另一侧可见栏宽。
- 主区最小保底从 720px 降为 30px：侧栏可拖到几乎占满窗口，主区最窄到 30px；左右栏手动收起后主区占满全窗口（现有行为保持）。
- 渲染宽度增加动态钳制：持久化的设定宽度超过当前动态上限时，按动态上限显示（设定值保留，窗口变宽后自动恢复完整设定宽度）。
- 窄宽度自动收边阈值推导保持「左栏阈值 = 左栏宽度 + 主区保底；右栏阈值 = 左栏宽度 + 右栏宽度 + 主区保底」的公式，但主区保底取新值 30px；阈值由此仅在极窄窗口下触发，手动展开覆盖规则的语义不变。
- 双击重置默认宽度（左 288px / 右 380px）与拖到最小宽度再收起的交互不变。

## 非目标

- 不引入窗口宽度比例上限（如 ≤40%），保持「唯一约束是主区保底」的 VS Code 语义。
- 不改 expand 态（面板占满主区）行为，不改默认宽度（左 288px / 右 380px）与最小宽度（左 220px / 右 320px）。
- 不改持久化结构 `novel.workspace.layout.v1` 及其版本号，不做数据迁移。
- 不在拖拽过程中响应窗口尺寸变化实时重算上限（松手后下次拖拽生效）。
- 不为 30px 极限态保证主区内容可读性，只保证布局不溢出、不崩溃。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `novel-workspace-layout`：「分栏宽度拖拽调节」的静态边界 SHALL 改为动态派生边界并新增渲染钳制；「窄宽度自动收边」的主区保底从 720px 改为 30px，手动展开时栏宽按动态上限钳制显示。

## Impact

- `packages/app`：`workspace-pane-width.ts`（常量改纯函数、阈值推导）、`workspace-frame.tsx`（三区容器宽度 signal、动态 min/max 下传）、`workspace-pane-width.test.ts`（边界断言重写）。无 API 契约、无数据模型、无其他包受影响。
- 兼容性：`novel.workspace.layout.v1` 持久化结构不变，仅语义收窄——旧数据中的设定宽度全部有效，只在超过动态上限的窗口下被渲染钳制，无需迁移。
- 涉及规格：`openspec/specs/novel-workspace-layout/spec.md` 两条 requirement 的 delta。

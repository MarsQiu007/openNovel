# Spec Delta

## Purpose

为 agent 提供跨压缩、跨重启的长程执行能力：工作进度锚定在持久化工作队列（WorkRun）而非上下文记忆，编排层在 agent 纯文本停机时自动续跑，阀门（续跑上限、无进展熔断、打断挂起）保证停机总是有意义的暂停而非失控消耗。

## ADDED Requirements

### Requirement: 持久化工作队列

会话 SHALL 支持创建会话绑定的持久化工作队列（WorkRun），用于承载长程工作的工作目标、单元清单与进度记录。队列与单元状态 MUST 持久化于本地数据库，在会话压缩后与进程重启后均可完整读取，不依赖上下文记忆。队列 MUST 严格绑定单一会话，不跨会话共享。队列具备活动（active）、挂起（paused）、完成（complete）状态；单元具备待处理（pending）、进行中（in_progress）、完成（done）、跳过（skipped）、受阻（blocked）状态。

#### Scenario: 创建工作队列

- **WHEN** 模型经工具声明一个含工作目标与若干单元的工作队列
- **THEN** 队列（active）与全部单元（初始为待处理）被持久化，并在同会话后续任意时刻可读取

#### Scenario: 压缩后进度不丢

- **WHEN** 会话发生上下文压缩
- **THEN** 工作队列的单元清单与各单元状态、进度笔记仍可完整读取

#### Scenario: 重启后进度不丢

- **WHEN** 应用进程重启后用户回到该会话
- **THEN** 未完结的工作队列仍存在且状态完整，用户可显式恢复续跑

### Requirement: 队列单元推进

模型 SHALL 经工具推进队列单元：将单元标记为进行中（领取）、标记为完成、标记为跳过或受阻，并写入面向下一回合的进度笔记。单元状态 MUST 单调收敛（待处理 → 进行中 → 完成/跳过/受阻），受阻单元 MUST 能被重置为待处理（经模型恢复指令或用户恢复流程），进度笔记 MUST 覆盖式更新而非累积重复。

#### Scenario: 领取下一单元

- **WHEN** 模型开始处理队列中某个待处理单元
- **THEN** 该单元转为进行中，队列其他单元状态不变

#### Scenario: 完成单元并记录进度

- **WHEN** 模型完成当前进行中单元并写入进度笔记
- **THEN** 该单元转为完成，笔记内容可被下一回合读取

#### Scenario: 单元受阻与重置

- **WHEN** 模型因前置条件缺失将某单元标记受阻，随后前置条件恢复
- **THEN** 该单元先转为受阻并附原因，之后能被重置为待处理继续处理，队列整体不因单个受阻单元终止

### Requirement: 纯文本停机守卫

当 agent 以纯文本正常结束回合（无工具调用，回合非 provider 失败结算）且该会话存在活动工作队列、队列中存在待处理或进行中单元时，编排层 SHALL 合成一条续跑入站指令投回该会话（queue 投递形态），指示模型继续处理队列中下一单元；指令 MUST 作为正常入站消息对用户可见，续跑提升时正常重置回合步数配额。队列不存在、队列挂起、队列无待处理与进行中单元（全部完成、跳过或受阻）、本回合为 provider 失败结算、或阀门触发（见安全阀）时，守卫 MUST 放行停机。守卫 MUST NOT 为普通无队列会话引入任何额外行为或开销。

#### Scenario: 队列非空时停机被续跑

- **WHEN** agent 在存在待处理或进行中单元的活动队列下以纯文本结束回合
- **THEN** 一条续跑指令被投回会话并在队列边界提升，agent 无需用户介入即继续下一单元

#### Scenario: 队列无可执行单元时放行

- **WHEN** agent 以纯文本结束回合且队列无待处理与进行中单元（全部完成、跳过或受阻）
- **THEN** 会话正常停机，最终汇报对用户可见，无续跑指令

#### Scenario: 无队列会话不受影响

- **WHEN** 无工作队列的普通会话以纯文本结束回合
- **THEN** 行为与本能力引入前完全一致

#### Scenario: provider 失败回合不续跑

- **WHEN** 回合因 provider 失败结算结束（非模型正常纯文本结束）
- **THEN** 守卫不合成续跑指令，不因连续 provider 失败重复投递

#### Scenario: 步数到限回合照常续跑

- **WHEN** 回合因步数上限触发强制总结并以纯文本结束，且队列仍有待处理或进行中单元
- **THEN** 守卫照常合成续跑指令，agent 继续处理队列而非每段停机等待用户

#### Scenario: 续跑对用户可见

- **WHEN** 守卫合成续跑指令并投回会话
- **THEN** 该指令以入站消息形态出现在会话记录中，用户可分辨 agent 为自动续跑而非自行发起新对话

### Requirement: 提示词契约

会话存在活动工作队列时，系统提示词 SHALL 注入两条约束：禁止以纯文本结束回合（须继续处理队列），以及复述要求——每回合经工具更新队列进度，使进度锚点常驻上下文近端并常态化保存进度（步数到限回合禁用工具，无法临时写入进度，常态复述是进度的持久保障）。队列挂起或终结后注入 MUST 停止，不污染后续普通对话。

#### Scenario: 活动队列注入约束

- **WHEN** 会话存在活动（active）工作队列
- **THEN** 该会话的系统提示词包含禁纯文本停机与复述更新两条约束

#### Scenario: 队列挂起或终结后停止注入

- **WHEN** 工作队列转为挂起或全部单元终结
- **THEN** 系统提示词不再包含上述约束，后续对话不受影响

### Requirement: 守卫安全阀

用户打断会话时，工作队列 MUST 转为挂起而非作废。用户 SHALL 能经界面或对话显式恢复挂起的队列继续执行，恢复时守卫续跑计数重置。步数上限触发的强制总结回合 MUST NOT 作为守卫停机点。守卫续跑 SHALL 受两道阀门约束：单条队列的连续守卫续跑次数达到可配置上限时，队列 MUST 转为挂起并放行停机；连续多次守卫续跑期间队列无任何单元状态变化时，队列 MUST 同样转为挂起并放行停机。

#### Scenario: 步数到限不停机

- **WHEN** 到限强制总结回合结束且队列仍有可执行单元
- **THEN** 守卫照常续跑，回合步数配额随续跑提升重置，长队列不因到限反复停机

#### Scenario: 续跑超限转挂起

- **WHEN** 单条队列的连续守卫续跑次数达到可配置上限
- **THEN** 队列转为挂起、守卫放行停机，用户恢复后续跑计数重置

#### Scenario: 无进展熔断

- **WHEN** 连续多次守卫续跑期间队列无任何单元状态变化
- **THEN** 队列转为挂起、守卫放行停机，避免对无法推进的工作重复消耗

#### Scenario: 用户打断挂起

- **WHEN** 用户在队列执行中打断会话
- **THEN** 队列转为挂起，单元状态与进度笔记保留，无续跑指令

#### Scenario: 用户显式恢复

- **WHEN** 用户对挂起队列发起恢复
- **THEN** 一条恢复指令投回会话，队列回到活动状态且续跑计数重置，agent 从进度笔记记录的位置继续处理剩余单元

### Requirement: 工作队列可见性与操作

系统 SHALL 提供查询当前会话工作队列状态与单元进度的协议端点；app 会话面板 SHALL 展示队列目标、单元清单与实时进度，并提供挂起与恢复操作。

#### Scenario: 面板展示队列进度

- **WHEN** 会话存在工作队列
- **THEN** 会话面板显示队列目标、各单元状态与进度笔记，随推进实时更新

#### Scenario: 用户经面板挂起

- **WHEN** 用户在会话面板点击挂起
- **THEN** 队列转为挂起，agent 在当前单元完成后停机，无续跑指令

### Requirement: 逐章审查消费者

全书逐章审查场景 SHALL 经工作队列承载：系统识别「审查全书/逐章审查」类请求后，为全书未完结章节逐章声明审查单元，并逐章执行审查、修改与进度记录。执行中途被打断或阀门触发后，进度 MUST 可从队列恢复，已审查章节 MUST NOT 重复执行。

#### Scenario: 请求全书逐章审查

- **WHEN** 用户请求审查全书且该书有多章未审查
- **THEN** 系统创建工作队列并为每章声明一个审查单元，逐章推进执行

#### Scenario: 中断后恢复不重复

- **WHEN** 逐章审查在第 k 章被打断（用户打断或阀门触发）后经用户恢复
- **THEN** agent 从第 k 章续跑，已完成的 1..k-1 章不重复执行

#### Scenario: 审查完成汇报

- **WHEN** 全部章节单元完成
- **THEN** 队列终结，agent 产出全书审查总结，守卫放行停机

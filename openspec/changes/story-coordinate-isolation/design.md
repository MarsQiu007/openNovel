## Context

上下文快照（`context.ts`）在"最近章节摘要""早期章节段摘要""召回历史""结构线/弧光"中大量使用 `第N章` 前缀。writer 提示词禁止了 Markdown、提纲标签和编号分段，但没有禁止控制层坐标进入叙事。auditor 没有专项检查维度。observer 时间线示例允许 `timestamp` 使用"第X章"，历史状态数据可能已含该格式。见 proposal.md 了解动机。

## Goals / Non-Goals

**Goals:**
- writer/reviser 提示词硬规则隔离控制层坐标
- 快照渲染降低"第N章"与叙事句混写的诱因
- auditor 新增"书籍坐标泄漏"检查维度
- observer 时间线 `timestamp` 只保存故事时间
- 历史数据中已有的"第X章"格式在渲染时兼容处理

**Non-Goals:**
- 不修改数据库 schema（不动 `timestamp` 列类型或新增迁移）
- 不修改 Protocol/HttpApi（无需 SDK 再生成）
- 不改动 37 维审计的整体架构，只在现有维度体系中新增一个检查点
- 不处理用户反馈泄漏（已由 writing-feedback-intent 覆盖）

## Decisions

### 1. 快照渲染：章节锚点改为独立标注行而非移除

**选择**：将"第N章 摘要标题：内容"改为"剧情概要为主体的渲染 + 独立的控制层标注（如 `[内部参照: 章9]`）"。

**理由**：auditor 需要完整章节锚点做连续性审计，writer 需要事件因果顺序而非章节号。把锚点从叙事句中拆出，writer 更容易只消费剧情记忆。如果直接移除锚点，auditor 的上下文组装需要另走一条路径或保留两个渲染版本。

**替代方案**：为 writer 和 auditor 分别构建两套快照（writer 不含章节号，auditor 含完整锚点）。这会让 `buildSnapshot` 变成两个分支，维护成本翻倍，且大部分内容重叠。当前方案通过同一份渲染降低复述概率，同时让 auditor 继续可见锚点，代价更低。

### 2. writer 提示词：在现有"正文纯净"规则后追加坐标隔离条目

**选择**：在 writer.ts 现有规则列表（第 72 行附近）追加一条编号规则，明确列出禁止的控制层坐标词和推荐的故事层替代表达。reviser.ts 同步添加。

**理由**：writer 现有规则按编号排列，追加最简单。不重构规则结构。

### 3. auditor 检查维度：作为文风/细节类的新检查点注入提示词

**选择**：在 auditor 提示词的维度列表中新增"书籍坐标泄漏"检查点，要求 auditor 判断正文是否把控制层坐标当作叙事记忆使用，并同时给出合法场景的排除条件。

**理由**：auditor 是 LLM 调用，由提示词驱动检查。机械正则拦截会大量误报（合法的"章"字场景太多），LLM 检查可以区分上下文。

**替代方案**：在 `detectOutlineLabels` 中新增正则。正则可以拦截明确的"记得在第九章"句式，但无法区分"他翻开那本书第五章"等合法场景。可以考虑 LLM 检查为主 + 可选的正则兜底作为补充信号。

### 4. observer 时间线：修改示例和字段说明

**选择**：修改 observer.ts 第 176 行的提示词示例，将 `timestamp` 的示例从"第X章"改为故事层时间表达，并明确说明章节锚点通过 `relative_order` 或章节 ID 承载。

**理由**：`timestamp` 字段已有数据继续保留原值，不做迁移。新提取的数据遵循新规则。上下文组装在渲染事件时间线时对"第X章"格式做过滤或转写。

### 5. 历史数据兼容：渲染层过滤而非数据迁移

**选择**：在上下文组装渲染事件时间线时检测 `timestamp` 是否匹配"第X章"模式，如果是则不将该字段作为故事时间输出，以故事层时间或事件顺序替代。

**理由**：不做数据迁移可以避免 schema 变更和存量数据风险。渲染层过滤是幂等操作，不改变底层存储。

## Risks / Trade-offs

- [LLM 坐标检查误报合法的"章"字用法] → 提示词中给出正反例（泄漏 vs 书中书），auditor 结果需有人工确认闸门兜底
- [渲染层过滤"第X章"可能误滤真实故事时间] → 过滤条件限定为 `第N章` 精确模式（N 为数字），不匹配"第五章开头写的"等变体
- [writer 新增硬规则可能与现有规则冲突] → 追加条目明确说明优先级：正文纯净 + 坐标隔离同属最高优先级，互不冲突
- [历史数据中的"第X章"格式短期内仍存在于数据库] → 渲染层过滤保证不泄漏到 writer 输入；后续可择机批量清理

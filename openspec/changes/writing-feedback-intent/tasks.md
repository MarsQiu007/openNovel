## 1. 反馈意图协议

- [x] 1.1 在 pipeline 与 director（含 director 直接派发 `writer`）提示词中定义结构化写作反馈意图字段（意图编号、反馈编号、意图类型、目标引用、禁止断言、期望状态、保留内容、允许正文否定、原始反馈、澄清问题），并用 prompt 断言测试验证字段完整
- [x] 1.2 在 pipeline 与 director 提示词中加入删除、替换、后续约束、剧情事实和模糊反馈五类转换规则，明确按初次生成、修订和目标断言是否存在选择意图类型，并用“不要 X”“把 X 改成 Y”“他没有带伞”等示例测试验证
- [x] 1.3 定义一次反馈包含多条意图的处理规则，要求每条意图有唯一编号且能追溯共同反馈编号，明确模糊意图只阻断依赖或冲突的意图，并用测试验证无关明确意图不因模糊项被合并或丢弃
- [x] 1.4 定义原始反馈的追溯方式与禁止正文复述控制层语言的规则，并用测试验证调度内容、反馈报告字段和正文隔离要求同时存在

## 2. 生成与修订路径接入

- [x] 2.1 更新初次生成路径，使 director 保留并传递用户原始生成约束，pipeline 或 director 在派发 `writer` 前编译为结构化反馈意图；`write_chapter` 拒绝后的 writer 重试必须保留同一意图块，并用 prompt 测试验证 `writer` 输入包含控制层隔离说明
- [x] 2.2 更新驳回后重写路径，使 pipeline 基于旧章节和用户批注构造修订意图，把意图连同旧正文传给 reviser，并把同一意图摘要传给后续 auditor，用 prompt 测试验证不直接派发原始批注
- [x] 2.3 更新 director 直接修订路径，使其保留用户原话、先编译反馈意图，并把意图摘要传给 auditor 和 reviser，用 prompt 测试验证原话不被转述替代
- [x] 2.4 为 `unclear` 反馈定义澄清返回行为，禁止调度方猜测派发生成或修订；澄清结果包含具体问题，`unclear` 项不进入 writer / reviser 执行块，且只阻断依赖或冲突的意图

## 3. 执行者故事层协议

- [x] 3.1 更新 writer 提示词，要求纠正型否定转为删除、替换或后续约束，并禁止把用户指令写成旁白或元否定，用 prompt 测试验证关键规则存在
- [x] 3.2 更新 reviser 提示词，要求根据目标引用定位受影响断言再做最小修订并保留无关内容，用固定夹具测试修订指令要求移除“心情很低落”且禁止“心情不会很低落”这类元否定
- [x] 3.3 为显式允许正文否定定义统一条件，要求执行者对照 `允许正文否定` 字段处理明确剧情事实和用户明确要求的否定替换，并用正反示例测试

## 4. 审计与回归防护

- [x] 4.1 更新 auditor 输入与检查规则，使其接收反馈意图摘要；存在反馈但缺少意图时报告缺少反馈上下文，无反馈时不因缺少意图报异常；同时识别控制层泄漏、作者说明、直接复述用户反馈和违反意图的否定句，用 prompt 测试验证检查点存在
- [x] 4.2 为审计规则增加合法剧情否定不误报的保护逻辑，要求对照意图中的允许标志而不是机械匹配否定词，并用正反示例测试
- [x] 4.3 补充初次生成（pipeline / director 直接派发 `writer`）、director 直接修订、驳回后重写和模糊澄清四个集成场景的回归测试，验证反馈不进入章节正文
- [x] 4.4 补充 pipeline 确定性检查 PASS 和 director 直接派发 `writer` 两条路径的回归测试，验证存在反馈意图时仍进入聚焦反馈意图审计，控制层泄漏不会被 PASS 跳过，且 PASS 专属聚焦检查不新增审批轮次

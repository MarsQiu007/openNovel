## 1. 反馈意图协议

- [ ] 1.1 在 pipeline 提示词中定义结构化写作反馈意图字段（意图类型、禁止断言、期望状态、保留内容、允许正文否定、原始反馈、澄清问题），并用 prompt 断言测试验证字段完整
- [ ] 1.2 在 pipeline 提示词中加入删除、替换、后续约束、剧情事实和模糊反馈五类转换规则，并用“不要 X”“把 X 改成 Y”“他没有带伞”等示例测试验证
- [ ] 1.3 定义原始反馈的追溯方式与禁止正文复述控制层语言的规则，并用测试验证反馈报告字段和正文隔离要求同时存在

## 2. 生成与修订路径接入

- [ ] 2.1 更新初次生成路径，使 pipeline 在派发 writer 前把用户生成约束编译为结构化反馈意图，并用 prompt 测试验证 writer 输入包含控制层隔离说明
- [ ] 2.2 更新驳回后重写路径，使 pipeline 基于旧章节和用户批注构造修订意图，并把意图连同旧正文传给 reviser，用 prompt 测试验证不直接派发原始批注
- [ ] 2.3 为 `unclear` 反馈定义澄清返回行为，禁止 pipeline 猜测派发生成或修订，并用测试验证澄清结果包含具体问题

## 3. 执行者故事层协议

- [ ] 3.1 更新 writer 提示词，要求纠正型否定转为删除、替换或后续约束，并禁止把用户指令写成旁白或元否定，用 prompt 测试验证关键规则存在
- [ ] 3.2 更新 reviser 提示词，要求先定位受影响断言再做最小修订并保留无关内容，用固定夹具测试“心情很低落”被移除且“心情不会很低落”不进入正文
- [ ] 3.3 为明确剧情事实定义允许正文否定的条件，要求执行者对照 `narrative_fact` 与 `允许正文否定` 字段，并用正反示例测试

## 4. 审计与回归防护

- [ ] 4.1 更新 auditor 检查规则，识别控制层泄漏、作者说明、直接复述用户反馈和违反意图的否定句，并用 prompt 测试验证检查点存在
- [ ] 4.2 为审计规则增加合法剧情否定不误报的保护逻辑，要求对照意图中的允许标志而不是机械匹配否定词，并用正反示例测试
- [ ] 4.3 补充初次生成、驳回重写和模糊澄清三个集成场景的回归测试，验证反馈不进入章节正文

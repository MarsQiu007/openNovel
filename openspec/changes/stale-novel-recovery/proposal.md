# Proposal

## Why

书籍详情查询对持久化恢复的当前书籍 ID 无失效处理：当该 ID 指向的小说已不存在（数据库重建、小说被删除、目录迁移）时，`/api/novel/{id}` 返回 404，但调用方只把错误写进 store 并保留失效 ID，界面反复重发同一请求（日志中同一 novelID 短时间多次 404），用户看到的是「获取小说详情失败」错误而不是可操作的空态。

## What Changes

- 书籍详情类查询收到 404（NotFound）时，应用 SHALL 判定为失效引用：清除对应的持久化/当前书籍引用，回落书架空态，并停止对该 ID 的后续请求。
- 失效引用清除覆盖：当前书籍选择、按书持久化的工作台状态、指向该小说的会话绑定展示（for-session 查询 404 按无绑定处理）。
- 404 以外的错误（网络、500）维持现有错误提示行为，不做清除。

## Capabilities

### New Capabilities

- `stale-novel-recovery`：指向不存在小说的持久化引用的识别与自愈。

### Modified Capabilities

- 无

## Impact

- 受影响包：packages/app（novel 上下文与 novel-queries 的 404 处理、按书状态清理）；无服务端改动（404 语义已正确）。
- 兼容性：不改变正常路径的数据流；仅对 NotFound 新增自愈语义。按书状态存档的清理为删除失效键，不影响其他书的存档。
- 不涉及 HttpApi 行为变更、无 Protocol/Schema 变更。

## 非目标

- 不实现小说删除时的主动绑定清理通知（服务端已有级联语义）。
- 不改书籍列表、书架等其他查询的错误处理。
- 不处理「小说存在于其他目录」的跨目录恢复。

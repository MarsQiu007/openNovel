# config-health-guard Specification

## Purpose
配置健康守卫：在升级/跨机场景下，全局配置（插件条目、agent 覆盖项、旧式定义残留）与新版本脱节时，让漂移可见、可定位、可经确认修复，而不是静默生效或静默失败。

## Requirements

### Requirement: 启动时全局配置健康检查

服务器启动（及配置变更后）MUST 对全局配置执行只读健康检查，检查面至少覆盖：① `plugins` 各条目是否可解析、已配置的插件是否加载成功；② `agent:` 各覆盖项引用的 provider/model 是否可解析；③ 配置目录下旧式 agent 定义目录（agent/agents/mode/modes 的 markdown）是否存在残留。体检 MUST NOT 修改任何配置或运行时注册表。

#### Scenario: 插件条目失效被发现

- **WHEN** 全局配置 `plugins` 含一个无法解析或加载失败的第一方插件条目（如指向已摘除的旧入口 id），服务器完成启动
- **THEN** 体检结果包含一条问题记录，指出该插件条目、失败原因（不可解析/加载抛错）与所在配置文件路径

#### Scenario: 失效的 agent 模型覆盖被发现

- **WHEN** `agent:` 段某覆盖项的 provider 或 model 在已知提供商目录中不存在
- **THEN** 体检结果包含一条问题记录，定位到配置文件路径与 `agent.<name>.model` 键

#### Scenario: 只读性

- **WHEN** 体检发现任意数量的问题
- **THEN** 配置文件内容、权限注册表与 agent 花名册均保持不变

### Requirement: 体检结果经 API 暴露

体检结果 MUST 经 HTTP API 暴露给客户端，内容包含问题清单，每条含严重级别、人类可读说明、来源文件路径、键路径与修复建议。无问题时 MUST 返回空清单。结果 MUST 随配置变更刷新。

#### Scenario: 客户端查询健康状态

- **WHEN** 客户端请求配置健康状态且存在两处漂移（一个失效插件条目、一个失效模型覆盖）
- **THEN** 响应包含两条问题记录，各带来源文件路径、键路径与修复建议，且不包含内部异常栈

#### Scenario: 健康无漂移

- **WHEN** 全局配置与当前版本完全兼容
- **THEN** 响应为空清单，且响应不触发任何写操作

### Requirement: 设置界面健康横幅

当体检发现问题时，设置 → 智能体页与设置 → 提供商页顶部 MUST 显示健康横幅，汇总问题数量并允许展开查看逐条明细（说明 + 来源定位）；无问题时 MUST NOT 显示横幅。横幅 MUST NOT 阻断页面其余功能的使用。

#### Scenario: 发现问题时展示横幅

- **WHEN** 体检发现插件加载失败，用户打开设置 → 智能体页
- **THEN** 页面顶部出现健康横幅，展开后可见该插件条目的失败说明与配置文件定位

#### Scenario: 无问题时不展示

- **WHEN** 体检结果为空清单，用户打开设置 → 智能体页
- **THEN** 页面顶部不出现健康横幅，页面与既有行为一致

### Requirement: 一键修复须经用户显式确认

对带修复建议的问题，UI MUST 在用户显式点击确认后才执行修复，确认前 MUST 展示将要写入的配置变更（至少含目标文件路径与变更键值）；修复 MUST 仅重写问题对应的配置条目。系统 MUST NOT 静默改写、删除任何用户配置项；修复完成后 MUST 重新执行体检并刷新横幅。

#### Scenario: 确认后修复插件条目

- **WHEN** 用户在健康横幅中对"插件条目失效"问题点击修复并确认预览的变更
- **THEN** 系统将该 `plugins` 条目重写为修复建议给出的现行值，重新体检后该问题消失，其余配置内容保持不变

#### Scenario: 未确认不得写入

- **WHEN** 用户未点击确认（仅浏览问题或关闭横幅）
- **THEN** 配置文件的任何内容均不得发生变化

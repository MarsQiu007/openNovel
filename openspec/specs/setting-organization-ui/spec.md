## Purpose

让用户在设定中心查看整理问题，并通过绑定会话安全委托 AI 整理；同时保留 agent 工具路径的计划校验、运行时确认和复查流程。

## Requirements

### Requirement: 设定中心提供整理报告入口

设定中心 SHALL 提供用户可见的“整理”入口。激活后系统 SHALL 请求当前小说的跨实体整理分析，并展示问题数量、问题类型、实体类型、受影响条目、证据摘要和建议。没有问题时 SHALL 展示“无需整理”状态；加载失败时 SHALL 展示可读错误并允许重试。

#### Scenario: 查看问题报告

- **WHEN** 用户打开设定中心的整理入口且当前小说存在格式、重复或引用风险问题
- **THEN** UI 展示按问题和实体组织的结果，并显示每条问题的证据摘要和建议

#### Scenario: 查看无需整理状态

- **WHEN** 当前小说没有通过分析识别出的问题
- **THEN** UI 展示无需整理状态，不显示执行计划操作

#### Scenario: 分析失败

- **WHEN** 分析请求失败
- **THEN** UI 保持现有设定数据不变，展示错误信息并提供重试入口

### Requirement: AI 一键整理委托受控会话

UI SHALL 提供收件箱内可见的 AI 一键整理入口。用户激活后，UI SHALL 将真实 `novel_id` 发送到该小说的未归档绑定会话；没有绑定会话时 SHALL 创建并绑定新会话。指令 SHALL 走批处理编排路由：执行设定 lint、一致性检查、去重扫描与整理分析，白名单内机械修复自动执行，其余产出统一写入收件箱并向用户汇报新增待审数量；SHALL 禁止猜测 `novel_id` 或使用旁路工具直接修改，SHALL NOT 扩大分级自动化白名单的执行边界。

#### Scenario: 一键整理发送受控指令

- **WHEN** 用户在收件箱点击 AI 一键整理
- **THEN** 绑定会话收到走批处理编排的指令，产出进入收件箱并汇报新增待审数量

#### Scenario: 没有绑定会话时创建会话

- **WHEN** 当前小说还没有未归档的绑定会话
- **THEN** UI 创建新会话、绑定当前小说，再发送批处理编排指令

#### Scenario: 指令不得绕过受控流程

- **WHEN** AI 接收一键整理指令
- **THEN** AI 只使用指令中的真实 `novel_id`，按编排产出白名单自动执行与待审暂存，不使用旁路工具直接修改正式数据

### Requirement: UI 不提供直接执行路径

UI SHALL NOT 提供 plan_json 导入与未经服务端重校验的直接执行控件。UI 的成果审阅页（收件箱）SHALL 提供受控审阅路径：对暂存变更逐条确认执行——接受动作 SHALL 由服务端完整重校验后才生效，是用户显式确认的产品化形态；UI SHALL NOT 绕过重校验直接调用执行端点修改数据。服务端 dry-run / apply 契约保留时，不得因 UI 简化而移除其计划校验和显式确认约束。

#### Scenario: 收件箱提供受控确认执行

- **WHEN** 用户在收件箱对一条暂存变更点击接受
- **THEN** 服务端完整重校验通过后才执行并留痕；校验失败时 UI 展示逐条错误且数据不变

#### Scenario: 用户查看整理面板

- **WHEN** 用户在设定树选中「整理」节点打开收件箱视图
- **THEN** UI 只展示收件箱列表、审阅操作与 AI 一键整理入口，不出现 plan_json 导入或跳过重校验的直接执行控件

#### Scenario: 受控流程失败或等待确认

- **WHEN** 会话内整理的 dry run 或 apply 失败，或流程等待运行时确认
- **THEN** UI 不在收件箱中伪造成功结果，由绑定会话展示流程状态、错误和确认请求

### Requirement: Agent 整理流程保持独立受控

新增 UI 路径 SHALL NOT 移除 `organize_settings` 的 analyze、dry_run、运行时确认、apply 和复查行为。agent 通过工具执行 apply 时 SHALL 仍请求运行时用户确认，并遵循现有计划校验和安全约束。

#### Scenario: Agent 执行整理

- **WHEN** AI 请求通过 `organize_settings` 执行计划
- **THEN** 系统仍然弹出运行时确认；确认后才执行，且执行前重新校验计划

#### Scenario: UI 路径不影响 Agent 路径

- **WHEN** 用户在 UI 中完成一次整理后再要求 AI 整理
- **THEN** AI 仍必须从或再次进入 analyze、dry run、确认、apply、复查流程，不继承 UI 的确认结果

### Requirement: 设定整理内容按纯文本展示

整理报告、计划原因、预览和执行结果中的设定长文本 SHALL 按纯文本段落展示，保留换行分段；UI SHALL NOT 对设定文本应用 Markdown 渲染或把列表、标题、链接语法转换为富文本结构。

#### Scenario: 展示分段纯文本

- **WHEN** 报告或计划预览包含包含换行分段的设定文本
- **THEN** UI 按原文段落展示换行，不渲染 Markdown 元素

#### Scenario: 防止语法意外渲染

- **WHEN** 文本中包含类似 Markdown 的符号
- **THEN** UI 将其作为普通字符显示，不生成标题、链接、列表或其他富文本结构

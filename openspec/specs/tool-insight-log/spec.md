# tool-insight-log Specification

## Purpose
将写作过程中发现的具体工具与 agent 问题沉淀为可归并、可复现、可验收的本地改进记录，并在用户显式授权后通过隔离复测验证修复效果，同时保护原书内容与用户隐私。

## Requirements

### Requirement: 本地日志开关与目录

系统 SHALL 将「是否启用工具改进日志」和「日志目录」保存为独立全局设置，并在处理事件及后台任务下一步前读取当前值。仅修改这两项设置 MUST 无需重开项目即可生效，且 MUST NOT 改变任何项目的插件加载范围。开关 MUST 默认关闭；未配置目录时 MUST 使用项目自评价目录下的独立子目录，共享目录 MUST 按项目隔离。关闭时 MUST NOT 新增本能力证据、归因模型请求或自动复测，且不得影响既有自评价功能。

#### Scenario: 默认不启用

- **WHEN** 用户从未配置工具改进日志并发生工具失败
- **THEN** 系统不新增本能力证据、不发起归因模型请求，既有指标与自评价报告仍按原行为运行

#### Scenario: 多项目共享日志目录

- **WHEN** 两个项目配置同一个日志根目录并分别产生问题
- **THEN** 两个项目的证据和问题记录写入各自隔离的目录，不相互归并

#### Scenario: 运行中仅保存工具洞察设置

- **WHEN** 用户在已打开项目中仅修改工具改进日志开关或目录
- **THEN** 新设置无需重开项目即可生效，当前项目实例与各项目插件加载范围保持不变

#### Scenario: 目录变化时旧目录仍有待整理证据

- **WHEN** 用户修改日志目录时，旧目录仍保存证据或排队整理任务
- **THEN** 新证据使用新目录，旧目录文件保持不删不改，旧队列停止且不自动迁移或写入新目录

#### Scenario: 运行中关闭开关

- **WHEN** 用户在已打开项目中关闭工具改进日志，随后发生工具失败或后台任务准备进入下一步
- **THEN** 系统不新增证据或模型请求，停止派生后续后台工作并保留既有文件，既有自评价功能不受影响

#### Scenario: 关闭或卸载时仍有活动后台任务

- **WHEN** 用户关闭开关或卸载项目时，归因或复测后台会话仍在执行
- **THEN** 系统中断实际后台执行而不只是停止等待，已保存证据和最后完整问题记录保持可用

#### Scenario: 全局配置暂时不可读

- **WHEN** 系统处理事件时无法读取或解析全局设置
- **THEN** 本次按未启用处理并给出非阻断警告，不使用过期配置继续采集

### Requirement: 客观证据先行与隐私白名单

系统 SHALL 在模型分析前保存客观证据。证据 MUST 来自工具事件、可核实状态或用户输入的白名单字段，MUST NOT 原样保存完整工具参数、完整工具输出、小说正文或密钥；无法确认的事实 MUST 标为未知。正文片段的本地保留与模型使用 MUST 分别授权，仅同意本地保留时不得发送给模型。

#### Scenario: 工具失败后先落证据

- **WHEN** 已启用日志的写作会话发生工具失败
- **THEN** 系统先追加包含工具、调用关联、错误类别、脱敏摘要和版本信息的证据，再允许后台归因

#### Scenario: 输出包含正文和敏感参数

- **WHEN** 工具结果包含章节正文、完整路径参数或疑似密钥
- **THEN** 证据只保留允许的结构化事实与脱敏摘要，不保存原始正文、完整参数或密钥

#### Scenario: 用户明确提供必要正文片段

- **WHEN** 用户为复现问题明确指定一段必要正文并同意本地保留，但未授权将其用于模型请求
- **THEN** 系统只保存该指定片段，在对应问题记录中显著标记包含正文及分享风险，并在归因与复测模型输入中排除该片段

#### Scenario: 用户另行授权正文用于模型

- **WHEN** 用户已保留必要正文片段，又明确允许将其用于本次归因或本次复测
- **THEN** 系统只在该次授权范围内向已配置模型提供此片段，不扩大其他正文、字段或后续任务的授权范围

#### Scenario: 上次写入留下不完整尾行

- **WHEN** 应用在上次证据追加中途退出，重启后发现 JSONL 只有末尾记录不完整
- **THEN** 系统先将损坏尾部隔离保存，再恢复到可追加状态，后续证据与全部完好历史记录均可逐行解析

#### Scenario: 历史文件中部已经损坏

- **WHEN** 系统发现 JSONL 中部存在无法解析的记录
- **THEN** 系统保留原文件并给出非阻断警告，不跨过损坏行继续追加，也不把文件当作空日志

### Requirement: 事件触发的完整轨迹检测

系统 SHALL 在工具异常、反复修改或用户主动反馈时检查相关完整工具轨迹。检测 MUST 覆盖应调用而未调用、工具选择错误、参数错误、无意义重复调用或重试、恢复失败，以及表面成功但任务未完成；正常调用 MUST NOT 逐条生成 AI 意见。

#### Scenario: 工具未报错但路径错误

- **WHEN** 一次任务最终完成，但轨迹显示 agent 先选择了不适用工具并重复无效调用
- **THEN** 系统将该轨迹形成效率或工具使用问题，不因没有异常而丢弃

#### Scenario: 应当调用工具而未调用

- **WHEN** 用户反馈某项需要持久化的操作被 agent 仅在文字中宣称完成，且轨迹没有相应调用
- **THEN** 系统记录「应调用而未调用」问题并关联真实结果核验状态

#### Scenario: 普通成功调用

- **WHEN** 工具按预期一次成功且真实结果符合目标，也没有用户负反馈
- **THEN** 系统不生成该次调用的 AI 改进意见

### Requirement: 失败分类与假设边界

每条已确认问题 SHALL 归入工具实现缺陷、工具能力缺失、工具描述或参数结构问题、agent 选择或参数误用、工具结果误解、产品交互或流程问题之一。证据不足时 MUST 将主分类标为「未确认」，可保留多个属于上述类别的候选假设，MUST NOT 强行选择分类或将模型推测写成已确认根因。

#### Scenario: 证据只能支持多种解释

- **WHEN** 同一失败既可能来自工具描述不清，也可能来自 agent 误用
- **THEN** 问题记录分别列出两种假设及其支持证据，并将根因标为未确认

#### Scenario: 明确的能力缺口

- **WHEN** 客观轨迹证明现有工具没有完成用户目标所需的操作
- **THEN** 系统将其归类为工具能力缺失，而不是虚构一次工具实现异常

### Requirement: 过程与真实结果并验

系统 SHALL 同时记录执行轨迹和可核实的最终结果，MUST NOT 仅凭 agent 自称成功判定任务完成。无法从本地状态核验时 MUST 标记「未验证」。

#### Scenario: 自称落库但实际未落库

- **WHEN** agent 回复章节已保存，但工具轨迹没有有效保存且本地书籍状态证明目标内容不存在
- **THEN** 问题记录区分 agent 声明与真实状态，并将任务结果标为失败

#### Scenario: 最终状态无法读取

- **WHEN** 工具返回成功，但当前证据没有任何可安全查询的最终状态
- **THEN** 系统将任务结果标为「未验证」，不根据工具返回或 agent 声明推断成功

#### Scenario: 工具返回成功且状态已核实

- **WHEN** 工具返回成功且对应章节、审批或设定状态可从本地数据核实
- **THEN** 系统记录已核验的最终状态，不虚构额外问题

### Requirement: 稳定指纹归并与索引

系统 SHALL 根据工具、错误类别和操作场景等稳定事实生成问题指纹。相同指纹的新证据 MUST 更新同一问题记录的出现次数、时间、影响版本和证据索引，并维护可读总索引，MUST NOT 因措辞变化重复建档。证据 MUST 使用跨重启不重复的稳定标识，归并 MUST 按该标识去重；出现次数 MUST 按独立稳定的发生实例标识计算，同一实例的多条证据不得重复计数。

#### Scenario: 同一问题重复发生

- **WHEN** 同一工具在不同会话中以相同错误类别和操作场景再次失败
- **THEN** 系统更新原问题记录并增加出现次数和证据引用，不创建重复问题文件

#### Scenario: 一次发生产生多条证据

- **WHEN** 同一次工具失败同时生成过程、错误和真实结果三条证据
- **THEN** 三条证据都可被问题记录引用，但出现次数只增加一次

#### Scenario: 不同根因候选不得仅凭报错文案合并

- **WHEN** 两次失败的工具或操作场景不同，仅错误文案相似
- **THEN** 系统分别保留问题记录，不因自然语言相似度强行归并

#### Scenario: 两个进程同时写入同一项目日志

- **WHEN** 两个应用进程同时追加证据并整理同一指纹的问题
- **THEN** 文件更新被真实跨进程锁串行化，同一证据不重复计数，并发更新不丢次数，JSONL 与问题索引保持可读

#### Scenario: 重启后继续产生证据

- **WHEN** 应用重启后产生与重启前同指纹的新证据
- **THEN** 新证据不复用历史证据标识，归并结果能区分待整理与已整理证据

### Requirement: 可行动的问题记录

每条问题 SHALL 以可读文档记录用户目标、实际行为、期望行为、复现条件与步骤、影响程度、客观证据、原因假设、改进建议和验收标准。事实与推测 MUST 分节，影响程度 MUST 使用阻断工作、错误结果、效率损失或体验问题之一。

#### Scenario: 开发者取得问题文档

- **WHEN** 用户将一条问题文档交给开发者
- **THEN** 开发者无需原始写作会话即可区分已证实事实与 AI 推测，并据复现步骤和验收标准设计修复及测试

#### Scenario: 信息不足仍保留记录

- **WHEN** 当前证据不足以给出确定复现步骤或唯一改进方案
- **THEN** 系统明确标记缺口，不用编造内容填满文档

### Requirement: 安全边界的后台 AI 整理

自动归因 SHALL 只使用用户已配置的模型提供方和脱敏证据，并在原写作会话当前模型轮次结束后的安全边界后台运行。整理 MUST NOT 向原写作会话插入提示词、阻塞其后续操作或打断正在执行的模型轮次。归因模型请求 MUST NOT 携带原书 Location 的环境上下文内容，system 段只包含专用 agent 提示词；固定模型不可用或解析回退时 MUST 保留待整理状态，MUST NOT 改用其他模型。归因会话 MUST NOT 调用原项目读写、Shell 或网络工具，只能返回待校验的结构化整理内容。内部归因与复测会话 MUST NOT 计入既有自评价指标或触发既有自动报告。

#### Scenario: 工具失败时写作仍在继续

- **WHEN** 当前写作模型轮次尚未结束且已产生待整理证据
- **THEN** 系统先保存证据，等该轮次结束后再启动独立后台归因，原会话不收到归因提示词

#### Scenario: 归因模型请求不可用工具

- **WHEN** 后台归因模型尝试读写原项目、调用写作工具、Shell 或网络工具
- **THEN** 这些工具不在其可用集合中，整理只能依据请求内的脱敏证据返回结构化内容

#### Scenario: 归因专用权限未就绪

- **WHEN** 归因专用 agent 不存在，或发车前实际可用工具集合不是空集
- **THEN** 系统不发送归因提示词，保留待整理证据并标记整理失败，不依赖缺失 agent 的默认权限兜底

#### Scenario: 归因请求不携带原书上下文

- **WHEN** 已启用日志的项目存在小说设定、灵魂段或注入快照等上下文来源，后台归因构造模型请求
- **THEN** system 段只包含专用 agent 提示词，不含原书设定、注入快照或引用清单，整理只能依据请求内的脱敏证据

#### Scenario: 指定模型不可用时不回退

- **WHEN** 启动后台整理时固定提供方或模型不可用，现有解析会回退到默认或其他模型
- **THEN** 系统不发车并保留待整理证据与失败状态，不使用回退模型继续整理

#### Scenario: 模型整理失败

- **WHEN** 后台模型不可用、未配置、解析失败、超时或返回不可采用的内容
- **THEN** 原始证据仍保留，问题记录标明整理失败或未完成，不隐式切换到另一个模型提供方，写作会话继续正常运行

#### Scenario: 内部会话不得污染旧指标

- **WHEN** 已启用日志后运行归因或复测，内部会话产生创建、agent 或模型切换、Step、工具、压缩及完成后的尾部事件
- **THEN** 既有指标桶与自动报告触发计数不包含这些内部事件，表现等同于这些后台会话从未发生

#### Scenario: 进程在整理前退出

- **WHEN** 客观证据已经保存但后台整理尚未完成，应用随后重启且日志仍启用
- **THEN** 系统在启动后一次性补齐全部待整理证据，已整理证据不重复归因，不等待同类新问题再次发生，也不进行周期性扫描

#### Scenario: 证据落盘后问题骨架尚未更新

- **WHEN** 进程在证据追加成功之后、问题文档登记 pending 之前退出
- **THEN** 重启后对账发现该证据既未 pending 也未 organized，系统重新确定性摄取并排队整理，出现次数仍只计一次

#### Scenario: 启动补整理时原父会话已不存在

- **WHEN** 待整理证据关联的原写作 Session 已删除或不可恢复
- **THEN** 系统仍在当前项目中以同样的无工具权限完成独立后台整理，不向其他项目或复测临时项目发送证据

### Requirement: 用户主动记录与重新整理

系统 SHALL 允许用户在评价入口中用自然语言记录工具问题、补充反馈或重新整理指定问题。主动入口 MUST 覆盖没有报错但操作绕、理解偏差及写作之外的交互问题，自动检测不得替代该入口。

#### Scenario: 用户主动记录体验问题

- **WHEN** 用户要求「记录这个工具问题」并描述一次没有异常的繁琐操作
- **THEN** 系统保存用户目标和反馈，形成或更新问题记录，不要求必须存在工具失败事件

#### Scenario: 用户补充纠正归因

- **WHEN** 用户对既有问题补充实际期望并指出原假设不正确
- **THEN** 新反馈作为客观证据追加，重新整理后保留历史反馈且不伪称旧推测曾得到证实；补充反馈沿用原发生实例，不增加出现次数

#### Scenario: 使用既有报告或诊断导出

- **WHEN** 用户在扩展后的评价入口中执行既有报告或诊断导出
- **THEN** 原报告与导出的格式、冷却和确定性保持不变，不调用本能力归因模型，也不修改写作数据

### Requirement: 显式授权的隔离自动复测

系统 SHALL 仅在用户显式确认后自动复测。确认前 MUST 展示问题、运行次数、修复版本和案例摘要，并由宿主将本次确认绑定到请求插件和该案例内容；带工具的后台执行 MUST 校验宿主授权，不能仅凭插件自我声明已获确认。只有具备程序注册的确定性隔离适配器（合成夹具、固定工具白名单、真实结果核验器）的工具与操作才可自动执行，AI 文本 MUST NOT 扩大该白名单；没有适配器的案例 MUST 转人工。复测 MUST 在独立临时项目中使用匿名或合成的最小案例与必要夹具；除用户明确指定且授权本次模型使用的片段外，复测 agent MUST NOT 读取或修改原书。无法安全复制、隔离或具有真实外部副作用的案例 MUST NOT 自动执行。

#### Scenario: 用户授权可隔离案例复测

- **WHEN** 用户明确要求复测一个可由合成数据重现的问题，并在系统展示问题、次数、版本和案例摘要后确认执行
- **THEN** 系统在独立临时项目中执行，复测会话不继承原书位置，复测 agent 不读取原书且原书数据在复测前后保持不变

#### Scenario: 未经确认的执行请求

- **WHEN** agent 尝试执行复测，但用户尚未看到并确认本次问题、运行次数、版本和案例摘要，或后台请求没有匹配的宿主执行授权
- **THEN** 宿主不创建临时项目或后台复测会话，等待用户明确决定，插件自我声明已确认也不能绕过

#### Scenario: 确认后的案例发生变化

- **WHEN** 用户确认后，待执行案例、夹具、工具白名单、验收标准、模型提供方/模型或修复版本与确认时不再一致
- **THEN** 原确认不适用于变化后的请求，系统不继续执行并要求重新展示和确认

#### Scenario: 必要正文只有本地保留授权

- **WHEN** 一个案例必须包含正文才能成立，但该正文只获准本地保留而未获准本次复测模型使用
- **THEN** 系统不启动自动复测，将其标为「未验证」并说明需要人工验证，不向模型发送该片段

#### Scenario: 案例涉及真实外部副作用

- **WHEN** 复现步骤需要发布内容、通过工具调用真实外部服务或操作无法隔离的用户数据
- **THEN** 系统拒绝自动执行并记录人工验证要求，不用禁用部分安全检查的方式强行复测

#### Scenario: 隔离环境无法建立

- **WHEN** 必要夹具无法安全复制或临时项目不能与原书及外部服务隔离
- **THEN** 系统不启动自动复测，将结果标为「未验证」并说明原因

#### Scenario: 工具或操作没有隔离适配器

- **WHEN** 目标工具或操作没有程序注册的确定性夹具、精确白名单和真实结果核验器
- **THEN** 系统不根据 AI 自由文本构造可执行复测，不发送复测提示词，并将案例转人工验证

#### Scenario: 专用权限或目标工具未就绪

- **WHEN** 专用复测 agent 不存在、目标工具未加载，或发车前实际可用工具集合不完全等于案例白名单
- **THEN** 系统不发送复测提示词，不执行目标工具，并将本次结果标为「未验证」

### Requirement: 多次复测与回归留痕

可自动复测的问题 SHALL 支持按 1–20 的明确整数次数运行并保存每次结果。记录 MUST 包含修复版本、运行次数、通过或失败、真实结果核验和新证据引用；未实际执行 MUST 标为「未验证」，已解决案例 MUST 保留为回归材料。

#### Scenario: 修复后多次复测均通过

- **WHEN** 用户要求在指定修复版本上运行三次且三次均满足验收标准
- **THEN** 系统逐次留痕并记录三次通过，不只保存一次概括性成功结论

#### Scenario: 多次复测结果不一致

- **WHEN** 同一案例在多次复测中同时出现通过与失败
- **THEN** 问题保持未稳定解决并展示各次结果，不用最后一次通过掩盖先前失败

#### Scenario: 进程在复测中途退出

- **WHEN** 一次复测已写入 started 但进程在终态落盘前退出
- **THEN** 重启后完成一次未完成记录对账，将该运行标为 interrupted 和「未验证」，不自动重跑、不计为通过，也不误标另一进程仍在执行的活动运行

#### Scenario: 仅有人工验证或部分运行未执行

- **WHEN** 用户补充一条人工验证结论，或确认的运行中有一部分未实际执行
- **THEN** 系统标明验证来源、版本和未执行次数，不将人工结果或未执行运行计为自动复测通过

#### Scenario: 运行次数无效

- **WHEN** 用户或 agent 提供零、负数、非整数或超过 20 的运行次数
- **THEN** 系统在执行前拒绝该请求并说明允许的次数范围，不创建任何复测运行记录

### Requirement: 本地优先与非阻断

证据、问题和复测记录 SHALL 只写本地文件，不新增数据库表或管理页面。除用户已配置模型的必要归因与复测请求外，系统 MUST NOT 自动上报、创建外部议题或修改产品代码；日志读写与后台任务失败 MUST NOT 阻断写作。

#### Scenario: 日志目录不可写或文件锁不可用

- **WHEN** 写作过程中日志目录因权限、磁盘或文件锁原因无法安全写入
- **THEN** 系统发出非阻断警告并继续写作，不绕过锁直接写入，也不改变工具本身的执行结果

#### Scenario: 问题已整理完成

- **WHEN** 本地问题文档和索引已生成
- **THEN** 系统不自动创建 GitHub issue、不上传文件、不修改工具或产品代码，由用户决定后续分享和处理

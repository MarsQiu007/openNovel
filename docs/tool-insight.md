# 工具改进日志（tool-insight）说明

工具改进日志把写作过程中发现的具体工具与 agent 问题沉淀为本地可读的改进记录：客观证据先行、稳定指纹归并、可选的后台模型整理与显式授权的隔离复测。它默认关闭，只写本地文件，不会自动上报、创建外部议题或修改产品代码。本文说明日志目录里每个文件的含义、字段与隐私边界，供使用者检查、备份或分享前参考。

## 设置

两项设置保存在全局配置的顶层 `toolInsight` 字段中，项目配置不覆盖它们：

```json
{
  "toolInsight": {
    "enabled": false,
    "directory": ""
  }
}
```

- `enabled`：是否启用，默认 `false`。从未配置等同于关闭。
- `directory`：可选的共享日志根目录。留空或省略时，日志写入当前项目的 `.novel/evaluate/tool-insight/` 目录；填写后写入 `<directory>/<项目短哈希>/`，项目短哈希是项目稳定标识的 12 位十六进制摘要，不同项目互不混写。

只修改这两项设置不需要重开项目即可生效；关闭开关后立即停止新增证据、归因模型请求与自动复测，已生成的文件原样保留。全局配置暂时不可读或字段非法时，本次按未启用处理并给出非阻断警告，不会用过期的旧配置继续采集。

## 日志目录布局

```text
<log-root>/
  evidence.jsonl
  issues/<fingerprint>.md
  index.md
  cases/<fingerprint>.md
  runs/<fingerprint>.jsonl
  recovery/
  locks/
```

| 路径                       | 内容                                                   |
| -------------------------- | ------------------------------------------------------ |
| `evidence.jsonl`           | 客观证据，逐行一条 JSON，只追加                        |
| `issues/<fingerprint>.md`  | 每个问题一份可读文档，文件名是 16 位十六进制问题指纹   |
| `index.md`                 | 问题总索引，只从各问题文档的 frontmatter 确定性重建    |
| `cases/<fingerprint>.md`   | 可自动复测问题的案例文档（夹具、工具白名单、验收标准） |
| `runs/<fingerprint>.jsonl` | 复测运行记录，逐行一条 JSON，只追加                    |
| `recovery/`                | 上次写入中断留下的撕裂尾部隔离副本，仅供诊断           |
| `locks/`                   | 运行期跨进程文件锁，不属于日志内容                     |

`recovery/` 与 `locks/` 是运行期内部目录，不作为分享材料。

## 证据字段

每条证据来自工具事件、可核实状态或用户输入的白名单字段，逐行格式如下：

| 字段                                 | 说明                                                                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `id`                                 | 稳定证据 ID。自动证据由项目、事件信封 ID 和证据种类派生（`evi_` 前缀），重启不重用；用户主动记录使用 ULID              |
| `ts`                                 | 墙钟时间戳（毫秒）。排序使用事件顺序与文件顺序，不宣称墙钟单调                                                         |
| `kind`                               | 证据种类：`tool_called`、`tool_failed`、`tool_success`、`trajectory`、`user_report`、`content_exception`、`real_state` |
| `projectID` / `sessionID` / `callID` | 归属项目与会话；`callID` 只在同项目同会话内关联                                                                        |
| `turnID`                             | provider turn 边界（assistant 消息 ID），用于组织完整轨迹                                                              |
| `agent` / `model` / `appVersion`     | 使用的 agent、模型与应用版本                                                                                           |
| `trigger`                            | `auto`（事件触发）或 `user`（用户主动记录）                                                                            |
| `occurrenceID`                       | 稳定发生实例 ID（`oci_` 前缀或用户 ULID），出现次数按它去重                                                            |
| `fields`                             | 白名单化脱敏字段，见下                                                                                                 |

默认不落盘的内容：小说正文、完整工具参数、工具输出原文、密钥。`Tool.Called` 只保留工具名、参数键集合与非内容枚举值；`Tool.Failed` 只保留错误类型、稳定错误码和截断脱敏摘要（上限 200 字符）；`Tool.Success` 只保留成功标志、输出文件类别与核验标识。摘要中的绝对路径替换为 `<path:扩展名>`，密钥形状的键值对与令牌前缀替换为 `<redacted>`。

无法确认的事实一律标为「未知」，不用推测填补。

## 正文例外与两种授权

用户为复现问题明确指定的正文片段作为独立的 `content_exception` 证据保存（`exc_` 前缀），记录片段长度、本地保留授权时间和显著的分享风险标记。正文不能经普通反馈字段绕入白名单——反馈与正文是不同输入字段。

本地保留与模型使用是两项独立授权：

- 仅本地保留：片段只保存在本地证据文件中，对归因与复测的模型输入不可见。
- 模型使用授权：另行签发唯一 grant（`cgr_` 前缀），绑定用途（本次归因或一组复测）、案例或问题摘要与目标模型范围；授权范围外的请求拿不到该片段。依赖未授权正文才能成立的复测案例直接转人工，不悄悄换成不完整案例。

## 问题文档

每个问题一份 `issues/<fingerprint>.md`。frontmatter 由程序唯一写入，模型整理不能修改它，也不能修改证据、复测历史或用户反馈。frontmatter 保存：格式版本、指纹、标题、工具名、操作场景、错误类别、六类问题分类（初始 `unknown`，证据不足标 `unconfirmed`）、影响程度（`blocks_work` 阻断工作、`wrong_result` 错误结果、`efficiency_loss` 效率损失、`experience` 体验问题，未知标 `unknown`）、整理状态（`pending`、`organized`、`failed`）、发生实例引用与出现次数、证据引用、`pending_evidence_ids` 与 `organized_evidence_ids`、影响版本、别名（分类或指纹演变前的历史指纹）。

正文固定包含以下段落，缺失信息标「未知」：

| 段落                                      | 写入方         | 说明                                |
| ----------------------------------------- | -------------- | ----------------------------------- |
| 用户目标 / 实际行为 / 期望行为 / 复现步骤 | 程序或用户输入 | 事实描述                            |
| 影响                                      | 程序           | 影响程度枚举                        |
| 客观证据                                  | 程序           | 证据 ID 引用清单，一行一条          |
| 事实                                      | 程序           | 从 frontmatter 确定性渲染的稳定事实 |
| 原因假设 / 改进建议 / 验收标准            | 模型整理提交   | 推测性内容，固定结构校验后写入      |

事实与推测分节：程序写「事实」与「客观证据」，模型只能提交「原因假设」「改进建议」「验收标准」三个段落的内容，且序列化由程序完成，模型文本无法修改 frontmatter 或其他段落。

出现次数只按发生实例 ID 去重：同一次失败的过程、结果、真实状态和后续补充反馈可以产生多条证据，但只计一次；补充既有问题的反馈沿用原发生实例 ID，只有明确报告新一次发生才新增。相同指纹的新证据更新同一份问题文档；分类或指纹确需演变时，新文档记录旧指纹为别名，旧文档原样保留。

指纹由规范化工具名、操作场景、稳定错误码或类别（及可选稳定事实）派生，不含 Session、章节名、模型自由文本、时间和绝对路径，因此措辞变化不会重复建档，不同工具或操作场景的错误也不会因报错文案相似被误并。

## 索引与复测记录

`index.md` 只从各问题文档的 frontmatter 确定性重建（按指纹排序），启动对账时会顺带重建以修复崩溃残留的过期索引，不手工维护。

复测案例文档 `cases/<fingerprint>.md` 由程序从确定性案例适配器与证据生成，包含案例说明、夹具、精确工具白名单、验收标准、模型与修复版本，并固定声明「禁止外部副作用」：复测只在隔离临时项目中执行，不读写原书、不调用外部服务。

复测运行记录 `runs/<fingerprint>.jsonl` 只追加，每次运行一条：开始时间、结束时间、案例摘要、模型、工具轨迹摘要与逐项核验结论。进程中断的运行在重启对账时标为 `interrupted` 和「未验证」，不自动重跑、不计为通过；多次运行结果不一致时保留「未稳定解决」，不用最后一次通过掩盖先前失败。

## 分享前自查

问题文档与索引可能包含足够推断工作内容的版本、工具与场景信息。分享任何文件前请自查：

1. 文档 frontmatter 的 `aliases` 与「客观证据」段落不含正文例外引用；含正文的问题文档带显著分享警告。
2. 不要分享 `recovery/` 与 `locks/` 目录。
3. `content_exception` 证据的 `text` 字段保存正文片段本体，确认分享范围前不要外发 `evidence.jsonl`。
4. 只分享单个问题文档（`issues/<fingerprint>.md`）通常足以让开发者理解问题；需要补充时再附上对应的 `runs/` 记录。

系统本身不会上传任何文件：除用户已配置模型的必要归因与复测请求（且仅限已授权片段）外，没有网络副作用。

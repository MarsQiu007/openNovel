本模块为纯脚本目录，无运行时依赖，每个 `.ts`/`.ps1` 文件是一个独立可执行的 CLI 工具，通过 `#!/usr/bin/env bun` shebang 由 Bun 直接运行。
- 开发流程：`dev-all.ts` 使用 `Bun.spawn` 同时启动后端（`packages/opencode/src/index.ts serve`）和前端（`packages/app dev`），统一处理 SIGINT/SIGTERM 信号并级联关闭子进程。
- 构建与格式化：`generate.ts` 顺序调用 SDK 构建、OpenAPI 生成和 `format.ts`；`format.ts` 仅封装 prettier 命令。
- 发布流水线：`publish.ts` 通过 `@opencode-ai/script` 获取版本号，扫描所有 `package.json` 替换 version，依次调用各 package 的 `script/publish.ts`，并在 release 模式下执行 git tag、push 和 gh release 操作。
- 版本与变更日志：`version.ts` 根据 `Script.preview`/`Script.channel` 分支决定是否创建 GitHub Release 并输出 GHA 环境变量；`changelog.ts` 和 `raw-changelog.ts` 通过 `opencode run changelog` 生成 `UPCOMING_CHANGELOG.md`。
- 本地化：`translate-app.ts` 是核心 i18n 同步工具，解析多语言字典差异后通过 `opencode --pure run` 驱动 AI 翻译，支持并发池、dry-run、check 模式及模型变体验证。
- GitHub 自动化：`github/close-issues.ts`、`github/close-prs.ts`、`duplicate-pr.ts` 直接使用 GitHub REST API 操作 issue/pr，依赖 `GITHUB_TOKEN`。
- 平台特定：`sign-windows.ps1` 在 GitHub Actions 中通过 Azure Trusted Signing 对 Windows 二进制签名。
- 依赖方向：脚本之间基本相互独立，仅通过文件系统（如 `UPCOMING_CHANGELOG.md`、`translate-app.md`）和外部命令（`bun`、`git`、`gh`、`opencode`）通信，不互相 import。
